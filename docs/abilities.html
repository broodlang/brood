Brood · abilities · shipped

One dispatch, from print to +

An ability is an open generic function that dispatches on its first argument's identity. It's the one mechanism in Brood for polymorphism — the same defability/impl powers how a value prints, iterates, sorts, and does arithmetic. Core to the language, no import, and fast enough to leave on.

open · deterministic · inline-cached · hot-reloadable
The idea in ten lines

Declare an operation; implement it per type

Dispatch is on the identity of the first argument — a built-in's type-of kind (:int, :string, …), or a defrecord's nominal :module/name. Implement for any identity, from anywhere.

defability + impl · dispatch on identity core
(defability Sized (size [self] :-> int))

(impl Sized :int    (size [n] n))       ; a primitive
(impl Sized :string (size [s] (count s)))
(impl Sized :vector (size [v] (count v)))

(size 42)      ;=> 42
(size "hello") ;=> 5
(size [1 2 3]) ;=> 3   — one call site, three types
a driver is just a value your type
(defability Store (fetch [self key]))

(defrecord pg  (pool))            ; two backends,
(defrecord mem (data))            ; each its own type
(impl Store pg  (fetch [db k] (pg-get (get db :pool) k)))
(impl Store mem (fetch [db k] (get (get db :data) k)))

(fetch db "user:1")   ; picks the impl from db's identity —
                    ; swap the value, swap the backend. No
                    ; config, no module-atom indirection.

No (:use ability), no registration ceremony — abilities are part of the prelude. defability declares the ops, impl registers one for a dispatch id, and the call site just calls the op.

The same mechanism, four jobs

Print, iterate, sort, add — all one thing

Other languages give each of these a separate mechanism (a ToString, an Enumerable, a Comparable, operator overloading). In Brood they're all abilities — the standard library's, that your types opt into.

Display · how a value prints always on
(defmodule bank)
(defrecord money (amount currency))

(impl Display money
  (to-str [m] (str "$" (to-fixed (get m :amount) 2))))

(println (money 10.5 :usd))   ;=> $10.50
; no activation step — a record just prints itself.
Seqable + Conjable · a first-class collection your type
(defrecord stack (items))
(impl Seqable  stack (to-seq [s] (get s :items)))
(impl Conjable stack (-conj  [s x] (stack (cons x (get s :items)))))

(def s (stack (list 1 2 3)))
(count s)          ;=> 3
(fold + 0 s)       ;=> 6
(map inc s)        ;=> (2 3 4)
(first s)          ;=> 1
(seq (conj s 0))   ;=> (0 1 2 3)  — works with every seq op
Ord · a type's own sort order your type
(defrecord ver (major minor))
(impl Ord ver
  (compare-to [a b]
    (let (c (compare (get a :major) (get b :major)))
      (if (= c 0) (compare (get a :minor) (get b :minor)) c))))

(sort (list (ver 1 10) (ver 1 2) (ver 2 0)))
;=> (v1.2  v1.10  v2.0)   — semantic order, not 1.10 < 1.2
Num · arithmetic for your type your type
(defrecord usd (cents))
(impl Num usd
  (num-add [a b] (usd (+ (get a :cents) (get b :cents))))
  (num-mul [a b] (usd (* (get a :cents) b))))   ; by a scalar

(+ (usd 500) (usd 250))   ;=> usd 750
(* (usd 500) 3)           ;=> usd 1500
; int/float math is untouched — see "zero-cost", below.

Every one of these is an ordinary ability the prelude ships and your record opts into. There's nothing special about Display or + — they're the same open dispatch as Sized above.

Why it's usable, not just expressive

Open, deterministic, fast, live

Openness usually costs you determinism (whose impl wins?) or speed (a lookup every call) or the ability to change things at runtime. Brood's ability layer keeps all four.

open

Implement anything

An impl for any ability and any id — a primitive, your record, or a library's type. No orphan rule.

deterministic

Precedence, not roulette

When two impls compete for a slot, a fixed order decides: app > type-owner > ability-owner > other — never load order. A same-tier clash warns.

fast

Inline-cached

A per-op cache memoizes id → impl, validated by an epoch, so a hot monomorphic call is about 2× a direct call — down from ~3.5× with a plain registry lookup.

live

Redefine at runtime

Re-impl at the REPL and running processes pick it up next call — the cache deopts on the reload epoch. Erlang-style.

The "app is sovereign" part matters in practice: because the application's own module outranks every library (top of the precedence order), a dependency can never quietly change how your types behave — you can always override it, deterministically.

The part that's easy to get wrong

Zero cost on the hot path

Making + or first dispatch to a record looks like it should slow down ordinary int and list code. It doesn't — because the dispatch lives in the cold fallback, not the operator.

the naive way — a branch in the operator 195× slower
(defn + ((a b)
  (if (record? a) (num-add a b) (%add a b))))
; the JIT can no longer prove `+` is an int-add,
; so it stops specializing arithmetic entirely.
fib 35:  60 ms  ->  11,700 ms   — measured, reverted
the kernel way — dispatch in the fallback 0×
(defn + ((a b) (%add a b)))    ; operator unchanged

; %add inlines int+int / float+float (JIT). A record
; isn't a number, so it falls to the builtin, whose
; COLD path dispatches Num. The hot path never sees it.
fib 35:  61 ms   — identical to baseline

The same trick powers first/rest/empty? for custom collections: they're JIT-inlined for lists, and a record only reaches the fallback that consults Seqable. A tight fold over a million-element list is unchanged. The measurement is the load-bearing part — the branch-in-the-operator version was written, benchmarked, and thrown away.

The honest ledger

What it buys, and what it costs

What it buys

  • One idea to learn. Printing, iteration, ordering, and arithmetic are the same open dispatch. A new protocol is a defability; joining one is an impl. There's no separate Enumerable-vs-Comparable-vs-operator-overloading vocabulary.
  • Your types are first-class. A record can print itself, iterate, sort, and do arithmetic — the same standard-library operations built-ins get. A custom collection works with map/fold/for/conj, not a parallel API.
  • Open, but not chaotic. You can implement anything (Elixir/Ruby freedom), yet conflicts resolve by a fixed precedence with the app on top — no last-wins roulette, and a dependency can't silently change your types.
  • Fast enough to leave on. An epoch-validated inline cache halves dispatch overhead, and the operator/accessor hot paths (+, first, fold) pay nothing — dispatch lives in the cold fallback, verified by benchmark.
  • Live. Redefine an impl at the REPL; running green processes pick it up on their next call. The cache deopts on the reload epoch — hot reload survives the specialization.

What it costs

  • Dispatch is cached, not monomorphized. A call on a statically-unknown receiver does an inline-cache probe, not Rust's zero-cost monomorphization. Fast, but not free — the price of staying open and live.
  • Coherence is a convention, not a proof. There's no orphan rule; two libraries can both impl for the same slot. Precedence makes the winner deterministic and the checker warns, but it's discipline + a lint, not Rust's "it cannot exist."
  • The zero-cost paths need kernel support. +, first, rest can't dispatch from Brood without defeating the JIT (a measured 195× arithmetic regression). Extending them means a kernel fallback — more machinery under the hood than a plain function.
  • Records carry a hidden identity field. A defrecord value is a map with a reserved :__id__ key, so it is not = to a bare map (Elixir-struct semantics). The collection ops hide it; record?/fields give the clean view.
