## ADR-710 — `string/scripts` and `string/mixed-script?`: the Script property, and TR39's single-script test

**Status:** implemented (2026-11-11).

**Context.** A Cyrillic `а` (U+0430) looks like a Latin `a`, so `pаypal` reads as `paypal`. An
editor wants to mark an identifier or a URL that mixes scripts the way a homoglyph does (Emacs's
`textsec.el`, VS Code's ambiguous-character highlight); a package registry wants to refuse a
package name that imitates another; a mail reader wants to flag a sender's display name. Each
needs the Unicode Script property of a character, which is table data Brood did not have.

**Decision.** One native and one std function.

- `(string/scripts s)` (`builtins/string.rs`, over the `unicode-script` crate already in the tree
  through cosmic-text) — the scripts of `s`'s characters as keywords (`:latin`, `:cyrillic`,
  `:old-italic`), in order of first appearance, none twice. Common (digits, punctuation, spaces),
  Inherited (combining marks) and Unknown are left out: they belong to every script, so
  `(string/scripts "v1.2")` is `[:latin]`.
- `(string/mixed-script? s)` (`std/string.blsp`, Brood) — UTS #39's "highly restrictive" level:
  false for one script, for Han with kana, Hangul or Bopomofo (its augmented script sets), and
  for any of those with Latin; true for the rest, Latin with Cyrillic or Greek above all. The
  rule is policy over the property, so it is Brood; the property is data, so it is native.

**Not done.** UTS #39's *confusables* (`confusables.txt`, the skeleton that makes the whole-script
`раураl` — all Cyrillic — compare equal to `paypal`) need the `unicode-security` crate's tables
or a generated std table; a word in ONE script is not flagged. Script_Extensions (a character
several scripts share, U+30FC) are read as the character's single Script value.
