# Design decisions: numbers 700 to 799

One of the files the ADR log is split across by number; the index, and the notes that
apply to every entry, are in [../decisions.md](../decisions.md).

## ADR-710 — `string/scripts` and `string/mixed-script?`: the Script property, and TR39's single-script test

**Status:** implemented (2026-11-11).

**Context.** A Cyrillic `а` (U+0430) looks like a Latin `a`, so `pаypal` reads as `paypal`. An
editor wants to mark an identifier or a URL that mixes scripts the way a homoglyph does (Emacs's
`textsec.el`, VS Code's ambiguous-character highlight); a package registry wants to refuse a
package name that imitates another; a mail reader wants to flag a sender's display name. Each
needs the Unicode Script property of a character, which is table data Brood did not have.

**Decision.** One native and one std function.

- `(string/scripts s)` (`builtins/string.rs`, over the `unicode-script` crate already in the tree
  through cosmic-text) — the scripts of `s`'s characters as keywords (`:latin`, `:cyrillic`,
  `:old-italic`), in order of first appearance, none twice. Common (digits, punctuation, spaces),
  Inherited (combining marks) and Unknown are left out: they belong to every script, so
  `(string/scripts "v1.2")` is `[:latin]`.
- `(string/mixed-script? s)` (`std/string.blsp`, Brood) — UTS #39's "highly restrictive" level:
  false for one script, for Han with kana, Hangul or Bopomofo (its augmented script sets), and
  for any of those with Latin; true for the rest, Latin with Cyrillic or Greek above all. The
  rule is policy over the property, so it is Brood; the property is data, so it is native.

**Not done.** UTS #39's *confusables* (`confusables.txt`, the skeleton that makes the whole-script
`раураl` — all Cyrillic — compare equal to `paypal`) need the `unicode-security` crate's tables
or a generated std table; a word in ONE script is not flagged. Script_Extensions (a character
several scripts share, U+30FC) are read as the character's single Script value.

## ADR-711 — `mcp-server`: the MCP protocol out of `nest mcp`, for any program that serves tools to an agent

**Status.** Accepted (2026-11-11).

**Context.** `std/tool/mcp.blsp` held the whole Model Context Protocol server — the JSON-RPC
dispatch, the handler run in a monitored process of its own with stdout captured, the deadline,
the projection of Brood data onto JSON — bound to stdio and to `nest mcp`'s catalogue, in a DEV
module a shipped runtime does not carry. An editor that hands a coding agent its own tools (its
buffers, diagnostics, the tests it can run) needs exactly that dispatcher, served from inside
its own event loop and shipped with it; so does an agent harness exposing its file tools to a
CLI agent. `docs/mcp.md` had foreseen it: "the Brood half ports unchanged; only the transport
re-hosts".

**Decision.**
1. **A runtime module, `mcp-server`** (`std/mcp-server.blsp`), holds the protocol. A SERVER is a
   plain map: `:catalogue` (a fn answering `{:name :description :schema :handler}` entries, read
   on every request), `:info`, `:capabilities`, `:methods` (more JSON-RPC methods, `name -> (fn
   (params server) [status payload])`, answered before the built-in ones), `:emit` (where a
   progress notification goes), `:deadline-ms` and `:deadline-tools`. `handle` and `respond`
   answer one message; `json-data`, `pretty-json`, `listed-tool`, `rpc-error` and `progress` are
   public, so a server built elsewhere shapes its results the same way.
2. **Two transports.** `serve-stdio` — newline-delimited JSON, with an optional per-reply step
   (`nest mcp` carries its staleness warning on it). `http-handler` / `start-http` — MCP's
   streamable-HTTP transport with JSON responses only: a POST carries one message and gets one
   reply (202 for a notification, 405 for anything but POST), on loopback only and only with a
   secret token (`http/loopback-only`, `http/require-token`). `start-http` listens on an
   OS-assigned port in a process of its own and answers `{:pid :port :token :url}`.
3. **`nest mcp` is one server spec over it**: its catalogue, the reference documents as
   resources, the `brood-task` prompt (as `:methods`), the deadline on `eval` / `load`. Its
   behaviour is unchanged; `mcp/progress` is `mcp-server/progress`.

**Rejected.** *Leave it in `nest mcp` and let applications copy it*: the handler isolation and
the JSON projection are the subtle parts, and they would drift. *A stdio-only server, with a
relay process an agent launches to reach an application's port* (what an agent harness had
built): one more process and one more protocol hop for every call, when an agent CLI that
speaks MCP speaks HTTP too. *Server-sent events on the HTTP transport*: no client this serves
needs a notification mid-call yet; a JSON response is the smaller transport the spec allows.

**Consequences.** `mcp-server` ships in every runtime; `mcp` stays a dev module. A progress
report over HTTP goes to the server's `:emit`, not to the client. Guards: `tests/mcp_test.blsp`
(nest's server, through the shared dispatcher), `tests/mcp_server_test.blsp` (a spec of its own,
`:methods`, the deadline, HTTP with and without the token, a notification, GET).

## ADR-712 — `insert-program-output`: text a program writes, which undo steps over

**Status.** Accepted (2026-11-11).

**Context.** `std/editor/buffer`'s undo restores whole snapshots (`{:rope :point :mark …}`).
In a buffer that a program writes into while a person types (a shell's output above its
prompt, an agent's reply above the message being written), undoing what the person typed
restored a snapshot from before the program's later output, and so took that output away
(redo brought it back). bedit's agent chat turned undo off to avoid this; bshell and a
line-mode terminal had the same problem.

**Decision.** `(insert-program-output buf at text &optional properties)` inserts `text` as though it
had always been there:
- into the buffer, and into every snapshot of its history (`:undo`, `:pending-undo`), at the
  same position;
- recording nothing;
- point, mark, markers, narrowing and text properties move as any insertion moves them;
- a read-only or narrowed buffer takes it, because the text is the program's, not an edit.

Each snapshot goes through the same insertion as the buffer itself (restored into a widened,
unrecorded copy, inserted into, snapshotted again), so there is no second implementation of
how an insertion moves things.

**Rejected.**
- *Delta undo, Emacs's `buffer-undo-list`:* the whole undo model replaced, for one case that
  this covers exactly.
- *Turning undo off in such buffers:* a person loses undo of their own typing.
- *Re-applying the output after each undo:* the history would still hold states the buffer
  never had.

**Consequences.**
- The result is exact when the text before `at` is the same in every snapshot, which is how
  every program buffer is laid out (output above input). Elsewhere a snapshot gets the text at
  the same offset, clamped.
- The cost is one insertion per snapshot, bounded by the undo limit. `:undo-size` does not
  count the output.
- Guards: `tests/buffer_output_test.blsp`. It covers undo, a run of undos, redo, point,
  markers, narrowing and properties.

**Amendment (2026-11-12): `replace-program-output`.** A shell's output is not only inserted:
a carriage return in a progress counter (`10%\r20%`) REPLACES the line the program wrote
before. `(replace-program-output buf from to text &optional properties)` replaces `[from, to)`
the same way, in the buffer and every snapshot, recording nothing; `insert-program-output` is
it over an empty range. A position inside the replaced range lands at its start; one past it
moves by the change in length. Exact when the text up to `to` is the same in every snapshot.
bedit's shell and compile buffers write their output through it.

## ADR-713 — The 1.0 freeze list, restated

**Status:** accepted (2026-11-11). **Supersedes** ADR-170's table. ADR-170's principle and its
"what this list is not" section stand unchanged.

**Context.** ADR-170 gathered what Brood permanently does not have, so a "why not X?" has one
answer. Since it was written, two rows shipped (ratios, ADR-196; multiple dispatch, ADR-179),
the "nominal types" row went stale when a record became its own value kind (ADR-542: `type-of`
is `:record`, not `:map`), and continuations were refused in practice without being listed.
`road-to-1.0.md` §A asks for the table as it stands at 1.0. Every row below was checked
against the running language on 2026-11-11, by evaluating the refused form.

**Decision — the freeze list.** Brood 1.0 does not have:

| Refused | Instead | Where decided |
|---|---|---|
| Mutation of data: no `set!`, atoms, cells, transients | A `table` (the one mutable structure) or a process holding state | ADR-026, ADR-112 |
| `while`, `loop`, `recur` | Proper tail calls; `letrec` for a local loop; `doseq` for effect | ADR-154, ADR-674 |
| First-class continuations: `call/cc`, `dynamic-wind`, prompts | Processes and supervision; `try` for non-local exit | this ADR |
| Named arguments (`&key`) | A trailing options map with `{:keys …}` | ADR-163 |
| Reader metadata `^{}`, reader macros, `#(…)`, `#_` | A macro; `^` is the pattern pin; `(meta …)` is a form, not syntax | ADR-150 |
| A character type | A one-character string; the cursor unit is a grapheme cluster | ADR-159 |
| Digit-led tokens as names (`1_000`, `1N`, `1+`) | Reserved, so digit separators or a bigint suffix stay additive | ADR-169 |
| `#` forms beyond `#{…}`, `#b"…"` and the record form the printer writes (`#point{…}`), including `#\|…\|#` | Reserved, so each future `#` literal is additive | ADR-169, ADR-150, ADR-542 |
| `contains?` answering by index on a vector | Refused by name; `contains?` asks about keys | ADR-156 |
| Strings as sequences | `string/->list` or `string/->graphemes`, chosen by the caller | ADR-156, ADR-159 |
| Unbounded laziness, `lazy-seq` | Seq-views fuse pipelines; a process holds unbounded state | deferred.md #2 |
| Negation patterns `(not …)` | A `:when` guard | ADR-160 |
| `:as` in a map pattern | `(and whole {…})` | ADR-160 |
| Dispatch inferred from a `:type` field | A record's identity, given at construction | ADR-168 |
| User-defined value kinds beyond `defrecord` | A record is the one nominal construct: `type-of` answers a closed set of built-in kinds (`:record` for every record) and `record-id` the nominal id | ADR-542 |
| More than one spelling per thing | `lambda`, `let*`, `car`/`cdr`, `concat`, `some?`, `length`, `dotimes`, `dolist`, `unless`, `match*` removed; each is in the rename ledger | ADR-098, ADR-154, ADR-162, ADR-674 |
| Redefining a shipped name | An ability, `let` shadowing, or a namespaced name | ADR-166 |

**What changed from ADR-170.**
- *Dropped:* ratios and multiple dispatch, both shipped as relaxations the freeze allows.
- *Restated:* "nominal types" becomes "user-defined value kinds beyond `defrecord`". A record
  is nominal since ADR-542 (a record never equals a map), so the old row's claim that
  `type-of` is `:map` and `=` stays structural is no longer true.
- *Added:* continuations. A continuation captures a process's control stack, which the
  explicit frame stack (ADR-416), the VM and the JIT would each have to reify, and the
  process model already answers the use cases: a generator is a process, an escape is
  `try`, and cleanup is a `finally` or a supervisor.
- *Extended:* the `#` reservation names the record form, and the spellings row names
  ADR-674's removals.

**Found while checking.** Two refusals raised from an internal instead of the function the
caller called, and both are fixed: `(contains? [1 2] 1)` reported `%map-get`, and
`(map "ab" f)` reported `first`. Guard: `tests/error_wording_test.blsp`.

**Consequences.** The freeze list is current at 1.0. As in ADR-170, any row may later be
relaxed without breaking a 1.0 program; adding a row after 1.0 is a break.

## ADR-714 — A release publishes its runtimes, and `nest release --target` downloads them

**Status:** accepted (2026-11-11). **Amends** ADR-038, which left the runtime for another
target to the user: "the user provides a pre-built `brood` for the target."

**Context.** `road-to-1.0.md` §D. `nest release --target T` appends an app to a lean
runtime built for `T`. For any target but the host, that runtime had to be built on or for
`T` by hand and copied into `~/.cache/brood/runtimes/T/`, so shipping a Windows build of an
app from Linux needed a Windows machine with Rust. The releases published toolchains for
Linux (glibc) and macOS only, so there was nothing to download for Windows or for a Linux
without glibc, and the installer was a shell script.

**Decision.**
1. **Every release publishes, per target, the toolchain and the lean runtime**, each with a
   `.sha256` beside it: `brood-vX-T.tar.gz` (`.zip` on Windows) and `brood-runtime-vX-T`
   (`.exe` on Windows). The runtime is the same build the toolchain's `nest` embeds, so a
   host release and a downloaded one append to the same bytes. The targets are Linux
   x86_64 and aarch64 (glibc), Linux x86_64 musl (static), macOS arm64 and x86_64, and
   Windows x86_64. Every build but musl carries the window (the CPU and GPU backends, no
   audio); a static musl binary cannot load the display libraries a window opens at run
   time, so it is headless, for servers and containers.
2. **`nest release --target T` downloads the runtime it lacks.** The order is `--runtime`,
   then a runtime placed by hand in `runtimes/T/`, then one downloaded before, then a
   download from the release matching this `nest`'s version, kept under
   `runtimes/vX/T/`. Keyed by version, because a runtime is right only for the release that
   built it. The download is Brood (`project-release/fetch-runtime`), over
   `package/fetch-bytes`.
3. **The download is checked, and the check is not optional.** The runtime's SHA-256 must
   equal the digest its `.sha256` names, or nothing is written. The installers hold the
   same rule: no sidecar, or no tool to hash with, stops the install.
4. **One line installs the toolchain on each platform**: `curl -fsSL
   https://brood.fly.dev/install.sh | sh` on Linux and macOS (the static build where there is
   no glibc), and `irm https://brood.fly.dev/install.ps1 | iex` in PowerShell on Windows.
5. **`release.yml` has a dry run** (`workflow_dispatch` with `dry_run`): every target is built
   from the branch and kept as workflow artifacts, nothing published, so a change to the
   release is tried before a tag. A manual run for a tag now builds the tag; it built the
   dispatched branch's head.

**What the checksum proves.** The sidecar comes from the same release over the same HTTPS
connection as the file, so it catches a corrupt or truncated download and a file replaced
without its sidecar, not a compromised release. Signing the release is the stronger guard,
and it is additive.

**Rejected.**
- *Cross-compiling the runtime in `nest release`:* it needs each target's Rust toolchain and
  C compiler on the releasing machine, which is the burden this removes.
- *Embedding every target's runtime in `nest`:* six runtimes in every install, most never
  used.
- *A musl build with the window:* static musl cannot load the display libraries.

**Consequences.** A project on Linux can ship Windows, macOS and static Linux binaries with
`nest release --target …` and no other machine. Guards: `tests/project_test.blsp` (a
matching download is kept, a mismatched one refused and nothing written, a missing one
named), `crates/nest/src/release.rs` tests (what is downloaded and where it is kept).
v0.51.0 is the first release with runtimes.

## ADR-715 — The supported platforms at 1.0, by what CI proves on each

**Status:** accepted (2026-11-12).

**Context.** `road-to-1.0.md` §D asked whether macOS and Windows must run the full suite
before 1.0, and for the answer to be written down as the supported-platform list. ADR-714
publishes six targets. They are not tested equally, and the list should say so rather
than imply it.

**Decision.** A platform's tier is what CI proves on it, nothing more.
1. **Tier 1: Linux x86_64 (glibc).** The full suite on every push, `full.yml` nightly,
   the weekly soak, the sanitizer runs and the downstream bedit smoke. A red here blocks a
   release.
2. **Tier 2: macOS arm64 and Windows x86_64.** Every push builds them and runs the platform
   smoke set (`scripts/ci/platform-smoke.sh`: paths, files, processes, the pty, the
   clipboard, text width), and both jobs gate the merge. Not the full suite: most of the
   suite is the language, which does not change with the OS, and the smoke set holds the
   files where the OS shows through.
3. **Tier 3: Linux aarch64 (glibc), Linux x86_64 musl (static, headless) and macOS
   x86_64.** Built and published by every release, and their runtimes are what
   `nest release --target` downloads. CI tests nothing on them beyond the build.

**Running the full suite on macOS or Windows is not required for 1.0.** It is additive
(ADR-011): moving a platform up a tier breaks nobody.

**Rejected.** *The full suite on macOS and Windows before 1.0:* runner time several times
Linux's on every push, to retest a language that the smoke set already shows is the same on
each OS.

**Consequences.** README's install section and `docs/release.md` can name the tiers. A bug
found on a tier-3 platform is fixed like any other, and the fix's guard runs on tier 1
unless it is about the platform.

## ADR-716 — The surface pass: names that broke a rule already set

**Status:** accepted (2026-11-12).

**Context.** `road-to-1.0.md` §F: a rename after 1.0 costs a deprecation window, so a misnamed
public name is cheapest now. A sweep of every public std name (2,373), the `nest` flags and
the manifest keys looked for names that break a rule an earlier ADR already set. It did not
look for names that are merely a matter of taste. This ADR records the first batch: each
change below applies an existing rule, so none of them is a new decision. The larger
questions the sweep raised (regex and fuzzy argument order, prefixed settings, per-type
lengths, the `editor/*` prefixes) are decided separately.

**Decision.**
1. **Conversions use the arrow (ADR-239):** `text/from-string` → `text/string->`,
   `path/to-file-uri` → `path/->file-uri`, `path/from-file-uri` → `path/file-uri->`,
   `io/port-fn` → `io/port->fn`.
2. **`!` means "raises" (ADR-302):** `registry/put!`, `put-new!` and `remove!`,
   `repl/start-in!` and `stdimage/retract-registration!` lose the bang. None of them raises.
3. **One spelling per thing (ADR-300, ADR-713):**
   - `agent/start-link` is removed. `agent/start` takes `{:link true}`, as `gen/start` does
     since ADR-433.
   - `editor/buffer-server/delete-buffer` (an alias of `stop-buffer`) is removed.
   - `io/fn-port` (it was `identity`) is removed.
   - `seq/but-last` is removed for `(seq/drop-last xs 1)`. The prelude keeps a private
     `%but-last`, because `receive` and `try` need it before `seq` loads.
   - `nest`: `--jobs` (an alias of `--max-parallel`) and `nest test --doc FILE` (the same as
     `nest doctest FILE`) are removed.
4. **No doubled module prefix (ADR-236):** `url/parse-url` → `url/parse`.
5. **Pairs and families are spelled alike:**
   - `string/triml` and `trimr` → `trim-left` and `trim-right`, beside `pad-left` and
     `pad-right`.
   - `gui/texture-free` and `sound-free` → `free-texture` and `free-sound`, beside
     `alloc-texture` and `alloc-sound`.
   - `debug/dbg-stop`, `dbg-state` and `dbg-events` → `stop-debugger`, `debugger-state` and
     `debugger-events`, beside `start-debugger`.
   - `table/has?` → `table/contains?`, as maps, sets, `sorted` and `multimap` say.
   - `stream/for-each` → `stream/each`, after the bare `each`.
   - `nest release --output` → `--out`, as `nest docs` and `nest profile` spell it.
   - The manifest key `:width` → `:format-width`, beside the other `:format-*` keys.
   - `ansi/colour` → `ansi/color` and the attribute key `:underline-colour` →
     `:underline-color`, the only British spellings in the API.
6. **No abbreviations in a public name:** `test/r-*` and `opt?`/`opt-val` → `result-*` and
   `option?`/`option-value`; `reflect/scan-form-start-2` →
   `scan-form-start-and-previous`. `debug/tc-debugger` and `tc-span` become private.

Every renamed or removed public name is in the rename ledger, so a stale caller's error and
`nest check` name the replacement. A removal points at a call shape, which `--fix-renames`
names and leaves to a person.

**Consequences.** The `test/r-ms` rename also fixed a latent bug: `eval-server` and bedit called
that private by its qualified name from another module. It is public now, as
`test/result-ms`. The checker's "one element shorter" rule for `seq/but-last` now applies to
the prelude's `%but-last`, so user code calling `(seq/drop-last xs 1)` loses that precision
until the checker reads a literal count there.

## ADR-717 — `regex` and `fuzzy` take the subject first

**Status:** accepted (2026-11-12). **Applies** ADR-308 to two modules it missed.

**Context.** ADR-308 put the collection first across std, but `regex` and `fuzzy` kept the
pattern or query first: `(regex/split pattern s)` next to `(string/split s sep)`. The audit
that guards ADR-308 judges by parameter names, and its vocabulary did not include `pattern` or
`query`, so it passed them. This is ADR-308's own failure case: `(-> s (regex/split ","))`
splits the pattern, and because both arguments are strings nothing raises.

**Decision.** The text, rope or candidates come first:
- `(regex/match? s pattern)`, as are `matches?`, `find`, `find-all`, `replace`, `split` and
  `tokens`.
- `(regex/rope-find r pattern from)`, as are `rope-find-backward`, `rope-count` and
  `rope-spans`.
- `(regex/paint s prefix pattern suffix)`.
- `(fuzzy/match cand query)`, `(fuzzy/filter cands query)`, `(fuzzy/top cands query …)` and
  `(fuzzy/nearest candidates name)`.

Functions with one subject (`escape`, `scorer`, `edit-distance`) and the ranker's
session-first calls are unchanged.

**The guard.** The audit's vocabulary now counts `pattern`, `query` and `rules` as subjects,
and `cand`, `cands`, `candidates` and `r` as collections. `tests/audit_test.blsp`'s
"no public function puts a callback or index ahead of its collection" names `regex/split`
when its old order is put back.

**Why not a rename as well.** A rename makes every stale caller fail loudly, but each of
these names reads right, and a renamed pair would leave two spellings in the history of
every downstream project. Instead, every call site was examined by hand, in brood and
bedit, which is the only defence against a silent swap. The rename ledger cannot help here:
the names did not move.

**Consequences.** A downstream caller that passes the pattern first gets a wrong answer,
not an error. This is recorded in the changelog as the one break that needs reading call by
call.

## ADR-718 — The surface pass, second batch: duplicates and doubled prefixes

**Status:** accepted (2026-11-12).

**Context.** The rest of what the ADR-716 sweep found that an existing rule already decides:
per-type functions the bare vocabulary answers (ADR-253), two decimal constructors, the
retired `concat` (ADR-713), and settings whose names repeat their module (ADR-236, ADR-506).

**Decision.**
1. **`bytes/length`, `text/length` and `table/count` are removed for bare `count`.** Each one
   called the primitive `count` dispatches to (`%byte-length`, `%rope-length` or
   `string/length`, and `%table-count`), so the answers are identical. On bytes, `count` is
   faster, because the VM and JIT inline it. `string/length` fails the same test, but it is
   the primitive `count` calls on a string and has about 1,100 call sites, so it stays for
   now as an open question.
2. **`decimal/of` is the one way to a decimal; `decimal/number->` is removed.** The two
   disagreed on a float: `of` used its shortest round-trip form (`0.1` → `0.1M`), and
   `number->` used its exact binary expansion. `of` now also takes a ratio, the one case only
   `number->` handled.
3. **`bytes/concat` → `bytes/append` and `stream/concat` → `stream/append`.** Bare `append`
   returns a list, so these shadow it, as `stream/map` shadows `map`. `bytes/append` was a
   file-writing function until 2026-08-27, when it became `file/spit-bytes-append`. Nothing
   in brood or bedit still called the old meaning.
4. **The 47 settings that repeated their module's name drop the prefix**, for example
   `editor/ui/*ui-slow-ms*` → `*slow-ms*` and `http/*http-read-timeout-ms*` →
   `http/*read-timeout-ms*`.
   - The 31 that nothing outside their file read become private.
   - The rest stay public under the short name: those read from another module, documented
     as user settings (`test/*slow-ms*`, the http timeouts beside the public size limits),
     or `defonce` tables, which have no private form.
   - The editor watchdog defaults are private because each already has a model key that
     overrides it (`:slow-ms`, `:fold-budget-ms`, `:event-ceiling-ms`).

**A bug the rename found.** `eval-server` wrote `(def *test-formatter* …)` unqualified, which
binds `eval-server/*test-formatter*`, a global the test runner never reads. The progress
dots it meant to silence were never silenced. It now writes `test/*formatter*`.

**Left for later.** Private settings with the same doubled prefix (`project-image`'s
`*project-image-includes-file*`, repl's `*repl-rc-loaded*`, `project.blsp`'s
`*project-…*`) are not public surface, so they cost nothing to rename after 1.0.

## ADR-719 — An `editor/*` accessor keeps its module's noun

**Status:** accepted (2026-11-12). **Records** the carve-out from ADR-236 that the editor
modules have always had.

**Context.** ADR-236 drops a module's name from its own functions (`url/parse`, not
`url/parse-url`). Its rollout never reached `editor/*`, where about 130 public names still
repeat their module: `buffer-text`, `buffer-point`, `pane-count`, `lineedit-insert`,
`keymap-merge`. The surface pass (ADR-716) had to decide whether that is a leftover or a rule.

**It is a rule, for a reason the other modules don't share: apps `:use` these modules and call
them bare.** bedit has 153 files with `(:use editor/buffer)`, and `buffer-*` appears about
4,500 times there. Without the prefix, those files would hold bare `text`, `point`, `mark`,
`name`, `file`, `length`, `count`, `split` and `delete`:
- A local named `text` or `point`, which is in nearly every editor function, would silently
  shadow the function within its scope. `(text b)` would then call a string.
- `count`, `merge`, `update` and `split` would clash with the core functions of the same name.
- Elsewhere a caller writes `url/parse`, and the qualifier does the prefix's job. Here the
  prefix is the only qualifier a `:use`ing file has.

**Decision.** A public function in an `editor/*` module keeps the module's noun as a prefix
when it reads or queries that noun: `buffer-text`, `pane-count`, `lineedit-history-prev`,
`keymap-resolve`. A verb that acts on the noun and could not be confused with a local or a
core name may go without it: `insert`, `narrowed?`, `goto-char`. Settings follow ADR-718 and
drop the prefix, because a setting is always written qualified.

**Consequences.** No names change. A new `editor/*` accessor takes the prefix, and the surface
audit should not report `editor/*` names as doubled prefixes.
