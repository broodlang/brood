# Design decisions: numbers 700 to 799

One of the files the ADR log is split across by number; the index, and the notes that
apply to every entry, are in [../decisions.md](../decisions.md).

## ADR-710 — `string/scripts` and `string/mixed-script?`: the Script property, and TR39's single-script test

**Status:** implemented (2026-11-11).

**Context.** A Cyrillic `а` (U+0430) looks like a Latin `a`, so `pаypal` reads as `paypal`. An
editor wants to mark an identifier or a URL that mixes scripts the way a homoglyph does (Emacs's
`textsec.el`, VS Code's ambiguous-character highlight); a package registry wants to refuse a
package name that imitates another; a mail reader wants to flag a sender's display name. Each
needs the Unicode Script property of a character, which is table data Brood did not have.

**Decision.** One native and one std function.

- `(string/scripts s)` (`builtins/string.rs`, over the `unicode-script` crate already in the tree
  through cosmic-text) — the scripts of `s`'s characters as keywords (`:latin`, `:cyrillic`,
  `:old-italic`), in order of first appearance, none twice. Common (digits, punctuation, spaces),
  Inherited (combining marks) and Unknown are left out: they belong to every script, so
  `(string/scripts "v1.2")` is `[:latin]`.
- `(string/mixed-script? s)` (`std/string.blsp`, Brood) — UTS #39's "highly restrictive" level:
  false for one script, for Han with kana, Hangul or Bopomofo (its augmented script sets), and
  for any of those with Latin; true for the rest, Latin with Cyrillic or Greek above all. The
  rule is policy over the property, so it is Brood; the property is data, so it is native.

**Not done.** UTS #39's *confusables* (`confusables.txt`, the skeleton that makes the whole-script
`раураl` — all Cyrillic — compare equal to `paypal`) need the `unicode-security` crate's tables
or a generated std table; a word in ONE script is not flagged. Script_Extensions (a character
several scripts share, U+30FC) are read as the character's single Script value.

## ADR-711 — `mcp-server`: the MCP protocol out of `nest mcp`, for any program that serves tools to an agent

**Status.** Accepted (2026-11-11).

**Context.** `std/tool/mcp.blsp` held the whole Model Context Protocol server — the JSON-RPC
dispatch, the handler run in a monitored process of its own with stdout captured, the deadline,
the projection of Brood data onto JSON — bound to stdio and to `nest mcp`'s catalogue, in a DEV
module a shipped runtime does not carry. An editor that hands a coding agent its own tools (its
buffers, diagnostics, the tests it can run) needs exactly that dispatcher, served from inside
its own event loop and shipped with it; so does an agent harness exposing its file tools to a
CLI agent. `docs/mcp.md` had foreseen it: "the Brood half ports unchanged; only the transport
re-hosts".

**Decision.**
1. **A runtime module, `mcp-server`** (`std/mcp-server.blsp`), holds the protocol. A SERVER is a
   plain map: `:catalogue` (a fn answering `{:name :description :schema :handler}` entries, read
   on every request), `:info`, `:capabilities`, `:methods` (more JSON-RPC methods, `name -> (fn
   (params server) [status payload])`, answered before the built-in ones), `:emit` (where a
   progress notification goes), `:deadline-ms` and `:deadline-tools`. `handle` and `respond`
   answer one message; `json-data`, `pretty-json`, `listed-tool`, `rpc-error` and `progress` are
   public, so a server built elsewhere shapes its results the same way.
2. **Two transports.** `serve-stdio` — newline-delimited JSON, with an optional per-reply step
   (`nest mcp` carries its staleness warning on it). `http-handler` / `start-http` — MCP's
   streamable-HTTP transport with JSON responses only: a POST carries one message and gets one
   reply (202 for a notification, 405 for anything but POST), on loopback only and only with a
   secret token (`http/loopback-only`, `http/require-token`). `start-http` listens on an
   OS-assigned port in a process of its own and answers `{:pid :port :token :url}`.
3. **`nest mcp` is one server spec over it**: its catalogue, the reference documents as
   resources, the `brood-task` prompt (as `:methods`), the deadline on `eval` / `load`. Its
   behaviour is unchanged; `mcp/progress` is `mcp-server/progress`.

**Rejected.** *Leave it in `nest mcp` and let applications copy it*: the handler isolation and
the JSON projection are the subtle parts, and they would drift. *A stdio-only server, with a
relay process an agent launches to reach an application's port* (what an agent harness had
built): one more process and one more protocol hop for every call, when an agent CLI that
speaks MCP speaks HTTP too. *Server-sent events on the HTTP transport*: no client this serves
needs a notification mid-call yet; a JSON response is the smaller transport the spec allows.

**Consequences.** `mcp-server` ships in every runtime; `mcp` stays a dev module. A progress
report over HTTP goes to the server's `:emit`, not to the client. Guards: `tests/mcp_test.blsp`
(nest's server, through the shared dispatcher), `tests/mcp_server_test.blsp` (a spec of its own,
`:methods`, the deadline, HTTP with and without the token, a notification, GET).

## ADR-712 — `insert-program-output`: text a program writes, which undo steps over

**Status.** Accepted (2026-11-11).

**Context.** `std/editor/buffer`'s undo restores whole snapshots (`{:rope :point :mark …}`).
In a buffer that a program writes into while a person types (a shell's output above its
prompt, an agent's reply above the message being written), undoing what the person typed
restored a snapshot from before the program's later output, and so took that output away
(redo brought it back). bedit's agent chat turned undo off to avoid this; bshell and a
line-mode terminal had the same problem.

**Decision.** `(insert-program-output buf at text &optional properties)` inserts `text` as though it
had always been there:
- into the buffer, and into every snapshot of its history (`:undo`, `:pending-undo`), at the
  same position;
- recording nothing;
- point, mark, markers, narrowing and text properties move as any insertion moves them;
- a read-only or narrowed buffer takes it, because the text is the program's, not an edit.

Each snapshot goes through the same insertion as the buffer itself (restored into a widened,
unrecorded copy, inserted into, snapshotted again), so there is no second implementation of
how an insertion moves things.

**Rejected.**
- *Delta undo, Emacs's `buffer-undo-list`:* the whole undo model replaced, for one case that
  this covers exactly.
- *Turning undo off in such buffers:* a person loses undo of their own typing.
- *Re-applying the output after each undo:* the history would still hold states the buffer
  never had.

**Consequences.**
- The result is exact when the text before `at` is the same in every snapshot, which is how
  every program buffer is laid out (output above input). Elsewhere a snapshot gets the text at
  the same offset, clamped.
- The cost is one insertion per snapshot, bounded by the undo limit. `:undo-size` does not
  count the output.
- Guards: `tests/buffer_output_test.blsp`. It covers undo, a run of undos, redo, point,
  markers, narrowing and properties.

**Amendment (2026-11-12): `replace-program-output`.** A shell's output is not only inserted:
a carriage return in a progress counter (`10%\r20%`) REPLACES the line the program wrote
before. `(replace-program-output buf from to text &optional properties)` replaces `[from, to)`
the same way, in the buffer and every snapshot, recording nothing; `insert-program-output` is
it over an empty range. A position inside the replaced range lands at its start; one past it
moves by the change in length. Exact when the text up to `to` is the same in every snapshot.
bedit's shell and compile buffers write their output through it.

## ADR-713 — The 1.0 freeze list, restated

**Status:** accepted (2026-11-11). **Supersedes** ADR-170's table. ADR-170's principle and its
"what this list is not" section stand unchanged.

**Context.** ADR-170 gathered what Brood permanently does not have, so a "why not X?" has one
answer. Since it was written, two rows shipped (ratios, ADR-196; multiple dispatch, ADR-179),
the "nominal types" row went stale when a record became its own value kind (ADR-542: `type-of`
is `:record`, not `:map`), and continuations were refused in practice without being listed.
`road-to-1.0.md` §A asks for the table as it stands at 1.0. Every row below was checked
against the running language on 2026-11-11, by evaluating the refused form.

**Decision — the freeze list.** Brood 1.0 does not have:

| Refused | Instead | Where decided |
|---|---|---|
| Mutation of data: no `set!`, atoms, cells, transients | A `table` (the one mutable structure) or a process holding state | ADR-026, ADR-112 |
| `while`, `loop`, `recur` | Proper tail calls; `letrec` for a local loop; `doseq` for effect | ADR-154, ADR-674 |
| First-class continuations: `call/cc`, `dynamic-wind`, prompts | Processes and supervision; `try` for non-local exit | this ADR |
| Named arguments (`&key`) | A trailing options map with `{:keys …}` | ADR-163 |
| Reader metadata `^{}`, reader macros, `#(…)`, `#_` | A macro; `^` is the pattern pin; `(meta …)` is a form, not syntax | ADR-150 |
| A character type | A one-character string; the cursor unit is a grapheme cluster | ADR-159 |
| Digit-led tokens as names (`1_000`, `1N`, `1+`) | Reserved, so digit separators or a bigint suffix stay additive | ADR-169 |
| `#` forms beyond `#{…}`, `#b"…"` and the record form the printer writes (`#point{…}`), including `#\|…\|#` | Reserved, so each future `#` literal is additive | ADR-169, ADR-150, ADR-542 |
| `contains?` answering by index on a vector | Refused by name; `contains?` asks about keys | ADR-156 |
| Strings as sequences | `string/->list` or `string/->graphemes`, chosen by the caller | ADR-156, ADR-159 |
| Unbounded laziness, `lazy-seq` | Seq-views fuse pipelines; a process holds unbounded state | deferred.md #2 |
| Negation patterns `(not …)` | A `:when` guard | ADR-160 |
| `:as` in a map pattern | `(and whole {…})` | ADR-160 |
| Dispatch inferred from a `:type` field | A record's identity, given at construction | ADR-168 |
| User-defined value kinds beyond `defrecord` | A record is the one nominal construct: `type-of` answers a closed set of built-in kinds (`:record` for every record) and `record-id` the nominal id | ADR-542 |
| More than one spelling per thing | `lambda`, `let*`, `car`/`cdr`, `concat`, `some?`, `length`, `dotimes`, `dolist`, `unless`, `match*` removed; each is in the rename ledger | ADR-098, ADR-154, ADR-162, ADR-674 |
| Redefining a shipped name | An ability, `let` shadowing, or a namespaced name | ADR-166 |

**What changed from ADR-170.**
- *Dropped:* ratios and multiple dispatch, both shipped as relaxations the freeze allows.
- *Restated:* "nominal types" becomes "user-defined value kinds beyond `defrecord`". A record
  is nominal since ADR-542 (a record never equals a map), so the old row's claim that
  `type-of` is `:map` and `=` stays structural is no longer true.
- *Added:* continuations. A continuation captures a process's control stack, which the
  explicit frame stack (ADR-416), the VM and the JIT would each have to reify, and the
  process model already answers the use cases: a generator is a process, an escape is
  `try`, and cleanup is a `finally` or a supervisor.
- *Extended:* the `#` reservation names the record form, and the spellings row names
  ADR-674's removals.

**Found while checking.** Two refusals raised from an internal instead of the function the
caller called, and both are fixed: `(contains? [1 2] 1)` reported `%map-get`, and
`(map "ab" f)` reported `first`. Guard: `tests/error_wording_test.blsp`.

**Consequences.** The freeze list is current at 1.0. As in ADR-170, any row may later be
relaxed without breaking a 1.0 program; adding a row after 1.0 is a break.

## ADR-714 — A release publishes its runtimes, and `nest release --target` downloads them

**Status:** accepted (2026-11-11). **Amends** ADR-038, which left the runtime for another
target to the user: "the user provides a pre-built `brood` for the target."

**Context.** `road-to-1.0.md` §D. `nest release --target T` appends an app to a lean
runtime built for `T`. For any target but the host, that runtime had to be built on or for
`T` by hand and copied into `~/.cache/brood/runtimes/T/`, so shipping a Windows build of an
app from Linux needed a Windows machine with Rust. The releases published toolchains for
Linux (glibc) and macOS only, so there was nothing to download for Windows or for a Linux
without glibc, and the installer was a shell script.

**Decision.**
1. **Every release publishes, per target, the toolchain and the lean runtime**, each with a
   `.sha256` beside it: `brood-vX-T.tar.gz` (`.zip` on Windows) and `brood-runtime-vX-T`
   (`.exe` on Windows). The runtime is the same build the toolchain's `nest` embeds, so a
   host release and a downloaded one append to the same bytes. The targets are Linux
   x86_64 and aarch64 (glibc), Linux x86_64 musl (static), macOS arm64 and x86_64, and
   Windows x86_64. Every build but musl carries the window (the CPU and GPU backends, no
   audio); a static musl binary cannot load the display libraries a window opens at run
   time, so it is headless, for servers and containers.
2. **`nest release --target T` downloads the runtime it lacks.** The order is `--runtime`,
   then a runtime placed by hand in `runtimes/T/`, then one downloaded before, then a
   download from the release matching this `nest`'s version, kept under
   `runtimes/vX/T/`. Keyed by version, because a runtime is right only for the release that
   built it. The download is Brood (`project-release/fetch-runtime`), over
   `package/fetch-bytes`.
3. **The download is checked, and the check is not optional.** The runtime's SHA-256 must
   equal the digest its `.sha256` names, or nothing is written. The installers hold the
   same rule: no sidecar, or no tool to hash with, stops the install.
4. **One line installs the toolchain on each platform**: `curl -fsSL
   https://brood.fly.dev/install.sh | sh` on Linux and macOS (the static build where there is
   no glibc), and `irm https://brood.fly.dev/install.ps1 | iex` in PowerShell on Windows.
5. **`release.yml` has a dry run** (`workflow_dispatch` with `dry_run`): every target is built
   from the branch and kept as workflow artifacts, nothing published, so a change to the
   release is tried before a tag. A manual run for a tag now builds the tag; it built the
   dispatched branch's head.

**What the checksum proves.** The sidecar comes from the same release over the same HTTPS
connection as the file, so it catches a corrupt or truncated download and a file replaced
without its sidecar, not a compromised release. Signing the release is the stronger guard,
and it is additive.

**Rejected.**
- *Cross-compiling the runtime in `nest release`:* it needs each target's Rust toolchain and
  C compiler on the releasing machine, which is the burden this removes.
- *Embedding every target's runtime in `nest`:* six runtimes in every install, most never
  used.
- *A musl build with the window:* static musl cannot load the display libraries.

**Consequences.** A project on Linux can ship Windows, macOS and static Linux binaries with
`nest release --target …` and no other machine. Guards: `tests/project_test.blsp` (a
matching download is kept, a mismatched one refused and nothing written, a missing one
named), `crates/nest/src/release.rs` tests (what is downloaded and where it is kept).
v0.51.0 is the first release with runtimes.

## ADR-715 — The supported platforms at 1.0, by what CI proves on each

**Status:** accepted (2026-11-12).

**Context.** `road-to-1.0.md` §D asked whether macOS and Windows must run the full suite
before 1.0, and for the answer to be written down as the supported-platform list. ADR-714
publishes six targets. They are not tested equally, and the list should say so rather
than imply it.

**Decision.** A platform's tier is what CI proves on it, nothing more.
1. **Tier 1: Linux x86_64 (glibc).** The full suite on every push, `full.yml` nightly,
   the weekly soak, the sanitizer runs and the downstream bedit smoke. A red here blocks a
   release.
2. **Tier 2: macOS arm64 and Windows x86_64.** Every push builds them and runs the platform
   smoke set (`scripts/ci/platform-smoke.sh`: paths, files, processes, the pty, the
   clipboard, text width), and both jobs gate the merge. Not the full suite: most of the
   suite is the language, which does not change with the OS, and the smoke set holds the
   files where the OS shows through.
3. **Tier 3: Linux aarch64 (glibc), Linux x86_64 musl (static, headless) and macOS
   x86_64.** Built and published by every release, and their runtimes are what
   `nest release --target` downloads. CI tests nothing on them beyond the build.

**Running the full suite on macOS or Windows is not required for 1.0.** It is additive
(ADR-011): moving a platform up a tier breaks nobody.

**Rejected.** *The full suite on macOS and Windows before 1.0:* runner time several times
Linux's on every push, to retest a language that the smoke set already shows is the same on
each OS.

**Consequences.** README's install section and `docs/release.md` can name the tiers. A bug
found on a tier-3 platform is fixed like any other, and the fix's guard runs on tier 1
unless it is about the platform.

## ADR-716 — The surface pass: names that broke a rule already set

**Status:** accepted (2026-11-12).

**Context.** `road-to-1.0.md` §F: a rename after 1.0 costs a deprecation window, so a misnamed
public name is cheapest now. A sweep of every public std name (2,373), the `nest` flags and
the manifest keys looked for names that break a rule an earlier ADR already set. It did not
look for names that are merely a matter of taste. This ADR records the first batch: each
change below applies an existing rule, so none of them is a new decision. The larger
questions the sweep raised (regex and fuzzy argument order, prefixed settings, per-type
lengths, the `editor/*` prefixes) are decided separately.

**Decision.**
1. **Conversions use the arrow (ADR-239):** `text/from-string` → `text/string->`,
   `path/to-file-uri` → `path/->file-uri`, `path/from-file-uri` → `path/file-uri->`,
   `io/port-fn` → `io/port->fn`.
2. **`!` means "raises" (ADR-302):** `registry/put!`, `put-new!` and `remove!`,
   `repl/start-in!` and `stdimage/retract-registration!` lose the bang. None of them raises.
3. **One spelling per thing (ADR-300, ADR-713):**
   - `agent/start-link` is removed. `agent/start` takes `{:link true}`, as `gen/start` does
     since ADR-433.
   - `editor/buffer-server/delete-buffer` (an alias of `stop-buffer`) is removed.
   - `io/fn-port` (it was `identity`) is removed.
   - `seq/but-last` is removed for `(seq/drop-last xs 1)`. The prelude keeps a private
     `%but-last`, because `receive` and `try` need it before `seq` loads.
   - `nest`: `--jobs` (an alias of `--max-parallel`) and `nest test --doc FILE` (the same as
     `nest doctest FILE`) are removed.
4. **No doubled module prefix (ADR-236):** `url/parse-url` → `url/parse`.
5. **Pairs and families are spelled alike:**
   - `string/triml` and `trimr` → `trim-left` and `trim-right`, beside `pad-left` and
     `pad-right`.
   - `gui/texture-free` and `sound-free` → `free-texture` and `free-sound`, beside
     `alloc-texture` and `alloc-sound`.
   - `debug/dbg-stop`, `dbg-state` and `dbg-events` → `stop-debugger`, `debugger-state` and
     `debugger-events`, beside `start-debugger`.
   - `table/has?` → `table/contains?`, as maps, sets, `sorted` and `multimap` say.
   - `stream/for-each` → `stream/each`, after the bare `each`.
   - `nest release --output` → `--out`, as `nest docs` and `nest profile` spell it.
   - The manifest key `:width` → `:format-width`, beside the other `:format-*` keys.
   - `ansi/colour` → `ansi/color` and the attribute key `:underline-colour` →
     `:underline-color`, the only British spellings in the API.
6. **No abbreviations in a public name:** `test/r-*` and `opt?`/`opt-val` → `result-*` and
   `option?`/`option-value`; `reflect/scan-form-start-2` →
   `scan-form-start-and-previous`. `debug/tc-debugger` and `tc-span` become private.

Every renamed or removed public name is in the rename ledger, so a stale caller's error and
`nest check` name the replacement. A removal points at a call shape, which `--fix-renames`
names and leaves to a person.

**Consequences.** The `test/r-ms` rename also fixed a latent bug: `eval-server` and bedit called
that private by its qualified name from another module. It is public now, as
`test/result-ms`. The checker's "one element shorter" rule for `seq/but-last` now applies to
the prelude's `%but-last`, so user code calling `(seq/drop-last xs 1)` loses that precision
until the checker reads a literal count there.

## ADR-717 — `regex` and `fuzzy` take the subject first

**Status:** accepted (2026-11-12). **Applies** ADR-308 to two modules it missed.

**Context.** ADR-308 put the collection first across std, but `regex` and `fuzzy` kept the
pattern or query first: `(regex/split pattern s)` next to `(string/split s sep)`. The audit
that guards ADR-308 judges by parameter names, and its vocabulary did not include `pattern` or
`query`, so it passed them. This is ADR-308's own failure case: `(-> s (regex/split ","))`
splits the pattern, and because both arguments are strings nothing raises.

**Decision.** The text, rope or candidates come first:
- `(regex/match? s pattern)`, as are `matches?`, `find`, `find-all`, `replace`, `split` and
  `tokens`.
- `(regex/rope-find r pattern from)`, as are `rope-find-backward`, `rope-count` and
  `rope-spans`.
- `(regex/paint s prefix pattern suffix)`.
- `(fuzzy/match cand query)`, `(fuzzy/filter cands query)`, `(fuzzy/top cands query …)` and
  `(fuzzy/nearest candidates name)`.

Functions with one subject (`escape`, `scorer`, `edit-distance`) and the ranker's
session-first calls are unchanged.

**The guard.** The audit's vocabulary now counts `pattern`, `query` and `rules` as subjects,
and `cand`, `cands`, `candidates` and `r` as collections. `tests/audit_test.blsp`'s
"no public function puts a callback or index ahead of its collection" names `regex/split`
when its old order is put back.

**Why not a rename as well.** A rename makes every stale caller fail loudly, but each of
these names reads right, and a renamed pair would leave two spellings in the history of
every downstream project. Instead, every call site was examined by hand, in brood and
bedit, which is the only defence against a silent swap. The rename ledger cannot help here:
the names did not move.

**Consequences.** A downstream caller that passes the pattern first gets a wrong answer,
not an error. This is recorded in the changelog as the one break that needs reading call by
call.

## ADR-718 — The surface pass, second batch: duplicates and doubled prefixes

**Status:** accepted (2026-11-12).

**Context.** The rest of what the ADR-716 sweep found that an existing rule already decides:
per-type functions the bare vocabulary answers (ADR-253), two decimal constructors, the
retired `concat` (ADR-713), and settings whose names repeat their module (ADR-236, ADR-506).

**Decision.**
1. **`bytes/length`, `text/length` and `table/count` are removed for bare `count`.** Each one
   called the primitive `count` dispatches to (`%byte-length`, `%rope-length` or
   `string/length`, and `%table-count`), so the answers are identical. On bytes, `count` is
   faster, because the VM and JIT inline it. **`string/length` goes too** (decided the same
   day): the same answer on a string, and the compiled tiers inline `count` to the same
   cached character count. Its primitive is the internal `%string-length`, which `count`
   and the prelude call. About 1,100 call sites in brood and 700 in bedit moved.
2. **`decimal/of` is the one way to a decimal; `decimal/number->` is removed.** The two
   disagreed on a float: `of` used its shortest round-trip form (`0.1` → `0.1M`), and
   `number->` used its exact binary expansion. `of` now also takes a ratio, the one case only
   `number->` handled.
3. **`bytes/concat` → `bytes/append` and `stream/concat` → `stream/append`.** Bare `append`
   returns a list, so these shadow it, as `stream/map` shadows `map`. `bytes/append` was a
   file-writing function until 2026-08-27, when it became `file/spit-bytes-append`. Nothing
   in brood or bedit still called the old meaning.
4. **The 47 settings that repeated their module's name drop the prefix**, for example
   `editor/ui/*ui-slow-ms*` → `*slow-ms*` and `http/*http-read-timeout-ms*` →
   `http/*read-timeout-ms*`.
   - The 31 that nothing outside their file read become private.
   - The rest stay public under the short name: those read from another module, documented
     as user settings (`test/*slow-ms*`, the http timeouts beside the public size limits),
     or `defonce` tables, which have no private form.
   - The editor watchdog defaults are private because each already has a model key that
     overrides it (`:slow-ms`, `:fold-budget-ms`, `:event-ceiling-ms`).

**A bug the rename found.** `eval-server` wrote `(def *test-formatter* …)` unqualified, which
binds `eval-server/*test-formatter*`, a global the test runner never reads. The progress
dots it meant to silence were never silenced. It now writes `test/*formatter*`.

**Private settings too.** The 19 private settings with the same doubled prefix
(`project-image`'s `*project-image-includes-file*`, repl's `*repl-rc-loaded*`, the
`*project-…*` in `project` and `project-check`) are shortened as well.

**What shortening cost: KI-383.** An unqualified `defdyn` inside a module declares a ROOT
name, and once a name is declared dynamic, every module's `*x*` resolves to root. Two
shortened settings, lineedit's `*indent-width*` and coverage's `*targets*`, matched a
root `defdyn` in bedit. With std loaded from source, bedit's variable took them over. They
are now `body-indent` (a constant needs no earmuffs) and `*instrumented*`. Every short name
here was checked against bedit's root `defdyn`s. The hazard itself, and the fix to make an
unqualified `defdyn` in a module module-scoped, is KI-383.

## ADR-719 — An `editor/*` accessor keeps its module's noun

**Status:** accepted (2026-11-12). **Records** the carve-out from ADR-236 that the editor
modules have always had.

**Context.** ADR-236 drops a module's name from its own functions (`url/parse`, not
`url/parse-url`). Its rollout never reached `editor/*`, where about 130 public names still
repeat their module: `buffer-text`, `buffer-point`, `pane-count`, `lineedit-insert`,
`keymap-merge`. The surface pass (ADR-716) had to decide whether that is a leftover or a rule.

**It is a rule, for a reason the other modules don't share: apps `:use` these modules and call
them bare.** bedit has 153 files with `(:use editor/buffer)`, and `buffer-*` appears about
4,500 times there. Without the prefix, those files would hold bare `text`, `point`, `mark`,
`name`, `file`, `length`, `count`, `split` and `delete`:
- A local named `text` or `point`, which is in nearly every editor function, would silently
  shadow the function within its scope. `(text b)` would then call a string.
- `count`, `merge`, `update` and `split` would clash with the core functions of the same name.
- Elsewhere a caller writes `url/parse`, and the qualifier does the prefix's job. Here the
  prefix is the only qualifier a `:use`ing file has.

**Decision.** A public function in an `editor/*` module keeps the module's noun as a prefix
when it reads or queries that noun: `buffer-text`, `pane-count`, `lineedit-history-prev`,
`keymap-resolve`. A verb that acts on the noun and could not be confused with a local or a
core name may go without it: `insert`, `narrowed?`, `goto-char`. Settings follow ADR-718 and
drop the prefix, because a setting is always written qualified.

**Consequences.** No names change. A new `editor/*` accessor takes the prefix, and the surface
audit should not report `editor/*` names as doubled prefixes.



## ADR-720 — A drain a process's data pins ends by copying the data out

**Status:** accepted (2026-11-12). **Amends** ADR-091's drain (Stage 3); KI-388, KI-389.

**Context.** ADR-091 reclaims the shared code region a generation at a time: age, migrate the
live globals into the new generation, then drain the old one, freeing it once every live
process reports that it holds nothing of it. A process that runs old code stops pinning when
the calls return. A process that HOLDS old values in its data stops only when the data dies,
and a long-lived one keeps its data for good: an editor's loop keeps its model, which holds
callbacks, closures and strings it read before the migration. The drain then never ends,
and each report re-walked the process's whole heap to find the same answer (KI-388). That
cost bedit 58% of its CPU while typing.

**Decision.** The process copies the values out. When the report finds it dirty, it asks for
a re-home, done at the next point that may rewrite its heap: the end of its own collection
(the collection's roots in hand), or the parked-process inspector over a parked heap.
Every draining-generation handle it holds privately (roots, delivered messages, dynamics,
memo stores, caught payloads, both generations of its local heap) is rewritten to the
value's copy in the current generation. It then reports clean. The live compiled arms on its
stack are not rewritten, because on a shared runtime they can be shared with other
processes. A process running old code is left to finish those calls, as before.

**One forwarding map per drain.** `=` on functions is handle identity, so the copies must be
the ones the migrated globals hold. `migrate_live_globals` keeps its map as
`RuntimeCode::drain_forward`; every re-home and every `def` of an old value
(`rehome_to_current_locked`) copies through it; ending the drain drops it.

**Rejected.**
- *Throttle harder.* The probe would still run for as long as the process lives, only less
  often, and the drain would still never free.
- *Re-home inside the report.* The JIT's safepoint holds the heap immutably, and a
  collection is where handles already move.
- *Compare functions by `identity`.* The field feeds a hash and is shared by contract shims,
  so it is not an equality.

**Consequences.** A drain ends within about one collection of each process, so aging, which
waits for the previous drain, can run again. Each aging clears every process's JIT and IC
caches, so its cost is now paid when it happens rather than never. A process that copies
out pays about one heap walk and one rewrite per drain, counted in its collection's pause;
a process that pins nothing pays nothing: the ask is read from the probe's own dirty-epoch
fields and the once-a-drain mark lives in the lazily boxed `HeapExtras` (`process_floor`).

## ADR-721 — A program says it is running by holding a file lock

**Status:** accepted (2026-11-13).

**Context.** Programs on one machine sometimes need to find each other: several bedit windows
each running agent sessions want to list all of them, a single-instance app wants to know
whether it is already open, and a tool wants the running `nest mcp` images. The usual answer,
a file per program with its pid in it, needs a way to ask whether that pid is alive, and pids
are reused: a crashed program's file can name a live stranger. Brood also had no way to read
its own pid. The runtime's own Rust already solved this for test scratch homes
(`cli_support.rs`): a directory belongs to a live run while a lock on its stamp is held.

**Decision.** Three kernel primitives over an OS advisory lock (`File::try_lock`: `flock` on
Unix, `LockFileEx` on Windows):
- `(file/lock path)` takes an exclusive lock, creating the file, and holds it for the life of
  the program: `true`, or a failure when another program holds it.
- `(file/unlock path)` releases it.
- `(file/locked? path)` asks whether any program holds it.

A lock belongs to the PROGRAM, not a process: the runtime keeps the open files in one table
keyed by absolute path. No handle value is returned, so no new value kind exists for it. The
OS drops the lock when the program exits, however it exits, so a lock still held means its
program still runs, and no pid is involved.

**Rejected.**
- *`os/pid` and `os/alive? pid`.* Pid reuse makes a stale file name a live stranger.
- *A lock handle closed by `os/close`.* It needs a new value kind for one use; holding for
  the program's life is what announcing presence wants.
- *Heartbeat files* (a timestamp rewritten every few seconds). That means a timer in every
  program, and a guess at how stale is dead.

**Consequences.** `file/locked?` takes a shared lock for an instant, so a `file/lock` racing
it can be refused once; a caller locking its own uniquely named file is not affected.
`file/lock` and `file/unlock` are world effects (`source-deps`), so a live evaluator does not
run them on a half-typed form. Guard: `tests/file_lock_test.blsp` (the second program is
util-linux's `flock`, the same `flock(2)` lock), also in the platform smoke
set on macOS and Windows.

## ADR-722 — A module's `defdyn` is the module's own; no name is ambient

**Status:** accepted (2026-11-13). **Amends** ADR-151 (ambient names). Closes KI-383.

**Context.** ADR-151 made a name root ("ambient") when it was declared with `defdyn`, wherever
the declaration sat. From then on every module's `*x*` resolved to that root variable, its
`def` heads included. A downstream project that wrote `(defdyn *x* …)` inside one of its own
modules therefore took over every std module's `*x*`: bedit's 116 such declarations included
`*indent-width*`, and with std loaded from source lineedit's private `*indent-width*` became
bedit's variable and read `nil` (KI-383). The same rule let a std module declare a root name by
accident (`project-release/*…*`, ADR-714), and made a dynamic variable the one kind of name
`(:use …)` could not import. std itself had already stopped relying on it: every std module
spells its settings qualified (`(defdyn test/*filter* nil)`).

**Decision.** A dynamic variable is named like any other definition.

- Inside module `m`, `(defdyn *x* v)` declares and defines `m/*x*`. It is bare inside `m`, and
  `m/*x*` or (after `(:use m)`) bare elsewhere. That holds for a read and for `binding` alike.
- Root names come from root code only: the prelude, a file with no `defmodule`, or a head
  spelled with the `/name` root escape, which every definition now accepts (`qualify_name`):
  `(defdyn /*1 nil)` in the REPL module, `(def /*out* port)` to redirect output from a module.
- `binding` quotes the names it rebinds, and a quoted symbol is never resolved, so it resolves
  each name at expansion time (`%resolve-name`) to the variable the same spelling reads.
  `defdyn` marks the name its `def` will bind, by `def`'s own rule (`%def-name`, which
  `defonce` already used).
- **A bare definition head that names a dynamic variable visible from elsewhere is an error
  inside a module**: a root one, or one `(:use …)` imports, a `defdyn` head included (bedit
  re-ran `defdyn` as an assignment). `(def *out* p)` there used to set the root port; reading
  it as a new `m/*out*` would change the program with no diagnostic, so it is refused with
  the fix in the message (`/*out*`, or `other/*x*`; `:exclude` the import to define the
  module's own) (ADR-152). This is what makes the change safe for code written under ADR-151.

`is_ambient` is gone from the resolver, the pre-scan, the import table and the template
escape; `project-check`'s duplicate-definition scan and the native `scan-source-extract`
follow `qualify_name`. The unused-`let` lint's shadow exemption also counts the module's
qualified globals, so `(let (*x* 5) …)` shadowing the module's own `*x*` is still a
deliberate shadow.

**Rejected.**
- *Keep ambient names, and let a module's own definition win over one.* Narrows KI-383 to
  names a module defines itself, but a module that reads a knob another module declared still
  reads whichever root declaration loaded last, and an import still cannot name one.
- *Ambient only for earmuffed names.* ADR-151 removed exactly that spelling rule.
- *Warn instead of refusing a bare root-dynamic head.* A warning the batch checker does not
  see at run time (`reflect/eval`, a REPL) leaves the silent reinterpretation in place.

**Consequences.** Downstream modules' `defdyn`s become module-qualified; a reference from
another module needs `(:use m)` or `m/*x*`, which the checker reports as unbound until
written. A module that sets a prelude knob writes `/*x*`; the error says so. The batch
checker does not run a `defdyn`, so a module that defines a bare `*x*` while importing
another module's dynamic `*x*` is refused only when it loads: std's `format` did, and its
built-in width is now the constant `default-width`. bedit's
migration was 44 `:only` imports, four `/*spy-sink*` heads and one cross-module write that
the checker then flagged as a lost-update race (`cape` re-ran complete-at-point's `defdyn`;
it now calls `complete-add-auto-trigger!`). Two collisions surfaced as fixed rather than
broken: hatch's `web/accounts/*transaction*` and hive's `db/*transaction*` were one root
variable, and bedit's profiling scripts' root `*base*` overwrote the theme colour.

## ADR-723 — `nest eval`: one expression, answered from the shell

**Status:** accepted (2026-11-13).

**Context.** An assistant working on a Brood project often needs one fact: what a function
answers, what shape a value has, whether a private helper does what it should. With no MCP
server attached (a common setup), the only way to evaluate code "as the project sees it" was to
write a test file and run `nest test`. So assistants wrote throwaway probes, such as
`tests/zz_probe_test.blsp`, hundreds of times across sessions. Each one is a file in a tree
other sessions are reading: a probe that appeared and vanished made a neighbour's `nest check`
fail on a file it had just listed, and a forgotten one is committed. Piping into `nest repl`
evaluates, but it cannot see a module's private names, cannot arm a test run's scratch home,
and mixes its banner into the output.

**Decision.** `nest eval [--in MODULE] [--test] EXPRESSION…`:
- It loads the project as `nest repl` does (`load-project-image`), evaluates every form of the
  expression, and prints the last value with `pr-str`, after whatever the code printed.
- `--in MODULE` loads the module (`require-one`) and evaluates inside it (`%in-ns`), so its
  private names and imports resolve bare.
- `--test` arms a test run before the interpreter exists, in Rust (`arm_test_env`), as
  `nest test` does: the run's mark and a scratch home, and none of a suite's knobs. Only a
  `--test` among the flags counts, not one inside the expression.
- `-` reads the expression from stdin. The argument parser now reads a lone `-` as a
  positional for every subcommand, as clap does.
- Contracts are armed by default, as under `nest run` and `nest test`.
- Exit 0 with the value printed, 1 when the code raised, 2 with nothing to evaluate.

The skill, `docs/brood-for-claude.md`, the scaffolded `CLAUDE.md` and the README say to use it,
and never a probe file.

**Rejected.**
- *`brood -e`.* `brood` does not load a project, and the test-run arming lives in `nest`.
- *Teach agents `echo … | nest repl`.* No private names, no scratch home, a banner in the
  output.
- *An `eval` that keeps a live image between calls.* That is the MCP server's job, and a
  one-shot command needs no lifecycle.

**Consequences.** Every call loads the project, about half a second on a 260-module project
from its image. Guard: `blsp_dispatch::eval_answers_one_expression_in_the_project_a_module_or_a_test_run`.

out pays about one heap walk and one rewrite per drain, counted in its collection's pause.

## ADR-724 — `nest test --watch`: one process, a run per save

**Status:** accepted (2026-11-13).

**Context.** A TDD cycle is a save and a one-file `nest test`. Measured on hatch after the day's
startup fixes (KI-390, lazy named files, the daily cache sweep), that run is ~100 ms, of which
the tests are ~25: the rest is reaching `nest/main`, materialising the tool modules from the std
image, and the project's setup and image install. None of it is slow code, so compiling ahead
of time would not remove it. A native image would still be loaded the same way. Repeating it per save is the cost, and
the language already reloads definitions in a running image (ADR-013).

**Decision.** `nest test --watch [FILE…]` runs the tests, then stays up. One loop polls the
mtimes of the project's source files and every `.blsp` under its test paths (200 ms; a 50 ms
settle reads them again so a multi-write save is one change). On a change it re-evaluates the
changed source files' definitions (`reload/reload-file`: `system/reload-defs` under the file's
package context) and reruns the named files, or with none named the test files whose
require-closure (the `--stale` graph) reaches a changed file, or all of them when a changed
file is outside the graph. A changed file defining a macro also re-evaluates the source files
whose closure reaches it, since late binding reaches a changed function but not an expansion
already compiled into a caller. Each test file runs in its own rolled-back scope, as in any run, so a run
leaves nothing for the next. A save that does not load is reported and runs nothing; a cycle
that raises is reported and the loop goes on.

**Rejected.**
- *`reload/on-change`'s watcher per file.* Each file reloads in its own process on its own
  clock, so a save touching two files could run between the two reloads, and nothing orders
  a reload before the run that should see it.
- *Reloading every dependent of every changed file.* Calls look their target up, so only an
  expansion needs it; reloading all dependents would make a save to a low module cost a
  reload of most of the project.
- *A daemon the one-shot `nest test` connects to.* It takes the same reload and isolation
  machinery and adds a protocol and a lifetime to manage. A watch the user starts and ends
  needs neither.

**Consequences.** A cycle costs the reload of the changed files plus the tests (2 ms for the
watch test's projects, against ~100 ms a fresh run). The project image is not rewritten while
watching. A section the image holds for an edited module is never consulted again, because
the reload leaves the module loaded outside every rolled-back scope. A macro's
dependents are found from its source text (`(defmacro`), so a macro a file defines through
another macro is not seen. The whole-suite run's check pre-flight and docstring gate do not
run per save, and coverage, `--stale` and `--repeat-until-failure` refuse `--watch`. Guard:
`nest::test_watch`.

## ADR-725 — Inference read off function types, both ways: inferred guards, reverse arrows, bound tests

**Status:** accepted (2026-11-14).

**Context.** Elixir's type system series (v1.17 → v1.21, "Type inference and narrowing with
reverse arrows", 2026-11-10) reads narrowing off function TYPES rather than a table of
recognised forms: a predicate is the pair of arrows `(T -> true) ∧ (¬T -> false)`, and a demand
on a call's result selects the arms of the callee that can satisfy it ("reverse arrows"). A probe
of Brood's checker against the same ideas found it already narrowed in both branches, through
`match` patterns, `cond`'s type-based dead clauses and `let`-bound single guards — and found
the gaps: a user predicate narrowed nothing unless declared `(is T)`; `(math/rem (negate x) 2)`
over an overloaded `negate` inferred `x : number` where only the int arm can answer an int; a
parameter whose uses conflict (`(+ x 1)` then `(string/upper x)`) was silently retreated to
`any`; a `let`-bound conjunction narrowed nothing; a repeated `((:ok _) …)` clause was not
unreachable; a guard on `(get m :foo)` did not reach a `foo` bound from it. The If-T narrowing
benchmark (utahplt/ifT-benchmark) gave an outside measure.

**Decision.** Each gap closes by reading what a form's type already says, in both directions:

- **A predicate's guard is inferred** from its body's tail: the tail IS the result, so its
  then- and else-branch scopes (`guards::branch_scopes`) are what a truthy and a falsy result
  prove of the first parameter. `Sig` carries the two sides (`guard`, `guard_else`); a declared
  `(is T)` sets `T` / `¬T`, an inferred `and` sets only the truthy side, and only a function
  answering `bool` carries one. Both sides render back as `(is T)` when they are exact
  complements, so "Declare signature" writes what inference found.
- **A declared `(is T)` is checked** against an exact inferred guard within the declared
  domain (ADR-259: a declaration is checked, not trusted).
- **Reverse arrows** in the parameter-domain walk: an argument that is a call of an
  overloaded function, in a position with a known demand, contributes the union of the
  domains of the arms whose result meets the demand — recursively through nested calls.
- **An empty parameter domain is reported at the definition**, once, rather than retreated to
  `any` and left for a caller to stumble on.
- **A test bound by `let` carries what it proves** (`Ctx::cond_facts`), so the name narrows
  as the test itself, as a conjunct and as a disjunct; `(not X)` is X with its branches
  swapped; an `(if c a b)` used as a test proves what its two paths agree on.
- **Refinement through data**: a guard on an access path narrows a name bound from that path;
  `(contains? m :k)` false over a known map/set/nil reads `(get m :k)` as `nil`; `(= (count x)
  n)` false drops the fixed-length alternatives of length `n`.
- **`match` clause redundancy by type**: a clause whose exact pattern type lies inside the
  union of earlier unguarded clauses' is unreachable.

**Rejected.**
- *Feeding inferred guards to the never-true lint.* `(refute (my-pred? bad))` is how a
  predicate's false answer is tested; judging an inferred guard reported every such test as
  dead code (two in `tests/`). The lint stays on stated guards — built-ins and `(is T)`.
- *Narrowing an unknown-shape value after `(contains? m :k)` fails* (Elixir's `not_set()`): a
  `defrecord` value may answer `get` through a `Lookup` impl for a key `contains?` reports
  absent, so absence of the key does not prove a `nil` read for a value of unknown kind.
- *Lazy BDDs for the lattice.* Elixir needed them for the compile-time cost of large unions;
  Brood keeps four alternatives before a widening merge, which is what keeps its relations
  cheap. The union-based checks here (match redundancy) use a union only while it stays
  below that cap, so the widening can never manufacture a verdict.

**Refinements from review** (an independent read of the diff found each as a false positive):
the empty-domain report reads an extensible operator's demand (`+`, `<` — `operator_domain`) as
admitting any record, since an impl another module adds can bring one in; a guard alias bound
from an inferred predicate (`refute`'s `(let (v (pred? x)) …)`) does not feed the dead-clause
lint either; an `or` disjunct keeps its explicit else type (a guard proving only when false
read `¬any = never`); an `or` pattern counts as exact only below the widening cap; the
declared-guard check reads only a body that is its tail. One finding predated this work and is
fixed with it: a later operand of a hand-written `(let (g …) (if g …))` chain that names the
chain's own binder narrowed the outer name. And the downstream differential (bedit, hatch and
ten more projects, before/after) surfaced a pre-existing false positive the sharper narrowing
made visible in a second spelling — `(nth xs (- n 2))` with `n` bound to `(count xs)` under
`(>= n 3)` — so an index that is the collection's own count less a positive step now reads an
element.

**Consequences.** Soundness arguments are per rule (each states why its result
over-approximates); every rule was sabotaged red. On the If-T benchmark all 13 accept cases
are silent in both modes; 11 of 13 reject cases are reported (two, `merge_with_union` and
`struct_fields`, under `--strict` only, being merely-wider values), and two —
`nesting_condition` and `tuple_elements` — stay silent by design, their "unclear" value being
an unannotated parameter or a declared `any`, which Brood reads as `dynamic()` (contract #4).
Guards: `types::check::tests::narrowing_arrows`, `types::check::tests::if_t_benchmark`.

**Follow-up (2026-11-16): the index rule reads bounds on the index's base.** An index reads
as base + offset against bounds on the base: a count alias bounds itself at `n - 1`, and a
`let` of an offset carries its base's bounds (an index bound before a guard on its base keeps
the interval it was bound with; relating the two would need relational intervals, not done).
Tried and not kept: reading every `and`/`or` chain as a `let` used as a test, in place of the
shape readers — correct, but +22% (+9% with a fast path) instructions on the strict corpus
check, for no bug fixed.

## ADR-726 — A window that keeps the display's time and the desktop's look; input asked for inside a turn

**Status:** accepted (2026-11-16).

**Context.** A side-by-side study of bedit against Ptyxis (VTE 0.84, GTK 4.22, GNOME 50 on
Wayland, one 144 Hz and two 60 Hz panels) asked what makes a GTK terminal feel smooth that the
window host does not do. The host's own path was already short — two thread hops, input
coalesced, rows diffed, damage presented — so the differences were of time and look:

- Everything the window animated by itself ran on fixed clocks: the kinetic coast every 12 ms
  (~83 Hz), particles every 16 ms. On a 60 Hz panel some refreshes showed one step and some
  two (judder); on the 144 Hz panel the coast was held to 83. Nothing tied a paint to the
  compositor's frame clock, so a burst of frames each painted and blocked on a buffer Mutter
  had not released. GDK's frame clock paints at once when idle and paces only bursts.
- Every window move by less than a cell sent the app a `[:resize]` for the grid it already had.
- The first glyph the font lacked scanned every installed font inside the paint (a one-off
  freeze), because the scan was on demand only.
- GNOME's `font-rendering 'automatic'` makes GTK 4 draw grayscale, slightly hinted text blended
  in sRGB, whatever the older `font-antialiasing 'rgba'` key says (`gtkwidget.c`, 4.22.0); its
  caret blinks for half of `cursor-blink-time` a phase and stops after
  `cursor-blink-timeout`. An app had `gui/color-scheme` and `gui/reduce-motion?` to read the
  desktop, nothing for text or the caret, and ran a settings tool per key.
- Long work inside one turn (an idle beat's slice) could not ask whether a key was waiting:
  `proc/take-priority` takes the key, and only the quit key interrupts (ADR-491).

**Decision.**

- **The window steps by its monitor's refresh.** `Win::frame_period` is one refresh of the
  monitor the window is on (`MonitorHandle::refresh_rate_millihertz`, clamped to 30–360 Hz, 60
  when unknown), re-read at most once a second by a paint, since a move between panels at one
  scale sends no event. The coast and the particles step by it, and a coast step moves what its
  span of time would have (`coast_step`: `v(1-dʳ)/(1-d)` for `r` 12 ms ticks), so a coast covers
  the same ground in the same time at any refresh.
- **A paint is paced by the compositor.** `pre_present_notify` right before each present — never
  before a paint that might present nothing, whose frame callback would never come: on
  Wayland the commit asks for a frame callback and winit holds the next `RedrawRequested` until
  it comes, so an idle window still paints at once and a burst paints once a refresh, the
  newest frame each time. The GPU target's `resize` already ran before each paint only when
  the size changed, so the swapchain is now reconfigured at most once a refresh.
- **`[:resize]` only for a new grid.** `publish_size` remembers what it last told the app
  (`published_size`) and sends again only when cells (pixels, for a pixel-input window)
  changed; the sub-cell leftover is placed at paint time already.
- **A GPU frame skipped on a swapchain `Timeout` is owed** (`GpuWindow::take_retry`) and asked
  for again; an occluded window owes nothing.
- **The installed fonts are scanned in the background** once the first window has painted
  (`FontShared::prescan`); a lookup that comes first waits out the rest of that scan, or scans
  itself if none ran.
- **`gui/desktop-preferences`** reads the desktop once — one `gsettings list-recursively
  org.gnome.desktop.interface`, or kdeglobals — and answers `{:color-scheme :reduce-motion?
  :text-rendering :cursor-blink}` through pure readers, `gui/text-rendering-from` (GNOME's
  `automatic` read as GTK 4 draws it) and `gui/cursor-blink-from`. Mechanism stays in the
  window: an app applies what it wants through `gui/text-aa` and `gui/text-contrast`, and a
  caret's `cursor-blink`.
- **`proc/priority-pending?`** answers, in O(1) from the count the mailbox keeps, whether a
  priority-lane message waits, without taking it. A display says the same for its own input
  through `:input-pending?` (`editor/frontend/display-input-pending?`: the window and the
  terminal ask the lane, a broadcast asks each), and `ui-run` binds `editor/ui/*display*` so
  code inside a turn asks `editor/ui/ui-input-pending?`.

Not done: hinting stays swash's (skrifa's smooth LCD target, mostly vertical for TrueType
fonts, close to FreeType's light); a separate slight/none mode would replace swash's scaler for
little visible change. Served displays answer `:input-pending?` false, having no lane to read.

**Consequences.** On a 144 Hz panel a coast moves once a refresh; on 60 Hz no refresh shows two
steps. bedit follows the desktop's text rendering and caret blink, and its idle beat yields to
a key between jobs. CI on this branch is the test of the host changes; none ran on the
development desktop.

## ADR-727 — A process collects as it parks when its next collection is near

**Status:** accepted (2026-11-16).

**Context.** bedit's loop, typed at 90 wpm in the live probe (`tools/probe-typing.blsp`),
collected 10–11 times in two rounds; 5 of those landed inside a key's turn, 58–90 ms of pause
charged to keys, and they were the tail: p99 30 ms, max 35–75 ms. The loop's young
collections take 6–8 ms, up to 23. A collection fires at the eval safepoint when the young
generation reaches its trigger (`gc_threshold`, or the nursery's byte budget), which is
wherever the allocation happens to cross it — usually mid-turn. The same loop parks between
keys for ~100 ms with nothing to do, and the runtime already collects at that moment when a
heap grew (`trim_parked`).

**Decision.** A process that parks with its next collection near collects then: the young
generation past `park_collect_fraction()` of its object trigger — **0.75**, `BROOD_GC_PARK_EARLY`
to tune, 1.0 to turn it off — or under a quarter of the nursery's byte floor left
(`Heap::park_collect_due`). It is an ordinary collection (`collect_on_park`), run in the same
parking window and under the same ownership as the trim. Right after a collection the young
generation holds at most half its trigger, so a park never collects twice. No field was added:
the per-process floor (`tests/process_floor.rs`) holds.

**Consequences.** Measured on the probe, two runs each: collections inside a turn 5 → 0, GC
time inside turns 58–90 ms → 0, key latency p99 30–31 → 20–21 ms, max 35–75 → 30–31 ms; 10–11
collections → 14, but less pause in all (98–116 → 81 ms), each collecting less. The worst case
is a process that parks after every small step: up to `1 / fraction` (1.33×) as many young
collections. A turn that allocates more than a quarter of the budget still collects inside it.
Guard: `core::heap::gc::tests::park_collect_fires_near_the_trigger_and_not_twice` (red with the
fraction at 1.0). Not run on the desktop: the GC-touching suites (`make gcstress`, the loops)
are for the test machine and CI.

## ADR-728 — `[:translate drow dcol ops]`: a rendered piece moved by rows, resolved at parse

**Status:** accepted (2026-11-16).

**Context.** Render ops name absolute cells, so a memoised view fragment (`ui-memo`, ADR-336)
is pinned to where it was drawn: an editor keys a row's fragment by its screen row, and a
scroll that moves every line up one row misses every fragment and repaints every row — the
Brood side rebuilds each row's ops and the window parses each again. bedit measured +1.6 ms a
scroll turn for it. A fragment keyed by what it shows (a buffer line) would hit after the
scroll, if the frame could say "these ops, moved".

**Decision.** A block op `[:translate drow dcol ops]` paints `ops` moved `drow` rows down and
`dcol` columns right. The cell ops move (text, cursor, rect, image, frect, cursor zone,
vspans, cells, a cell region's rectangle — its inner ops are in its own grid), and so does
everything a fragment, scroll region or above-seam block inside holds; an op pushed off the
top or left edge is dropped; ops in pixels and the frame-wide ones stay put.

- **Resolved where it is parsed, never painted.** The GUI window resolves it in `%gui-draw`'s
  parse (`Op::translated`) into ops at absolute cells, so no painter, damage tracker, strip
  diff, GPU replay, bleed or hit test learns a new op. A block holding one parsed fragment is
  cached per window by (that fragment's allocation, drow, dcol): a row that kept its place is
  last frame's `Arc` (the frame diff skips it by pointer), a row that moved is shifted natively
  from the fragment it already parsed.
- **A flattened frame gets it resolved by `%ui-harvest`.** A display that does not take memo
  markers (the terminal, served clients) is handed the frame with every translate block
  replaced by its moved ops; a display that does (`:fragments?`, the GUI window) gets the block
  with the markers. No new primitive: `%ui-harvest` already walks every op of every frame.
- **`ui-memo-at key deps row col thunk`** is the caller's form: the thunk paints at the origin,
  the result is `[[:translate row col [marker]]]` in a loop and the ops already moved outside
  one (`ui-translated`).

Rejected: generalising `[:scroll-region]` — its inner offset replaces the outer one, it
shifts pixels across the seam, and its damage band is the whole frame.

**Consequences.** A row fragment keyed by content survives a scroll: C-n at the edge rebuilds
one row instead of all of them. The translation cache is bounded by the frame, like the
fragment cache. Guards: `fragments::tests::a_translated_row_is_moved_and_shared_while_it_stays_put`,
`…::a_translate_moves_every_cell_op_and_drops_what_leaves_the_grid`, and `tests/ui_test.blsp`'s
translate tests (harvest, `ui-translated`, `ui-memo-at`, markers kept).

## ADR-729 — `reflect/scan-bracket-partner`: a bracket's partner, read natively

**Status:** accepted (2026-11-16).

**Context.** A show-paren runs on every key. `editor/highlight/bracket-match` found the partner
with two interpreted `string/char-at` walks: forward from an opener to its closer, and from the
top-level form start to a closer to learn its opener. In bedit's live typing probe, a key next
to a bracket cost 1.7–2 ms in it (a 4000-char window each side of point; inside a large `defn`,

`scan-form-start` / `scan-form-end`, with a safepoint table carried across edits, but nothing
named a bracket's partner.

**Decision.** `%scan-bracket-partner s pos` (`reflect/scan-bracket-partner`) answers the

## ADR-730 — Text hinted as the desktop hints it: `gui/text-hinting`, FreeType's light target

**Status:** accepted (2026-11-16).

**Context.** Beside a GNOME terminal, the window's text read softer. Measured, not guessed: one
line of Ubuntu Sans Mono at 15 px from the window's painter (`gui/render-frame`) against pango
(FreeType, fontconfig's `hintslight`) — the window's glyphs were row for row FreeType's
UNHINTED ones (`=`'s bars 132/132 and 88/176, grey across two rows each), where FreeType's
slight hinting puts each bar on one row (236 then 28). cosmic-text hands swash its glyphs with
hinting off, and swash's own hinter has one fixed mode, FreeType's LCD target. A GNOME desktop
at a 1× scale draws every app's text with the light target; GTK 4 turns hinting off on HiDPI.

**Decision.**
- **`gui/text-hinting`** — `:slight`, `:medium`/`:full`, `:none`, or `:auto` (the default:
  slight at a 1× scale, none on HiDPI, as GTK 4 decides) — for every window and the default for
  ones opened later, like `gui/text-aa`; `gui/render-frame`'s spec takes `:text-hinting`.

  on, so nothing new is compiled) and rasterises them with the zeno pass, placement and offsets
  swash uses: unhinted, the mask and its placement are swash's to the byte. **Slight is skrifa's
  autohinter in light mode**: on Ubuntu Sans Mono it matches FreeType's hintslight to the byte,
  while the font's own instructions, run in light mode, move nothing — FreeType autohints a
  light target here, and so do we. Full is FreeType's engine choice at its normal target. Colour
  glyphs stay swash's. The subpixel path draws the same hinted outline three times wider, so it
  is the gray glyph with three coverages, and its own swash scaler is gone.
- A hinting change drops the cluster cache and the retained frame, and is folded into
  `font_generation`, which every GPU cache keys on.
- **`gui/follow-text-rendering rendering`** applies a `text-rendering-from` answer — its
  anti-aliasing and its hinting — in one call: what any app does to look like the desktop it
  runs on. GNOME's `'automatic'` now reads as `:hinting :auto` (it is slight only at 1×).
- A geometric mark (a status dot) centres on the lowercase `x` as DRAWN: hinting snaps the
  x-height by the hinter's rules, which `x_middle`'s prediction from the font's numbers misses.

**Consequences.** Text at a 1× scale has its horizontal strokes on whole pixel rows, as the

## ADR-731 — `editor/span-tree`: ascending spans carried through an edit in O(log n)

**Status:** accepted (2026-11-16).

**Context.** Text properties, highlights, diagnostics — spans `[start end value]` over a text,
ascending and apart — were kept as vectors of absolute spans, so every edit before the last
span rewrote every span after it: 5.2 ms for an insert at the start of 10,000 spans, every key.

**Decision.** A std module any app can use, with no buffer in it: a persistent join-based AVL
tree (Blelloch, Ferizovic and Sun) of RELATIVE items `[gap length value]`, each node caching its
height, count and extent. `split` and `join` are the O(log n) primitives; `edit` is the one
operation that changes spans — the spans touching a range handed to a function as plain absolute
spans, what it answers spliced back and every later span moved by a delta, which is one gap.
`carry` (Emacs's text-property rules: an insert inside a span splits it, one at an edge stays
outside, a delete shrinks and joins), `replace`, `clip` (O(log n + k): subtrees outside the
range are never walked), `from-spans`, `->spans`, `same?` (two trees of the same spans can be
shaped differently, so `=` compares shapes). Brood, not Rust: it holds arbitrary values, which a
Rust object would have to trace, copy and compare.

**Consequences.** An insert at the start of 10,000 spans: 5.2 → 0.13 ms; one in the middle
0.23 ms whatever the count. Guards: `tests/span_tree_test.blsp` — every operation, 300 random
runs of inserts, deletes and replaces against `editor/span-properties`' vector code as the
oracle with the tree's balance and cached measures checked after every step (red, with a
minimal counterexample, when the insert split is off by one), and ten thousand spans through a
thousand edits staying under height 24.

**Addendum — text properties kept in it (2026-11-16).** A buffer's `:properties` now holds each
key's spans as a span tree: `editor/span-properties`' functions over a stored map carry, add,
replace and clip trees (and take a vector for a key, built into a tree, so a data map assigned
where a stored one belongs still works); what crosses a boundary stays data — `buffer-property-map`
(`properties->data`), the splice log, the wire, region undo's pieces. `buffer-property-store` is
the stored map for code that reads a range (`properties-in`, O(log n + k)); a change that changes
nothing answers the very same map, so the `=` checks after a property edit stay O(1); comparing
a wire map with a stored one is `properties-same?`. A key at the top of a buffer with 10,000
property spans: 5.3 → 0.23 ms. `span-tree/overlapping` gives a view the spans reaching into its
lines uncut. The oracle the tests check the tree against is the old vector code, kept verbatim in
`tests/span_tree_test.blsp`.

## ADR-732 — Named regex groups: `(?<name>…)`, a match's `:named`, `${name}` in a template

**Status:** accepted (2026-11-17).

**Context.** A pattern with more than two groups is read by counting parens, and every group
added in front renumbers the ones after it (handoff thread 3). Backreferences and lookaround,
listed beside it, have no linear-time engine, and the engine is linear by design (ADR-389), so
they stay out.

**Decision.** `(?<name>…)` and Python's `(?P<name>…)` open a capturing group, numbered with the
unnamed ones by its opening paren — a name adds a way to reach a group and changes nothing else.
The translation hands the engine a plain `(`; the names are read off the AST in std, so the
native side is unchanged. A match of a pattern that names a group carries `:named`, each name's
keyword to its group map (nil when it took part in nothing, the key still there); a pattern that
names none carries no `:named`, so `find` on it costs what it did (a pattern's text is tested for
`(?<`/`(?P<` before anything is parsed). A name given to two groups is the leftmost of them that
took part, which is what an alternation of two layouts of the same field wants (PCRE needs `(?J)`
for it; refusing would be the one parse error besides `*max-repeat*`). A replacement template
reads `${name}`, and `${n}` reaches a numbered group past `$9`. A malformed name (`(?<1x>`,
`(?<>`, and the lookbehind spellings `(?<=`/`(?<!`) is the characters it looks like, as every
other malformation in the dialect is.

**Consequences.** `find`, `find-all`, `rope-find`, `rope-find-backward` and `replace` see names;
`tokens`, `paint` and the counts expose no groups and are untouched. Guards:
`tests/regex_test.blsp` "regex named groups", including matches sent back from 16 processes;
sabotaging the name parse, the `:named` attachment, the leftmost rule or the `${…}` expansion
each turns it red.

## ADR-733 — `url/resolve`: a reference against a base, RFC 3986 §5, strict

**Status:** accepted (2026-11-17).

**Context.** `std/url` could parse and build a URL but not resolve one (handoff thread 4): an
HTTP client following a relative `Location`, a crawler reading `href`s, a feed with relative
links all had to join strings by hand, which gets `..`, `?y` and `//host` wrong.

**Decision.** `(url/resolve base reference)` → string, the algorithm of RFC 3986 §5.2 as
written: the strict reading (a reference with a scheme is absolute even when it is the base's,
so `http:g` stays `http:g`), §5.2.3's merge, §5.2.4's dot-segment removal, §5.3's recomposition.
It splits with the RFC's own five components (Appendix B), not `parse`'s map: resolution needs a
scheme before any `/?#` (`mailto:x`) and an empty authority told apart from none (`file:///`),
neither of which `parse`'s host-and-port reading keeps. A base with no scheme raises, naming it —
the RFC requires an absolute base, and guessing one would resolve against nothing the caller
named. Strings in and out, because the output is what goes into a request line or a header. Not
WHATWG: no scheme defaults, no `\` read as `/`, nothing encoded or lowercased; that is a
different specification and stays out until a customer needs it.

**Consequences.** Guards: `tests/url_test.blsp` runs every example in RFC 3986 §5.4.1 and §5.4.2,
the edges around them (an empty base path, an empty authority, a scheme without `//`, a relative
base refused) and answers sent back from eight processes. Sabotaging the merge's empty-path rule,
the empty-reference query fallback, the absolute reference's dot removal or the `..` segment
drop each turns it red.

## ADR-734 — A local binding shadows a macro; the evaluator's eight forms cannot be bound

**Status:** accepted (2026-11-17). Supersedes the 2026-07-26 choice recorded in
`docs/deferred.md` §7 (keep macro names as reserved operator words, "Option A") and settles
open thread 10.

**Context.** The runtime looks a call head up in the lexical environment first, so a local
named `count` was called in place of the root function. The compile pass did not: it expanded
every head that named a macro against the root, so `(let (when f) (when x))` and
`(defn g (cond) (cond 5))` silently ran the macro and ignored the local — no error, no warning,
the wrong answer. A local spelled like a special form (`(let (if f) (if 1 2 3))`) was ignored
the same way. The owner's rule for a hazard like this (2026-11-17): the language makes it work,
or compilation fails; it never hides, and a lint is not the answer.

**Decision.**
1. **The nearest binding wins, for a macro as for a function.** The compile pass keeps the
   lexical scope it walks: `let` (each target from the value after it on), `letrec` (every
   target in every value), each `fn` clause's parameters (`&optional` names and the `&` rest
   name included) and `defmacro`'s. A head bound in that scope is a call, never a macro
   expansion. Binders a macro introduces (`for`, `doseq`, a pattern, a `catch`) are in scope
   because the expander walks from the outside in: the macro has expanded, into `let`/`fn`,
   before its result is walked. (`crates/lisp/src/eval/macros/local_heads.rs`.)
2. **Templates stay safe.** A macro's own call heads were pinned to root when it was defined
   (ADR-423) and its binders renamed (ADR-066), so a caller's local `when` cannot capture the
   `when` inside a `when-let` it uses. An expander body runs with no locals in scope: it is
   code of its own.
3. **The eight evaluator forms are the language's only keywords.** `def do fn if let letrec
   quote quasiquote` are read by spelling before any lookup, so a local spelled that way
   could never be called. Binding one fails compilation, at the binding, naming the form.

**Alternatives.** *Keep reserved words* (Option A): simple, but it is exactly the silent wrong
answer above — a reserved word that can be bound and then ignored is not reserved. *Refuse a
binding named like any macro*: it would fail compilation honestly, but turns ~40 macro names
into keywords and breaks every `for`/`cond` parameter that is only passed along. *Lisp-2*:
rejected in ADR-007 for the `funcall` tax.

**Consequences.** Every existing std, test and example file checks the same with the scope on
and off (`nest check --strict` output identical), so nothing relied on the old reading. A
leaked scope would be masked at run time (the runtime's lazy expansion consults the real
environment) and cost only performance, which is why the scope is a mark/release pair per
binding form. Static editor grammars still colour a shadowed `when` as the macro; the LSP's
semantic tokens follow scope. Guards: `tests/lexical_shadowing_test.blsp` — every binder kind,
the extent of a shadow, templates under a local, an expander that asks `macroexpand-1` under a
caller's local, all eight refusals, and a shadowing function run from 16 processes;
sabotaging the scope lookup, the refusal, the expander's isolation or `letrec`'s binding order
each turns it red.

## ADR-735 — A module that defines a root name declares it, or fails compilation

**Status:** accepted (2026-11-17). Extends ADR-423 §3 (a warning, for root macros only) to
every name the language ships, and makes it an error.

**Context.** Inside a module its own definition wins (ADR-423), which is the designed way for a
module to own `get` or `count` (ADR-236). But nothing said so: `(defn count …)` in a module
silently changed what every bare `count` in that file meant, and only a macro's name earned a
warning — which a reader of the file never sees. The owner's rule (2026-11-17): it works, or
compilation fails; nothing hides.

**Decision.** A module definition (`def`, `defn`, `defmacro` and everything that expands to
them) of a bare name the language ships fails compilation unless the module's header declares
it with `(:shadow name)`. The error names the clause to add. Declared, it works as before: the
module's definition wins inside the module, and `/name` reaches the root one. "A name the
language ships" is a sealed root name (`Heap::is_root_name`) — the prelude's and the builtins'
— held to the same rule while std itself loads. `%`-names are internal and exempt. The error
rides the resolve pass's existing channel (`derive::take_resolve_error`, beside ADR-722's
dynamic-variable refusal), so it points at the definition.

**Consequences.** 47 definitions in 24 std modules declare their shadows (`std/stream` owns
`map`, `fold`, `take`, `drop` and five more; `std/sorted` and `std/table` the map verbs;
`std/node` `spawn` and `monitor`); bedit and the other downstream projects add theirs. The
warning, its once-per-process `static` and ADR-423's stderr test are replaced by the refusal
and a test of it. Guards: `crates/cli/tests/macro_shadow_warning.rs` (now the refusal and the
declared case, for a function and a macro) and `tests/prelude_capture_test.blsp`.

## ADR-736 — The terminal as slick as its emulator: deltas, erases, its own colours and title

**Status:** accepted (2026-11-17).

**Context.** Measured on bedit `-nw` in a 120×40 pty: every colour change restated both colours
from a reset (~35 bytes; 58% of a page-down's 8.3 KB), blank runs were written as spaces, the
first frame cleared to the terminal's colour and then wrote every themed blank (~12 KB); the
input thread woke every 20 ms and reopened `/dev/tty` twice a wake to ask the size (≈1,250
syscalls a second, idle); a lone ESC at a read's end was the Escape key at once, so `ESC f` split
across two reads (ssh, tmux, a person typing ESC then f) was Escape and a plain `f`; a press always
counted 1, so a double click never selected a word; the terminal's own padding and cursor kept its
own colours; and a terminal app could not set its title.

**Decision.**
- `screen::sgr_change`: only the slots that differ (`22 23 24 27 39 49 59` to switch one off), or
  the full sequence from a reset when that is shorter — proven equivalent by an SGR interpreter
  over every pair of a spread of styles at every depth.
- `screen::Output { depth, erase_fills_background }`: where erasing fills with the background
  (every terminal but GNU screen's `screen*` and a dumb one), a row's blank tail is one `CSI K`, a
  blank stretch inside a run `CSI n X` + `CSI n C`, and the first frame clears to the frame's
  commonest blank, whose cells are then never written. `TERM`s naming kitty, foot, WezTerm,
  Alacritty or Ghostty are true colour without `COLORTERM`.
- A wake pipe (`tty::wake`, written by the SIGWINCH handler and a stop request) polled beside the
  tty: an idle terminal is one poll a second, the size is asked only when a SIGWINCH came, a
  forwarder stops at once.
- A lone ESC waits `ESCAPE_PATIENCE` (30 ms, Neovim's `ttimeoutlen`) for the key it makes Meta;
  under the kitty protocol Escape is `CSI 27 u` and never waits.
- `host::gui::ClickChain`: one click-chain rule (same button, same cell, 400 ms) for the window and
  the terminal.
- `term/bg` at true colour also sets the terminal's own colours (OSC 10/11, the cursor's OSC 12);
  `term/title` sets OSC 2 with the shell's title saved on the title stack; every leave path gives
  both back (OSC 110/111/112, `CSI 23;0t`), and taking the screen again (a continue after a
  suspend) sets both again. The colours are given back only when a face set some, so a face or
  depth that sets none never undoes the colours the user's shell gave the terminal.
- `editor/frontend/display-configure`: the window options a display can change, `:title`
  everywhere — a window's bar, the terminal's OSC 2, a thin client's window — so an app sets its
  title one way.
- `card-surface` in the terminal draws `│` side edges in a `:border` colour, so a card stays told
  from the text under it at 16 colours.

**Consequences.** The same bedit session: 80 KB written → 47 KB; first frame 12 → 6.4 KB, a
page-down 8–11 → 5.4–6.4 KB, a wheel notch 8.7 → 4.5 KB. Idle: 3,128 → 238 polls and 1,667 → 80
ioctls in 16 s. Not done here: scrolling by scroll region (`DECSTBM` + `SU`/`SD`) for a moved row
band, and the startup queries batched behind one DA1 (they wait 2.5 s on a terminal that answers
neither) — both need the decoder to read OSC/DCS replies first.

## ADR-737 — The CPU painter's text blend by table, and the pieces an app's text view shares

**Status:** accepted (2026-11-17).

**Context.** With no GPU, a full-screen text redraw took 19 ms (grayscale) and 39 ms (subpixel)
at 1080p, most of it a `powf` per partly covered pixel (three for subpixel): `TextInk` was built

## ADR-738 — `bound?` waits for a load another process holds

**Status:** accepted (2026-11-17).

**Context.** A module's globals are staged while it loads and published whole when it is
provided (ADR-344). A REFERENCE to a name of a module another process is loading waits for that
load (`%lazy-global`, parked as frames). `bound?` did not: it answered from the table as it
stood, so a name the finished load would bind read as unbound for as long as another process was
mid-load. A parallel test run met this as a flake with a different answer each run: bedit's
`writable_test` lists every buffer type's layers by `bound?` while the file's other tests open
buffers of those types, materialising their modes from the project image; 6 runs in 6 listed a
different set of "unbound" layers (`guards_test` likewise saw `commands/cmd-dabbrev-expand`
unbound about one run in three). The program had the names; `bound?` asked mid-publish. The
2026-11-14 review made `bound?` NOT wait there, and for a real reason: the wait is a `receive`,
and under `bound?`'s native frame it cannot park, so it blocks an OS worker.

**Decision.** `bound?` of a qualified name whose module another live process holds the load of
hands its call back to the engine (ADR-505) as `(%lazy-bound? module 'name)`: the prelude helper
waits for the load as ordinary frames (`%lazy-require`, the wait in `%require-await` parks) and
asks again. A failed load leaves the name unbound — `bound?` still never raises. Nothing waits
under the native frame: a `bound?` called from Rust (by a builtin such as `map`) cannot take a
redirect and gets the old answer. Every other case is answered as before: a name in the table, a
module this process is loading, a module no one is loading (a lazily installed image section is
still materialised to answer).

**Consequences.** `bound?` answers for the program, not for a moment in another process's load.
A process that holds a load and waits on another process that asks `bound?` of that module's
names now waits for itself — the same cycle a reference already had. `%require-await`'s cycle
check does not see it, since the asker holds no claim, so it ends at the 30 s backstop: a loud
`[require] BUG` line and the asker force-loading the module a second time. A load that waits on
a server must not have that server ask `bound?` of the loading module's names. The
`module_publish_test` observer, which looked for a half-published module through `bound?`, reads
the global names instead.

## ADR-739 — The CPU painter keeps a resized canvas, copies one pane's columns, diffs a zoomed pane, draws on threads

**Status:** accepted (2026-11-17).

**Context.** After ADR-737 a full 1080p redraw is 6–10 ms on a CPU-only machine, and four
common frames still paid most of one. A configure painted the stale frame at the new size from
an empty canvas, then the laid-out frame — and a new seam row (the mode line, ADR-610) cleared
the retained frame, so that second paint was whole too. A scroll in one pane of a side-by-side
split could not be copied: `strip_blits` required every leaf of the row to move, and the other
pane's did not. A cell region (a zoomed pane) was one opaque leaf, so a keystroke in it repainted
every row of the pane across the window. The glyph cache was probed through SipHash twice per
cluster drawn.

**Decision.**
- **A resize keeps the canvas** (`resized_canvas`): the old pixels anchored top-left, the
  window background where only the new size has pixels. A frame laid out on other rows than the
  canvas was — a new size or a new seam — is diffed against the canvas as those rows placed it
  (`resize_damage`, `RetainedFrame::prev_rows`): a strip on the same pixel rows whose leaves are
  the same ops on the same bands keeps its pixels; one that changed is drawn in its changed
  columns; one that moved or reaches past the old height is drawn whole; the new right edge is
  its own rects. `same_leaf` compares bands too, which within one row map changes nothing.
  `Renderer::set_layout` invalidates only when row 0's band changes, no longer on a new seam.
- **A blit copies the changed columns** (`StripMove`): a dirty strip is tried as a translation
  over its changed columns (`strip_columns`) only, comparing just the leaves that can reach
  them (`reaches`) — so the other pane of a split has no say — and only those columns are copied.
  `copy_strips` orders column moves as it orders whole ones; within a strip, rows go the move's
  way. Exact for the same reason column damage is: outside the differing leaves' columns the
  pixels are the old ones.
- **A cell region diffs as cells** (`pair_regions`, `region_damage`): a region at the same rect,
  size, shift and band in both frames is a twin — the same leaf to the window's diff — and its
  own ops are diffed on a uniform grid from its top with its metrics, strip by strip and column
  by column, the rects cut to its band and rasterised like any other.
- `dirty_rects` merges adjacent strips only while the union draws at most a quarter more than
  the parts. The glyph cache and the blend tables hash with an FxHash-style `PaintHasher`
  (12 000 probes: 0.46 → 0.09 ms).
- **Large draws run on threads** (`paint/bands.rs`). `render_ops` draws through a `Painter`:
  the renderer, which builds what it lacks as it goes, or a `BandPainter`, which only reads —
  the glyph cache, the textures, the zoomed panes' cell sizes — and owns its blend tables (one
  set per band, kept between frames). A paint whose rects cover at least `THREADED_MIN_PX`
  (300 000 px) first prepares the frame on the GUI thread (`prepare_ops`: every glyph built,
  every pane's cell size decided), cuts the drawn rows into bands of equal work, one per thread
  (`gui_threads`: the parallelism, at most 8; `BROOD_GUI_THREADS=1` turns it off), and draws
  every rect cut to each band under `std::thread::scope` into disjoint slices of the canvas
  (`Canvas::first`). A band that meets something unprepared — a picture, which is resampled as
  it is drawn, a particle, a glyph the walk did not foresee — says so, and the rects are drawn
  again on the GUI thread. The bytes are the same on any number of threads: the glyphs are the
  cache's, and a blend table holds what the blend computes (ADR-737).
- `raster_frame` runs in stages: it makes a `Plan` — the strips copied, the rects drawn, the
  rects changed — from `resize_damage`, `diff_plan` (strip diff → changed columns → blits →
  `zoomed_pane_damage`), the whole frame or nothing; then copies (`copy_strips`) and draws
  (`draw_rects`). One thread and many draw a rect through the same `draw_rect` and
  `render_ops`; only the `Painter` differs.
- Every path is checked against a from-scratch raster byte for byte
  (`paint/incremental_tests.rs`: a resize grown, deepened and shrunk with a seam; a split whose
  panes scroll one at a time and opposite ways; typing, a blink and a scroll in a zoomed pane;
  frames drawn on 1, 2, 3, 8 and 64 threads). `paint/timings.rs` holds `#[ignore]`d one-shot
  clock readings of the frames below.

**Consequences.** At 1920×1080 (213×51 cells, subpixel text, warm cache, test profile, 28
cores, 8 threads): a full redraw 9.9 → 2.5 ms (gray 6.3 → 1.8 ms); a resize (stale frame then
the laid-out one) 22.4 → 5.2 ms; a one-pane scroll in a split 5.5 → 1.2 ms; a keystroke in a
zoomed pane 8.7 → 0.2 ms. At 3840×2160 a full redraw is 41 ms on one thread, 12.5 on four, 12.0
on eight, and a resize from two thirds the size 74 → 31 → 20 ms. Threads pay from about ten
changed rows at 1080p (390 000 px: 2.9 → 2.1 ms); at five (200 000 px) both take 1.5 ms, which
sets the threshold. A keystroke in an unzoomed pane is 0.19 ms, of which keeping the frame
(`to_vec`) and flattening it are 0.03 ms each: keeping the old op list and rejecting a text op
by columns were not done, there being nothing left to save. Not done: two panes scrolling
opposite ways in one frame (one strip, two deltas) are drawn, not copied; a scroll inside a
zoomed pane draws the pane's changed rows rather than copying them; a large draw that reaches a
picture or particles is drawn twice, its bands abandoned for the GUI thread (a picture is
resampled into the renderer's cache as it is drawn, so no band can draw it). All three: ADR-746.

## ADR-740 — The terminal's answers read as replies, asked in one batch; moved rows scrolled by the terminal

**Status:** accepted (2026-11-17).

**Context.** ADR-736 left two things that needed the decoder to read a terminal's answers. Startup
asked each capability on its own: the kitty keyboard flags through crossterm's reader (up to 2 s
for an answer), then the kitty graphics query behind a DA1 (500 ms) — on a terminal answering
neither, `bedit -nw` sat 2.5 s before its first frame. True colour came only from `COLORTERM` /
`TERM`, which ssh does not pass. The decoder swallowed `CSI ?` answers and APC, but OSC and DCS
were read as Meta chords (`ESC ]` is M-], `ESC P` M-P), and `ESC _` waited for a terminator, so
M-_ typed never arrived. And a frame whose rows moved (a wheel notch, C-n at the bottom) rewrote
every row: ~6.5 KB for three lines of scroll in a 120×40 pty. Separately, a std module whose
source did not parse (an unescaped `"` in a docstring) was reported at the right line and column
under the name of the PROJECT file whose `require` was loading it
(`src/xrefgrep.blsp:36:7: … dispatch character` for a line of `std/editor/display.blsp`).

**Decision.**
- `probe::Reply`, read by the decoder: DA1 (`CSI ? … c`), the kitty flags (`CSI ? flags u`), DECRPM
  (`CSI ? mode ; setting $ y`), XTVERSION (`DCS > | text ST`), DECRQSS (`DCS Ps $ r text ST`), OSC
  10/11/12 colours (`rgb:` at 1–4 hex digits a channel) and kitty graphics answers, ended by ST or
  BEL, read whenever they arrive — split across reads, late — and kept for whoever asked, never
  typed. `ESC ]`, `ESC P`, `ESC _` begin a string sequence only when the next byte is how an
  answer begins (a digit, `>`, `G`); otherwise they are the Meta key and the byte after is read
  again (M-], M-P, M-_ work). An introducer that ends a read waits
  `ESCAPE_PATIENCE` for the byte after it, as a lone ESC does, and is then the Meta key — so an answer cut right after
  its `ESC ]` is still an answer (a test cuts the whole batch at every byte).
- `probe`: `term-enter` writes ONE question — kitty flags, kitty graphics, OSC 10/11, DECRQM 2026
  and 2027, XTVERSION, a 24-bit SGR asked back by DECRQSS — ending with DA1, and reads until DA1's
  reply (1 s at most for a terminal that answers nothing); keys typed meanwhile reach the inbox.
  Asked once per process. Kitty keys and graphics follow the answers; true colour is the
  terminal keeping the probe's colour (xterm), or an XTVERSION name that has it (kitty, foot,
  WezTerm, Ghostty, iTerm2, Konsole, contour, mintty), before `COLORTERM` / `TERM`. Synchronized
  updates are bracketed unless the terminal said it does not know mode 2026. The colours and
  mode 2027 are kept, not yet acted on.
- `screen::find_scroll`: rows are matched whole, by hash; the shift most changed rows find
  their old content at is the candidate, the band the run of rows with the most gain (cells
  that would differ in place, less those that differ shifted), less what the rows the scroll
  leaves blank then cost. The frame then sets the blank rows' commonest background, writes
  `DECSTBM` + `SU`/`SD` + `CSI r`, and diffs the rest against the screen as the terminal now
  shows it. Whole rows only, so a pane beside a still one is diffed; only where erasing fills
  with the background (not GNU screen, not the Linux console); not while a kitty picture is
  held (it would move with the rows). A model terminal in the tests replays the bytes and
  checks every cell of every frame, up and down, by a row and by a page, past wide glyphs and
  a moving scrollbar.
- `%load-module-source` and `%load-string` name an error that names no file by the module's
  file; `LispError::relocated_out_of_std` leaves a parse error of std TEXT where it is — one
  whose trace has no frame in that file, since no std code ran. A parse error std code raises
  (`std/regex.blsp` rejecting a pattern) still moves to the program's call.

**Consequences.** bedit HEAD on `src/view.blsp`, 120×40 pty: on a pty that answers nothing,
alternate screen → first frame 2.65 → 1.03 s; in a real xterm (headless Xvfb), which answers in
about a millisecond, 49 → 47 ms, with frames now in true colour though xterm sets no `COLORTERM`.
A wheel notch 6.5 KB → 0.55 KB; C-v 6.9 → 6.3 KB and 4.8 → 4.7 KB (C-v keeps two rows of
context, so 36 of its 38 rows are new: little to move). Not done: DECSLRM for a side-by-side
pane, mode 2027 turned on (the cell model already measures graphemes), the terminal's own
colours used to choose a light or dark theme.

## ADR-741 — `defmemo-by`: one remembered answer per key, while its input is unchanged

**Status:** accepted (2026-11-17).

**Context.** `defmemo` (ADR-522, ADR-670) remembers a function's last N calls and compares a
call's arguments with each remembered call's by `=`. That is the right memo for "the same call
as a moment ago" and the wrong one for a second shape hot paths have: ONE answer per thing,
valid while the thing is unchanged — a registry's rows in rank order per registry id, a
buffer's table per buffer. `registry/ranked` used a 16-call `defmemo` on the table. bedit reads
about sixty registries in turn, so every call missed and re-sorted (one pass over 61
registries: ~210 µs), and even a hit on the identical table cost ~1.2 µs of memo machinery
(the argument vector, a `seq/find` with a closure over the remembered calls).

**Decision.** `memo/defmemo-by name capacity (key…) (input…) body` defines `(name key… input…)`
keeping one answer per key: a call whose key has an answer and whose inputs are `=` to the ones
it was worked out from returns it; otherwise the body runs and its value REPLACES the key's
answer. The key (the one key argument, or a vector of several) is hashed, so it is a small
value; the inputs are compared by `=`, never hashed, so the same cell answers at once whatever
its size. At most `capacity` keys are kept: a new key past that starts the store over (no
eviction order to keep, and a store that cannot grow). The store is `defmemo`'s per-process,
uncopied slot (`%memo-store`), holding a map key → `[value input…]`; a redefinition empties it
in every process. Written in Brood over the existing slot — no new primitive. `registry/ranked`
uses it (key = registry id, input = the entries table, capacity 1024); the cache stays per
process and outside `*registries*`, whose writes are journalled per writer (ADR-582).

**Consequences.** Measured with contracts armed, as `nest run` arms them: a `registry/ranked` hit
2.6 → 1.3 µs, a pass over 61 registries ~200 → ~90 µs (contracts off: 1.2 → 0.6 µs, ~110 → 40
µs). What is left of a hit is mostly the two contracts on `ranked` and `entries`, not the memo.
In bedit, `lsp/specs-for-extension` (key = the extension, input = the spec table) moved to it.
The other bedit memos stay `defmemo`: their arguments are the thing itself (a rope, a keymap),
with no small key to hash, and they are read once or twice a frame.

## ADR-742 — `table/tally`: a counter of several fields, bumped under one lock

**Status:** accepted (2026-11-17).

**Context.** A profiler counts two things per event — time and calls — and kept them as two
`table/incr`s, the second under a compound key `[:calls name]`. Each `incr` took the lock and
hashed its key; the compound key was also copied out of the heap on EVERY bump
(`incr_hashed` built the stored form before looking for it), and found by rebuilding the
stored key and comparing structurally. bedit's turnprofile paid that for every hook call and
every group of view sources: ~1.4 µs per `incr` with the compound key.

**Decision.** `(table/tally t k [d1 d2 …])` atomically adds each delta to the matching field of
the tally at `k` — a vector of integers as long as the deltas, an absent key counting as zeros —
and returns the new tally. One lock, one key hash and lookup, however many fields. A value of
another shape, a length mismatch or a field past ±2^63 is an error and leaves the table as it
was. It is its own primitive (`%table-tally`) rather than a vector-delta mode of `table/incr`,
whose int-only contract the JIT's dense lock-free path and the checker rely on. Alongside,
`table/incr` copies its key out of the heap only for an insert, as `put` already did.

**Consequences.** A time-and-calls note in bedit's turnprofile is one `tally` instead of two
`incr`s: 3.2 → 1.1 µs a note (contracts off: 0.65–0.9 → 0.4 µs; most of an armed call is the
std wrapper's contract). A tally lives on the hashed path: a dense (int-keyed) table migrates
the first time it is tallied, as it does for any non-scalar value.

## ADR-743 — `reflect/bound-value`: a late-bound name's value in one lookup

**Status:** accepted (2026-11-17).

**Context.** `reflect/call-if-bound` — how every registered hook is called — was
`(if (bound? name) (apply (reflect/eval name) args) fallback)`: the name resolved twice, once by
`bound?` and again by `reflect/eval`, whose path is the evaluator's. ~0.95 µs a call against
~0.3 µs for calling a no-op function. Ten other std sites spelt the same `bound?` + `eval` pair.
ADR-738 made `bound?` wait for a load another process holds (by handing its call back to the
engine as `%lazy-bound?`), so a second lookup cannot simply skip it.

**Decision.** A primitive `(reflect/bound-value sym [default])`: the value `sym` is bound to,
found exactly as `bound?` finds it — a short project spelling rooted, an imaged module's section
materialised, a load another process holds waited for (the redirect is
`%lazy-bound-value module sym default`, `%lazy-bound?`'s twin) — or `default` where `bound?`
would answer false. `bound?` and `bound-value` share one Rust walk (`derive::bound_lookup`).
`call-if-bound` is one `bound-value` with a sentinel default, so a name bound to nil still
raises when called, as before; the registry, project-image, stdimage, nest, dap and mcp sites
use it.

**Consequences.** `reflect/bound-value` is 0.15 µs; `call-if-bound` 0.9–1.0 → 0.7–0.85 µs (the rest is
the rest-argument list and `apply`). A name of a module nobody loaded still costs ~1.3 µs to
answer unbound, `bound?`'s own price: the module-loading and image-section checks. bedit's `sources/call-hook` resolves a hook once
with it and skips the claimant and the timing for a hook whose module has not loaded.

## ADR-744 — The terminal's answers acted on: its background's scheme, grapheme clusters, a pane scrolled in its columns

**Status:** accepted (2026-11-17).

**Context.** ADR-740 read the terminal's answers and kept three of them unused: its own colours
(OSC 10/11), whether it measures grapheme clusters (DECRQM 2027), and — not asked — whether it
has left and right margins. So `bedit -nw` on a light terminal drew the dark theme though the
user's init said to follow the system (a window follows `gui/desktop-preferences`; a terminal
had nothing to follow). A cluster whose code points add up to another width than the cluster
(a ZWJ family is three wide glyphs to `wcwidth`, a heart with VS16 one narrow one) was written
whole and counted at its Unicode width, so on a terminal without mode 2027 — xterm, VTE —
every cell after it on the row landed one or more columns off. And one pane of a side-by-side
split scrolling beside a still one moved no screen row whole, so ADR-740's scroll region never
applied: every row of the pane was rewritten (~5 KB a wheel notch in a 120×40 xterm).

**Decision.**
- `term/reported-colors` (primitive `%term-reported-colors`): `{:foreground [r g b]
  :background [r g b]}` as the terminal reported them when first asked — by the first
  `term-enter`, or by this call before it (raw mode taken for the moment, so the answer is read,
  not echoed, then left) — never the theme's colours `term/bg` gave it since. `{}` where there
  is no terminal. `term/color-scheme-of` is pure Brood: light when the background's WCAG
  relative luminance is above 0.179, where black and white text contrast it equally.
  `term/preferences` puts both in the shape of `gui/desktop-preferences`
  (`{:color-scheme … :foreground … :background …}`), so an app that follows the desktop in a
  window follows the terminal the same way.
- Grapheme clusters: `probe::ModeSetting` keeps a DECRPM answer whole (available, set, to be
  toggled). Where the terminal has mode 2027 reset, `term-enter` sets it (`CSI ? 2027 h`) and
  every leave resets it; set already, or permanently, it is left alone. `Screen::clusters`
  says which measure the terminal uses, and `glyph` draws by it: with clusters, the cluster
  whole; without, a cluster whose code points measure otherwise is drawn as its first code
  point, in the cells the app laid it out in (a narrow base then a blank) — so the grid, the
  app's layout and the terminal's cursor agree. A cluster that measures the same either way is
  drawn whole, as before.
- Column scrolls: DECRQM 69 (DECLRMM) joins the batched question; `Answers::column_margins` is
  `ColumnMargins::{Unavailable, Toggled, Held}` (`$TERM` cannot say, only the answer). One
  shape, `Region { top bottom left right }`, is what every scroll moves: `Scroll::sequence`
  writes `DECSTBM` alone for whole rows, and for a band of columns `DECSTBM` + `DECSLRM` inside
  the mode (`CSI ? 69 h` … `CSI ? 69 l`, whose reset also gives the margins back; `CSI s`
  instead when the mode was on already), so the terminal is never left in it. `find_scroll`
  first looks within the columns anything changed in (`changed_columns`, widened to take a
  wide glyph at its edge whole) with the same three stages over row SEGMENTS (`row_hash`,
  `likeliest_shift`, `best_band`, `vacated_cost` take the columns), at a higher cost
  threshold; a band that would cut a wide glyph at its edge is refused (`splits_a_glyph`); then
  whole rows as before. The model terminal of the tests now plays left and right margins and
  mode 69 (and both width measures, and mode 2027), and every frame of both panes scrolling,
  either margin mode, is checked cell for cell.
- bedit (`desktopprefs`): in a terminal whose theme follows the system, a one-shot timer on the
  loop's first turn reads `term/preferences` and puts `:theme-light` / `:theme-dark` in force,
  quietly (`:terminal-prefs` keeps the answer).

**Consequences.** Measured in a real xterm (headless Xvfb, 120×40, `bedit -nw src/view.blsp`,
C-x 3, three wheel notches over the left pane), the same binary with xterm's DECLRMM answer
filtered out of its input as the before: a wheel notch 4.9–5.1 KB → 0.7–1.0 KB; xterm's own
screen (dumped by its print-screen) is identical either way. C-v is unchanged (4.8 KB: 36 of
38 rows are new). On xterm (white background) bedit -nw now comes up in Catppuccin Latte. Not
done: the theme is chosen on the loop's first turn, so the first frame is drawn in the dark
theme for a moment — startup's `apply-look` asks the desktop only for a window, and could ask
`term/preferences` for a terminal (it works before `term-enter`); std/vt (the drivers' model
terminal) does not play DECSLRM, and nothing it hosts answers DECRQM 69, so it is never sent one.

## ADR-745 — A keymap names itself and groups its keys: `keymap-describe`, `keymap-bind`'s group

**Status:** accepted (2026-11-17).

**Context.** An Emacs prefix map carries a prompt string, and which-key reads a prefix's name
off the map it shows. A Brood keymap was a plain map `key -> binding` with nowhere to keep one,
so bedit kept which-key's names and groups in a registry of its own beside the bindings
(`keymaps/declare-prefix`, keyed by the chord), and listed every grouped key a second time, as
text, apart from the line that binds it. The panel then looked the pending chord up in that
registry: a map reached another way (a vim profile, a mode's prefix) had no name, and a key
rebound or moved left its group list stale with nothing to say so.

**Decision.** `std/editor/keymap` lets a keymap say what it is, in the map itself:
- Under ONE reserved key, `:keymap/info` (a qualified keyword: no frontend delivers one), a
  record — not a map, so a walker that has not heard of it never takes it for a prefix — of a
  `name`, the group `headings` in display order and `groups`, `{key heading}`.
- `keymap-bind` takes an optional `group`: the heading the last key is shown under, said where
  the key is bound. `keymap-describe keymap keys {:name :headings :group}` names the prefix map
  `keys` reaches (made empty when absent, as `define-prefix-command`), orders its headings, and
  puts the prefix KEY under a heading of its parent. `keymap-bind` extends a prefix in place,
  so the description survives later bindings under it (a user's, a package's).
- Readers: `keymap-name`, `keymap-key-group`, `keymap-groups` (`[[heading entries] …]`, the
  headings in order and holding only bound keys, then `[nil rest]`), and `keymap-entries`,
  the pairs less the info, which every walk in the module (`keymap-where-is`,
  `keymap-bindings`, the merges) goes through.
- `keymap-merge-stack` (so `keymap-merge`, `keymap-stack-binding` and `editor/layers`'
  composition) merges the infos: the highest map's name, every map's headings (higher first),
  each key in the group the highest map that groups it gives — a mode's `C-c` keys join the
  global map's groups.

**Consequences.** bedit's which-key panel and `keyhelp/ed-cmd-label` read the name and groups
off the pending keymap (`+project`); `declare-prefix`, its registry and the duplicated key lists
are gone, every grouped key tagged on its own `keymap-bind` line. describe-key, describe-bindings
and M-x's marginalia name a described prefix `+name` instead of `+prefix`. Not done: a
`describe-prefix-bindings` that prints the groups as headings.

## ADR-746 — The CPU painter copies each pane's own scroll, a zoomed pane's too, and leaves a picture's rows to the GUI thread

**Status:** accepted (2026-11-17).

**Context.** ADR-739 left three frames drawn that could be copied or shared out. Two panes of
a split scrolled opposite ways in one frame were drawn: a dirty strip was tried as one
translation over the hull of its changed columns, and one strip held two deltas. A scroll
inside a zoomed pane (a cell region on its own grid) drew every row of the pane it changed: the
pane's grid was diffed, never translated. And a large draw that met a picture gave its bands up
and drew every rect again on the GUI thread — a 1080p frame with a picture was slower on eight
threads (10.8 ms) than on one (8.5 ms).

**Decision.**
- **A strip's damage is spans of columns, each its own move** (`strip_spans`). The changed
  leaves' columns merged where they meet are the strip's spans; `strip_columns` is their hull.
  `strip_blits` tries the hull as one window first (one copy for a whole-pane scroll); when that
  is no translation and the spans are apart, each span is tried alone, with the deltas that
  carried strips before first (`RECENT_DELTAS`, a scroll moves a pane by one delta, two panes by
  two), and the strip is drawn over the hull of the spans left. Exact for the reason ADR-739's
  column copy is: outside the differing leaves' columns the pixels are the old ones, and inside
  a span every leaf that reaches it translates (`leaves_translate`).
- **A zoomed pane plans like the window** (`grid_plan`, the one plan of a grid: diff, narrow,
  copy, draw). `region_plan` runs it over the pane's own grid, its moves held inside the pane's
  band (`BlitBounds`), and copies a row only when the window's leaves over the same pixels — the
  ground under the pane, a box drawn over it — translate too (`BlitBounds::around`: the same
  `leaves_translate` over the window's leaves, the pane's leaf the twin of itself, its ops
  checked on its own grid).
- **A move carries its height** (`StripMove::height`: a zoomed pane's rows are its own), and
  `copy_strips` copies in place whenever its natural order — upward moves top down, then
  downward ones bottom up — writes no source still to be read (`StripMove::overwrites`); two
  panes scrolled opposite ways have their columns apart and pass. Any other mix goes through the
  kept scratch rows.
- **A band leaves a picture's rows to the GUI thread.** A picture is resampled into the
  renderer's cache as it is drawn, so no band draws it; instead of abandoning the frame, a band
  notes the rows the picture's block can reach (`BandPainter::pictures`), and the GUI thread
  draws those rows of that rect after the bands (`draw_rects`; `drawn_again_px` counts them). A
  rect drawn from the frame is its pixels whatever was under it, so the bytes are the same. A
  rect that met something else unprepared (a particle, an unforeseen glyph) is drawn again
  whole, and a band that panicked has all its rects drawn again. Knowing the pictures' rects in
  `prepare_ops` was not done: it would place every op a second time to save the band's drawing
  of the few rows that hold one.
- The leaves' columns are worked out once per leaf (`Leaves::columns`, on the grid they are
  measured on), and `Leaves::covering` finds a band's leaves through the strips it meets: a
  scroll asked both for every strip, span and delta it tried, and the opposite-way plan spent
  2.0 ms in them.
- Checked byte for byte against a from-scratch raster (`paint/incremental_tests.rs`: a split
  scrolled both ways one and two lines; a zoomed pane scrolled up, down and by two lines, with a
  box over it that stays put; a picture on 1, 2, 3 and 8 threads), and `copy_strips` against a
  reference for moves of mixed heights and opposite ways.

**Consequences.** At 1920×1080 (warm cache, test profile, a loaded 28-core machine; one thread
/ eight): both panes of a split scrolled opposite ways 8.1 → 1.4 ms / 2.7 → 1.7 ms, drawing
37 800 px instead of 1 963 332; a scroll in a zoomed pane 3.4 → 0.9 ms / 1.35 → 1.05 ms, drawing
80 600 px instead of 930 930; one pane of a split, which copied already, 1.24 → 0.9 ms on eight
(the columns memo). A full redraw holding a 480×360 picture on eight threads
10.8 → 6.2 ms (one thread: 8.5–9.7 ms), on eight bands instead of none. Not done: a zoomed pane
moved or resized (another rect) is still drawn whole; a span that is a translation of another
span's old columns (a pane scrolled sideways) is not looked for.

## ADR-747 — An answer only in an answer's shape; std/vt's left and right margins

**Status:** accepted (2026-11-17).

**Context.** ADR-740 read `ESC ]`, `ESC P`, `ESC _` as the start of a terminal's answer when the
byte after the introducer was how an answer begins (a digit, `>`, `G`), and then waited for a
terminator. So Alt-] then `1` typed in one read began an OSC "answer": every key after it was
swallowed until a 100 ms pause, and dropped. Separately, ADR-744 scrolls one pane of a
side-by-side split in its own columns (DECSLRM) where the terminal answers DECRQM 69, but
std/vt — the terminal bedit's pty drivers read the editor through — had no margins and answered
no DECRQM, so that path was never driven: and had it been, `CSI l;r s` was save-cursor there
and `SU` moved whole rows, the still pane with them.

**Decision.**
- One rule reads string sequences (`decoder::reply_shape`): their bytes are an answer while
  they are a prefix of one of `REPLY_SHAPES` — introducer, head (`10;rgb:`, `11;rgb:`,
  `12;rgb:`, `>|`, `0$r`, `1$r`, `Gi=`), then bytes of the shape's class (hex and `/` for a
  colour, printable text otherwise), within `REPLY_MAX` (512) bytes — and complete when BEL
  or ST ends them after a whole head. The first byte that fits no shape, a terminator before
  the head is whole, or a longer body, and they never were an answer: the introducer is the
  Meta key and every byte after it is fed again, as typed (`Decoded::KeyThenRest`, which now
  re-feeds any number of bytes). A shape whose values are garbled (a nine-digit channel) is
  an answer still, dropped, never typed. `begins_answer` is gone: it was this rule's first byte.
- Time: a part-read answer is a key time decides (`key_undecided`, `ESCAPE_PATIENCE`, 30 ms)
  unless a question is outstanding (`Decoder::await_replies`, set by `keyboard::ask` from the
  write of the question until its answers are in or its patience ends), when it waits as any
  sequence does (100 ms). Either way a flush re-reads it as Meta and the keys — never dropped.
  So an answer arrives in pieces only while one is expected; a late one must come whole, as a
  terminal writes it.
- std/vt: DECLRMM (mode 69, `:left-right-margins`; its set and reset give the margins back),
  DECSLRM (`CSI l;r s` in the mode, cursor home, a degenerate pair ignored; `CSI s` is
  save-cursor outside it), and every row scroll — SU/SD, IND/RI, a line feed at the bottom
  margin, IL/DL — confined to the columns between the margins (`shift-band`), doing nothing
  with the cursor outside them, and no history from a band narrower than the screen. DECRQM
  (`CSI ? n $ p`, `CSI n $ p`) is answered from one table of the modes vt has (1 set, 2 reset,
  0 for a mode it lacks — 2026 and 2027 included). The rules are the terminal tests' model
  terminal's (screen.rs); `std_vt_plays_the_column_scrolls_as_the_model_does` feeds the
  bytes of every frame of either pane scrolling, either margin mode, to both, and std/vt must
  show each frame's rows — one spec, checked from both sides on the same stream, rather than
  a third description kept by hand.
- bedit's driver harness answers its child as a terminal does (vt's `:replies` written back),
  so `bedit -nw` under a driver learns DA1, mode 69 and the rest in its startup question
  instead of waiting a second for none; `drive/start`'s `:watch` counts an output sequence,
  and `tools/drive-nw.blsp` checks that a wheel notch over the left pane of C-x 3 is scrolled
  in its columns (`CSI ? 69 h` written) and leaves every cell of the right pane as it was.

**Consequences.** Alt-], M-P, M-_ followed by anything typed arrive at once and whole; the
batch of real answers, cut at every byte, still reads as the same replies. Not done: std/vt
does not wrap printed text at the right margin, confine ICH/DCH to the margins, or make CUP
columns relative to the left margin in origin mode — nothing bedit writes relies on them.

## ADR-748 — The dispatcher enters a contract shim: arguments vouched for, the original called in its place, the result checked on return

**Status:** implemented (2026-11-17); its "Not done" and the walk it left are ADR-773.

**Context.** Under `nest run` / `nest test` every `sig` is a contract (ADR-381), and a
contracted call ran a Brood shim (`std/contract.blsp`) before its original: a frame of its
own on the bytecode VM (a shim never tiers, ADR-396), `%contract-args-known?`, a `not`,
`%contract-tail?` (a driver round trip), `%contract-await`, a computed call of the original,
`%type-verdict`. ADR-480 had made the CHECKS cheap — an unchanged argument is decided by its
tag or a remembered verdict — and left "a native shim" for when the shim itself was the
bottleneck. It now was: measured on the bytecode tier (callgrind, release-fast), a call of
`string/char-at` cost ~8 100 instructions armed against ~290 unarmed; a user `(int int ->
int)` wrapper ~14 000 against ~1 000. A decomposition with hand-written copies of the
template put the frame and its plumbing at ~85% of that and the type tests at ~10%. bedit's
`update "x"` makes ~540 contracted calls, 96% of them with every argument vouched for.

**Decision.** The call path takes a shim apart instead of entering it. Policy stays in Brood;
the kernel only skips a frame whose outcome it already knows.

1. **Entry** (`builtins/contracts.rs` `enter_shim`, from `dispatch`'s redirect loop, where a
   thin wrapper is redirected, ADR-069). A closure the contract module authored whose
   captured frame binds the template's names (`%contract-name`, `-orig`, `-spec`, `-ret`) is
   a shim. If the template would accept the call's arity and `args_vouched` — the one
   reading behind `%contract-args-known?` too — vouches for every argument, the dispatcher
   calls the ORIGINAL in the shim's place. Otherwise it runs the shim, whose Brood check
   walks, remembers and blames, exactly as before.
2. **The result** is owed unless the declared result is `any` (the template's tail call).
   `dispatch` roots the shim and hands the owed check back with the call: `Step::Tail`,
   `ChunkExit::Call` and `ChunkExit::Tail` carry `result_contract`. A call run to completion
   (a native caller, a value position, `force`) checks the value right there
   (`finish_checked`). A frame the bytecode driver pushes gets a **return handler**: a new
   `HandlerKind::ContractResult` on `Heap::vm_handlers`, naming the frame's depth and a root
   slot just below its base that holds the shim. On that frame's `Done` the driver asks
   `%type-verdict`'s question natively; a value it cannot vouch for runs the template's own
   `%contract-check-ret` IN THE RETURNING FRAME'S PLACE (a tail call at the same depth) — so
   its answer, or its `:callee`-blamed error, is the call's, named and positioned as the
   shim's frame would have had it (a contract-module arm, never named in a trace, its
   position the user's call). The handler
   catches nothing; an unwind drops it with the frame, a parked process keeps it.
3. **Tail calls stay flat** (KI-216, ADR-396). A tail call into a shim whose result an equal
   check is already owed — by a handler at this depth or by a shim's frame awaiting beneath
   (`contract_check_pending`) — owes nothing new; and a template's `%contract-tail?` now also
   answers true when a handler owes its frame's value. Both kinds of pending check collapse
   into each other.
4. **Base type names compile once.** `base_type_verdict` matched the name's spelling against
   thirty strings per check; each base name is now its set of runtime tags (one bit per
   `Tag`), built once per process — a lookup and a bit test. `is_base_type_name` and every
   kernel verdict read the same table.
5. The call sites that cache a callee's compiled arm (the VM's call IC, its computed-head
   miss, native code's link and computed-call caches) leave a shim to `dispatch`, as they
   leave a thin wrapper. `BROOD_NO_CONTRACT_DISPATCH=1` runs every shim as itself: the A/B
   and bisect lever. `%type-verdict-counts` reports `:entered`, the calls the dispatcher
   entered.

**Why not a native shim value, or a contract bit on every closure.** A shim stays the closure
`contract_bind` installed — its arity, `reflect/arglist`, the boundary alias (ADR-383), the
tree-walker and every introspection see what they saw — and the kernel recognises it by
construction, as `shim_original` already did. Nothing is cached about a shim, so a rebinding
or a changed declaration needs no invalidation. The cost to an uncontracted call is one
symbol compare where `dispatch` already reads the closure.

**Measured** (release-fast, this box loaded; callgrind on the bytecode tier, `BROOD_TIER=1`,
per iteration of a loop making one call, the empty loop subtracted):

| | unarmed | armed, shim (`BROOD_NO_CONTRACT_DISPATCH=1`) | armed, entered |
|---|---|---|---|
| `string/char-at` | ~290 | ~8 400 | ~6 200 |
| `string/starts-with?` | ~670 | ~8 800 | ~6 500 |

A root `(int int -> int)` wrapper called from a JIT'd caller (`perf stat`, noisier), ~11 000–14 000
→ ~5 300–6 400 (unarmed ~1 000). bedit at 213×49 on `src/view.blsp` (`tools/profile-turn.blsp`, three interleaved
runs each): `update "x"` 3.55–3.58 → 3.19–3.31 ms (unarmed 2.04–2.31), `view` after typing
2.57 → 2.33–2.39 ms (unarmed 1.44–1.89); per key ~6.1 → ~5.6 ms. What remains of an armed
key is the calls whose argument the kernel cannot decide (22 of ~540, through the Brood
`type-matches?` walk, ~12% of an armed update) and the path a contracted call takes through
`dispatch` (a hash lookup for the original's arm per call, and from native code the slow
call path — a shim is never linked).

**Consequences.** Guard: `tests/contract_dispatch_test.blsp` (entered calls answer as the
function does; `any`, rest and `&optional` shapes; a result only the walk decides; calls from
`map` and `apply`; a bad result blamed `:callee` with the shim's message and the user's
position, through a non-tail call and a tail call; a bad argument still the shim's `:caller`
error; the shim's arity error; return-checked mutual tail recursion flat at 300 000; an
unequal result type still checked) — three of its tests go red under
`BROOD_NO_CONTRACT_DISPATCH=1`. Unchanged and green: `contract_test`, `contract_memo_test`,
`contract_error_position` (every tier), `type_grammar_agreement`, `contracts_default`,
`check_contracts_agree`, `contracts_mode`'s enforcement and collapse cases. Not done: caching
the original's arm on the call site (the remaining `dispatch` cost), and linking a native
caller through an entered shim.

## ADR-749 — The CPU painter copies by a two-way offset: a pane scrolled sideways, a zoomed pane moved or resized

**Status:** accepted (2026-11-17).

**Context.** ADR-746 left two frames drawn whose pixels the canvas already held. A zoomed pane
(a cell region) that moved or changed size was compared as a value, so the rows of its old and
new rects were drawn across the window (1.37–1.49 M px at 1080p). And a pane scrolled sideways
was not seen as a copy at all: a move was a number of rows, found from leaves equal up to their
row, so a line cut at another column matched nothing (a whole-window sideways scroll drew
1.93 M px).

**Decision.**
- **A move is an `Offset` `{dx, dy}`**, and every copy is one: `StripMove` carries its
  destination columns and the column its source starts at, `strip_translates` checks the leaves
  over the destination against the old leaves over the source `offset` back, and
  `leaf_translates` asks each pair to paint the same pixels moved — the same op moved by the
  offset, a text whose units over those columns are the old one's moved (`text_translates`: a
  line scrolled sideways shows another slice of itself; a wavy underline only by whole
  periods), a fill that moved or covers both along each axis (`fill_translates`). The columns a
  sideways move brought in are drawn (`copied_columns`). One mechanism carries a scroll up or
  down, sideways, both at once, and a zoomed pane moved.
- **Candidates come from anchors** (`blit_offsets`): of the strip's first `ANCHOR_LEAVES`
  leaves, up to `ANCHORS` that pair with an old leaf — an equal op anywhere, or a text that
  lines up with one on its own row or on a row an earlier anchor moved by (`text_shifts`,
  after a byte check that one text starts inside the other) — suggest offsets, the ones more
  anchors agree on first, `ANCHOR_OFFSETS` at most. The old leaves are found through an index
  built once a frame is asked (`Leaves::partners_of`: texts by string, carets and one-row
  bands), not a walk of every leaf per anchor: a strip where nothing moved asks for each of its
  leaves, and that walk was most of what a frame showing another buffer spent looking.
- **A strip is cut into runs** (`strip_pieces`, which `strip_spans` gives way to; `piece_runs`):
  its changed columns as pieces
  (the differing leaves' columns merged where they overlap, so a gutter beside its text and two
  panes stay apart), and from the leftmost piece the rest whole at an offset already known (a
  whole-pane scroll: one check), else the first candidate carrying that piece stretched as far
  as it carries — to the end, to the last touching piece, then by halving. A pane moved down
  and sideways at once is two runs (its gutter down, its text down and across), two panes
  scrolled their own ways a run each. `STILL`, the zero offset, is a candidate too: a divider or
  a gutter the diff could not line up beside text whose leaf count changed paints what it
  painted, and is neither copied nor drawn. A copy must copy at least as many columns as it
  leaves to draw (a far move of something else's pixels lost to two near ones), anchors are
  looked for again past their reach only when the last ones carried something (`anchors_paid`),
  and a strip stops after `STRIP_MISSES` offsets tried in vain: a frame showing another buffer
  plans in ~0.5 ms more than drawing it outright. What is left to draw is cut into rects apart
  when far apart (`left_to_draw`, `GridDamage::apart`): two panes scrolled sideways opposite
  ways draw the columns each brought in at either end of the row, not the row.
- **A zoomed pane moved or resized is anchored like a resized window, by one mechanism**
  (`anchored_damage`, shared with `paint::resize_damage`). The pair is twinned when both keep
  their pixels to their rects (`region_extent`); its old pixels are copied to the new rect's
  top-left, row by row of its own grid, at the offset between the two (`moved_region_plan`),
  where the window's leaves over those pixels translate too (`window_translates`); the new rect
  is then diffed against the old ops laid out where the copy put them — drawn where they
  changed, past the old width (the new edge) and past the old height — and the old rect's
  uncovered part is drawn. The window's own diff leaves a moved pane to that plan
  (`differing_leaves` drops it), so a strip it alone came to or left is clean.
  `BROOD_GUI_BLIT=0` turns its copy off with every other.
- Checked byte for byte against a from-scratch raster (`paint/incremental_tests.rs`: a zoomed
  pane moved right over its own pixels, diagonally, grown, shrunk, moved and grown, moved with
  a line changed, under a box that stays, past the window's bottom and back; a pane scrolled
  sideways across the window, one pane of a split, the other, both opposite ways, down and
  sideways at once in four faces and in one, and another buffer shown; the moved and scrolled
  frames on 1, 2, 3, 8 and 64 threads).

**Consequences.** At 1920×1080 (`paint/timings.rs` `paint_move_timings`, test profile, warm
cache, a machine at load 10; one thread, the drawing on one thread: before → after): a
whole-window sideways scroll of 4 columns drew 1 926 288 px, now 37 044 (9.2 → 2.4 ms); one
pane of a split 926 100 → 37 044 px (5.0 → 2.1 ms); both panes opposite ways 1 926 288 → 74 088
px (8.9 → 3.7 ms); a line down and 4 columns across at once 1 972 593 → 76 923 px
(9.2 → 2.6 ms). A zoomed pane (half the window) moved 6 columns drew 1 370 880 px, now 39 510
(0.55 ms); moved diagonally 1 491 840 → 72 774; grown 1 451 520 → 68 238; shrunk 1 370 880 →
83 538 — 2.3 ms when only its new rect is drawn (the copy off), 0.55 ms copied. On eight threads
the copies gain less (whole-window sideways 3.3 → 2.4 ms), the copy itself being most of what is
left. A frame showing another buffer costs 3.0 → 3.5 ms on eight threads (9.0 → 9.7 on one) for
the looking. Not done: the copy of a moved zoomed pane's rows is per row of its grid, and the
window's moved rows below a seam on a resize are still drawn, not copied.

## ADR-750 — An import spelled like a language name is declared where it is used bare

**Status:** accepted, 2026-11-17.

**Context.** ADR-735 made a module that *defines* a root name declare it with `(:shadow name)`,
or fail compilation. An *import* spelled like a root name still only warned at the `(:use …)`:
`(:use version)` then `(compare a b)` silently called `version/compare`, and the warning went to
stderr where nobody reading the file sees it. The design rule is that a hazard either works as
written or fails compilation; a warning is neither.

**Decision.** A bare reference that resolves to an import whose bare name is a sealed, public
root name fails compilation unless the importing module's header declares `(:shadow name)` —
the same clause, the same key (`/shadow/name`), the same resolve-pass error channel as
ADR-735. The check runs where the name is *used*, like an import clash (ADR-235): an importer
that never writes the name bare compiles quietly, so `(:use log)` costs nothing until a bare
`error` appears. The error names both meanings and the three ways out (`(:shadow name)`, the
qualified import, `/name`); the hint names `:exclude`. A private prelude name (`def-`) is
exempt, as in ADR-735, since nothing could have referred to it. The `(:use …)` warning and its
mute flag `BROOD_NO_SHADOW_WARN` are deleted.

**Consequences.** Three test modules declare theirs (`version_test`, `version_oracle_test`:
`compare satisfies?`; `log_test`: `error`). No std module and no downstream project used such an
import bare. Guards: `crates/cli/tests/import_shadow.rs` (unused import quiet, bare use refused
before anything runs, declared wins, a private name's namesake free),
`tests/modules_test.blsp` and `tests/prelude_capture_test.blsp`; both Brood tests go red with
the check disabled.

## ADR-751 — A call stack is as deep as memory allows; the non-tail lint is gone

**Status:** accepted, 2026-11-17.

**Context.** A non-tail recursion stopped at fixed caps: 2^20 VM frames, 2^19 tree-walker
frames, and wherever the 16 MiB worker stack ran out for a native re-entry — a `try` body, an
`&optional` default, a `map` or `fold` callback, `eval` — measured on this machine at
1 048 574 plain, 355 822 through `map`, 104 856 through `map` on the tree-walker. The
checker's `:non-tail-recursion` lint warned about every self-call out of tail position
because of those caps, and 151 `(check-allow :non-tail-recursion …)` wrappers in std, the
tests and the fuzz generators answered it. The owner's rule: a hazard is designed away or fails compilation; a lint
that says "this might hit a cap" is neither.

**Decision.** A process's call stack is memory like its heap, bounded by memory:

- The engines' heap frames (VM `BcFrame`s, tree-walker continuations, the operand and env
  roots they hold) grow without a count cap. Every `FRAME_CHECK_INTERVAL` (4096) frames the
  engine measures them, plus the native stack the nest grew, against the process's
  **call-stack ceiling**: a quarter of the memory the runtime may use (the machine's physical
  memory, the address-space limit, the container's cap, the soft memory limit, whichever is
  least), and no more than the process's own `:max-heap`. Past it, `recursion too deep`
  (E0044, catchable) names the bytes and pending calls it held.
- A nested activation (`vm_apply`, the tree-walker's `eval` and `apply_closure` entries)
  runs in place while the native stack has room and continues on a heap-backed 8 MiB
  segment (`stacker::grow`) inside the last 512 KiB (`crate::stack::reenter`). Grown
  segments count toward the same ceiling. The JIT's stack-limit stamp is restored on the
  way out of a segment, since it is an address on one stack.
- A runtime with no memory limit takes a **soft** limit from its machine: three quarters of
  three quarters of physical memory, as a container cap of that size would give, and no
  more than half an address-space limit. Without it, a recursion whose levels each hold heap
  (the tree-walker's do) ran into the machine before any limit of the runtime's; with it,
  memory pressure stops the process holding the most, cleanly. The operating system stays
  the hard backstop.
- The `:non-tail-recursion` lint, its category and every wrapper are deleted, with the
  byte-budget guard (`stack_budget`, `BROOD_STACK_BUDGET`, `STACK_BASE`) and the native
  headroom refusal.

**Consequences.** Measured on the release build, 3 000 000 levels complete through a plain
call, `try` and an `&optional` default on both engines. Callback recursion (`map`, `fold`)
carries native stack per level, so it reaches its ceiling sooner: about 2 GB under a 16 GB
address-space cap, where that recursion stops near 3 M levels, catchably. A runaway
recursion under `:max-heap 200000000` stops at 200 MB. Tail calls are unchanged and still
hold no frame. Tests that relied on the caps to detect a broken tail position
(`tail_positions.rs`, `tree_walker_frames.rs`) set a small `:max-heap` instead; the JIT
recursion test now completes 2 000 000 levels in a spawned process where it expected the
cap. The `:check` policy test uses `:deprecated` as its advisory-by-default probe. Found on
the way: a deprecated name declared and used in the SAME file is reported only by the cached
`nest check` path, which loads the project first (a follow-up; the lint is built for the
cross-module case, where both paths agree). `GcBlockGuard` has no reader left; several call
sites say it blocks a collection, which ADR-061 ended — owed an audit.
## ADR-752 — `nest deps`: a project's module graph read as contexts, by name

**Status:** accepted (2026-11-17).

**Context.** bedit is being cut into contexts, Phoenix style: `display.blsp` is the context, its
details live under `display/` as `display/panebody` and the rest, and the other contexts call the
context's own functions. Nothing showed whether a project kept to that, or which modules reached
each other in a cycle; the first count was a grep over the sources, which also matched names in
docstrings and comments.

**Decision.** `nest deps` reads the module index (ADR-380: each file's module, the modules its
header requires, the modules its qualified references name — nothing loaded) into a graph of the
project's own modules, and reads it as contexts BY NAME: a module's context is its name before
the first `/`, and `a/b` is a detail of `a`. Nothing declares a context — the convention is the
declaration, as it is in Phoenix. The report lists every reference from outside a context into
one of its details, the groups of contexts that reach each other, and the busiest context edges.
`--check` exits 1 on any reference into another context's detail, so a project that has adopted
the convention can hold it in CI. The questions are pure functions over the graph
(`module-graph/violations`, `context-edges`, `cycles`), in `std/tool/module-graph.blsp`.

**Rejected.** A `(:context)` header clause that would make a reference into a detail a compile
error (an ADR-735-style refusal): it declares what the name already says, and a report is the
weight the convention wants — Phoenix teams hold the line with a report too.

**Consequences.** On bedit before the cut: 266 modules, 1464 references, four groups of modules
that reach each other (the git, LSP and mur modules, and the two ssh ones). A late-bound
reference by a quoted symbol (`'git/cmd-status` in a keymap) is not an edge: it loads nothing
and couples by name only. Tests: `tests/module_graph_test.blsp`.

## ADR-753 — `defdelegate`: a public function that is another module's

**Status:** accepted (2026-11-17).

**Context.** A context's API is mostly its details' functions under the context's name. Written
by hand, each is a wrapper that repeats the parameters and loses the target's documentation.

**Decision.** `(defdelegate name (params) target)` defines `name` to call `target/name` with the
same arguments; `:as other` calls `target/other`. `&optional` defaults and an `& rest` are
forwarded. It expands to an ordinary `defn`, so the call stays late-bound — a redefined target is
what the next call runs — and the target loads on first use like any qualified call. The
docstring names the target (`Delegates to [[target/name]]`) rather than copying it, because
copying would load the target at expansion. In the prelude beside `defmodule`.

**Consequences.** Tests: `tests/defdelegate_test.blsp` (plain, `:as`, optional, rest, late
binding, the docstring).

## ADR-754 — `nest rename-module`: a module renamed wherever it is named, its file moved

**Status:** accepted (2026-11-17).

**Context.** Cutting a project into contexts (ADR-752) renames most of its modules: `pool`
becomes `files/pool`. `nest rename` renames one identifier; a module is named as the prefix of
every qualified reference, in header clauses, and in prose, while a local often shares its bare
name (`region`, `pool`) — a token replace would rename the local too.

**Decision.** `nest rename-module FROM TO` rewrites, over the project's `.blsp` files: every
symbol `FROM/…` in code and in quoted data (through the lossless CST, so strings and comments are
untouched by that pass), the module of a `defmodule`, `:use`, `:use-internals` or `:alias`
clause, and a prose mention written `` `FROM/…`` or `[[FROM/…]]`. A bare `FROM` anywhere else is
a local and is left. The file moves to the path the new name gives under the same source root
(`src/pool.blsp` → `src/files/pool.blsp`). `codemod/rename-module-text` is the pure part.

**Consequences.** Tests: `tests/codemod_test.blsp` (clauses, quoted data, a local and a longer
name left alone, prose) and `crates/nest/tests/blsp_dispatch.rs` (the file moved, a missing
module refused).

## ADR-755 — The pattern grammar has one Rust reading

**Status:** accepted (2026-11-19).

**Context.** `std/prelude/match.blsp` compiles patterns and is the authority on what one
means. The Rust passes that need to know which parts of a pattern bind, which are
expressions and which are literals each re-read the raw syntax with their own switch over
the heads: the unused-binder lint, the checker's binding and domain readers, exhaustiveness,
the `:pure` walk, hygiene and the language server's scope analysis. The switches had drifted.
The clause-domain reader did not know `bytes` and read a `(bytes …)` parameter as a pair. It
read a map pattern as `map`, though the compiler's `%map-like?` admits a record, and it read
`(& r)` as a pair, though it matches anything. Each was a false "no clause accepts" on a call
that runs. The CST reader bound an `&optional` slot's default and a segment's dynamic size,
and the binding reader took `&optional` in a list pattern for a binder. A new pattern form
would have meant editing every switch, with a missed one failing silently.

**Decision.** `crates/lisp/src/syntax/pattern.rs` is the one Rust reading. `ListForm` says
what a list pattern's head makes it, and the readers that cannot use a parsed tree (the
hygiene rewrite, which rebuilds the pattern, and the CST) match it with no catch-all arm.
`Pattern` is the parsed tree, with `binders` (exactly `%pattern-vars`) and `expressions`. The
checker's readers are built on it. `crates/lisp/tests/pattern_grammar.rs` holds the two
languages together. The heads the compiler's shape predicates test for must be exactly
`ListForm::NAMED`. Rust's binders must equal `%pattern-vars` over a corpus covering every
form. A form the compiler refuses must parse as `Pattern::Refused`. The compiler now also
refuses two shapes it had accepted wrongly: `&optional` in a vector pattern (which compiled to
a test against the unbound symbol `&optional` and never matched), and anything after a record
pattern's field map (which was dropped without a word).

**Consequences.** A new pattern form starts in `match.blsp`, then takes a `ListForm` variant
and a corpus entry, and the compiler names every reader left to handle it. The parameter-list
readers (typed names, arity) are a separate grammar layered on top and keep their own code.
Tests: `pattern_grammar.rs`, `types::check::tests::domains` (the three domains, each side of
the boundary), `syntax::scope::tests` (the default and the segment size).

## ADR-756 — A verdict about every run of a form is judged over every copy of it

**Status:** accepted (2026-11-19).

**Context.** `%match-build-clause` splices a short fall-through into each point where a
clause can fail, so one source form appears in the expansion several times, each copy under
a different scope. In `(defn kx ((:a) 1) ((n) :when (int? n) n))` the second clause sits both
where the first clause's head was not `:a` and where it was `:a` but more arguments followed;
in that copy `n` is `:a`. The never-true lint judged each copy alone and reported
`int?: this can never be true — n is :a` on a guard the other copy needs. The same holds for
any clause-style `defn` or `match` whose first clause is a list or vector pattern with a
literal inside.

**Decision.** A finding on one path (an argument of the wrong type) is right to report from
the copy that has it, because that path runs. A finding that claims something of every run is
right only if every copy says so. `types/check/walk/every_copy.rs` opens a ledger around each
top-level form's walk. Each judged call records its visit and its verdict, and when the walk
ends a verdict that some visit did not reach is withdrawn. A copy on a path that cannot run
(its argument is `never`) records nothing. The expander rebuilds each copy, so the key is the
form's position and its text, not its heap identity. A macro that writes the same test twice
at one position is read as one form, which can only withdraw a finding, never invent one. The
never-true predicate lint is the one verdict that goes through it; the dead-clause lint
already rules out every binding the compiler generates.

**Consequences.** Tests: `types::check::tests::match_lints` (a guard one copy needs is not
reported; a guard dead in every copy still is). A future lint that states "never" or "always"
of a form reports through `every_copy::report`.

## ADR-757 — `:skip-unless CONDITION REASON`: a test a runtime fact skips still registers

**Status:** accepted (2026-11-19).

**Context.** `:skip` on a `test` or `describe` is a literal: a skipped test registers, counts and
reports, but the decision is written into the source. A project that gates tests on a fact it
learns at load time — a grammar compiled in, a tool on `PATH` — wrote
`(when (grammar-installed?) (describe …))`, which registers NOTHING when the fact is false. The
run reports fewer tests and stays green, so nobody notices: bedit's parsed-language tests had
been silently absent on CI. The run also only COUNTED skips (`3 skipped`); it never said which,
or why.

**Decision.** `test` and `describe` take `:skip-unless CONDITION REASON` among their modifiers,
beside `:skip` (and, written before a `(test …)` in a describe body, for that test alone, as
`:isolated` is). CONDITION is an expression evaluated as the test registers; when it is false the
test registers skipped and REASON (normally a string) rides in its meta and its result tuple, as
a 7th field read by `test/result-skip-reason`. A group's reason marks every test in it that has
no skip of its own. The human report lists every skipped test after the failures —
`○ group › name  file:line  — reason` under `Skipped (N):` — and `--trace`, TAP (`# SKIP reason`),
`--formatter json` and the eval server's structured result (`:skip-reason`) carry the reason.
The two static modifier scans in `tests/` learn that `:skip-unless` takes two forms.

**Rejected.** *A predicate-valued `:skip`* (`:skip (not (fact?))`): `:skip` is a bare flag today,
so a following form would be read as the body — changing what existing tests mean. *A reason
that is optional*: the reason is the point of the change; a runtime skip that cannot say why is
the silent `when` again with a count attached. *Not running a skipped group's body*: the body is
what registers the tests, so it must run for them to be counted; the work that needs CONDITION
belongs inside the tests, and the docs say so.

**Consequences.** Tests: `tests/test_skip_unless_test.blsp` (registration for a group, a test, a
body prefix and a lone test; a true condition runs; the listing, trace, TAP, JSON and non-string
reasons), the modifier scans in `tests/describe_modifiers_test.blsp` and
`tests/test_modifier_placement_test.blsp`; `tests/treesit_module_test.blsp` gates its new field
suite with it. Docs: `docs/testing.md` "Skipping a test". Projects replace their
`(when (fact?) (describe …))` gates with it.

**Amendment: the condition runs before the body.** A describe's CONDITION was first evaluated
after its body, where `emit-describe` applied the group skip, so a body-level form that needed
the condition's side effect — `(def tree (parse-with-grammar …))` under
`:skip-unless (load-test-grammar :perl)` — ran before the grammar was loaded. The describe now
evaluates CONDITION and REASON once, before the body, into `*group-skip*`, which `emit-describe`
reads when the body has registered its tests. A test's condition already ran as it registered,
before its body ever could. A skipped group's non-test body forms still run: the body is what
registers the tests, and tests sit inside `let`s and `doseq`s, so there is no clean cut between
the forms that register and the forms that do work.

This amendment first kept the skip on a stack, so that a nested describe could push and pop its
own. That was half a design: the collection state (`*collecting*`, `*collected*`) was not
stacked, so a nested describe discarded its outer group's collected tests, reported its own
twice and left the outer group's later tests outside any group, and a body that raised left its
entry on the stack. Nothing in Brood or bedit nests a describe, and supporting it would need a
rule for what an inner group inherits of each modifier, so **a describe does not nest**: one
written in another's body is refused at expansion, and one a body reaches through a call is
refused as it registers, because `*collecting*` (now the open group's name) is already set. A
body that raises leaves its group open; the runner loads each file in a scope it rolls back, so
that only outlives a load made outside it (a REPL's), where the next describe names the stale
group once and clears it, and `test/reset-units` clears it too. The body is not wrapped in a
`try` to close the group: a closure around it would hide its `def`s and impls from the checker.
A describe inside a `(test …)` body is not nested: the test runs it later, in a run of its own.

**Amendment: REASON cannot swallow the body.** With REASON left out, `(test "t" :skip-unless
(fact?) (assert= …))` read the assertion as REASON and registered a test with no body, which
passed. A REASON that is not a string literal must now have a form after it, and a
`:skip-unless` test with no body is refused, both at expansion. A bare `:skip` beside a
`:skip-unless` skips unconditionally and drops the reason (it reported the `:skip-unless`'s).
The eval server's structured result printed a non-string REASON as a value where TAP and JSON
printed its text; all of them use `test/result-skip-reason-text` now. Tests:
`tests/test_skip_unless_test.blsp`.

## ADR-758 — The indenter: brackets that hang, and content that opens at its line's start

**Status:** accepted (2026-11-19).

**Context.** `editor/treesit/indent-column` aligns a line under the first item of an enclosing
bracket that has content after its opener on the same line (`__all__ = ['a',` puts the next
item under `'a'`). A lambda breaks that rule: in Kotlin's `xs.forEach { item ->`, Scala's
`{ item =>` and Ruby's `{ |x|` what follows the `{` is a HEADER, and every formatter hangs the
body one level in. bedit's Kotlin and Scala modes aligned it nineteen columns over. Separately,
a line is left alone as content only inside a `:verbatim` node that began on an EARLIER line —
but Perl's grammar begins a heredoc's body AT its first content line, so that line was
re-indented as code and the heredoc's text changed.

**Decision.** Two rules, both data in the language's indent spec:
- `:hanging #{kinds}` names brackets that never align: when the innermost enclosing bracket is
  one, the line counts levels like any hanging indent. Only the innermost bracket is asked, so
  a lambda inside an aligned call still hangs, and the call's own arguments still align.
  A `:blocks` node whose nearest enclosing opener is a hanging bracket WITH a header after its
  opener shares that bracket's level: Scala keeps `{ item =>`'s body in an `indented_block`, and
  counted as a block it sat two levels in. A hanging brace that ends its line has no header, so a
  block inside it (`val x =` with its value below) still counts.
- A `:verbatim` node that begins EXACTLY at the line's start encloses the line as content when
  its parent began on an earlier line — the content continues what an earlier line opened. A
  docstring opening a statement at column 0 is still code, because its statement begins on that
  line too.
`language-names` reports `:hanging` kinds, so `grammar-problems` checks them against the grammar.

**Rejected.** *Recognising a lambda by its text* (`->`, `=>`, `|x|` after the brace): every
language spells its header differently and some (Swift's `in`) put it after the parameters; the
grammar already says which node is a lambda. *Treating every node that starts at the line's
start as content*: a misindented docstring at column 0 would then stay misindented.

**Consequences.** Tests: `tests/treesit_module_test.blsp` "a :hanging bracket indents one level"
(Ruby: a block alone, a call's arguments, a block inside an aligned call) and "a block directly
inside a :hanging bracket with a header shares its level". bedit's Kotlin and
Scala modes name their lambdas `:hanging`; its Perl heredoc test runs on a real heredoc again.

**Amendment: content from its start is named, `:verbatim-from-start`.** The second rule fired
for any `:verbatim` kind that began exactly at a line's start and ran past the line, so a PHP
`/* a` block comment at column 0 in a function body, or a Scala `"""` argument starting a line,
kept column 0 where a one-line comment got its level. Only Perl's heredoc body begins at its own
first content line; the kinds that do are named in `:verbatim-from-start #{:heredoc_content}`
(and are verbatim on later lines too), and every other `:verbatim` kind is content only from the
line after it opens. A comment line's column is the next code line's, and that line is now the
first after the comment ENDS, not a block comment's own second line. Tests:
`tests/treesit_module_test.blsp` "indent-column: :verbatim-from-start".

## ADR-759 — A tree-sitter node carries the field it fills in its parent

**Status:** accepted (2026-11-19).

**Context.** `editor/treesit/node-chain` and `node-children` (over `%tree-sitter-chain`,
`%tree-sitter-kids` and their held-tree twins) hand back each node as
`{:kind :start :end :named :container}`. Nothing says which SLOT of its parent a node fills, so a
caller that wants a definition's name guesses: bedit's breadcrumbs took "the first word that is
not a keyword", which names Java's `public static void main(` as `void` and Go's
`func (r *Rec) Name()` as `r`. The grammar already knows — `name`, `parameters`, `body` are
fields of the definition node.

**Decision.** Every node those queries return carries `:field <keyword>` — the field it sits
under in its parent (`:name`, `:body`) — when it sits in one; a node in no field (the root, a
keyword token) has no `:field` key. String and held-tree paths share one walk, so they agree.
The walks read the field off the `TreeCursor` they step with (`TreeCursor::field_name`): the
chain's descent finds its child with a cursor and keeps that child's field, allocating nothing
per level; the kids list is one cursor pass over the parent's children.

**Rejected.** *`Node::child_by_field_name` on demand*, a separate query per question: a caller
reading a breadcrumb for every definition on screen would make a round trip per node for a fact
the walk already had in hand. *`:field nil` on every node*: an absent key reads the same through
`(:field node)` and keeps the common, fieldless node's map as it was.

**Consequences.** Tests: `tests/treesit_module_test.blsp` "nodes carry their field" (a Ruby
method's name, parameters and body by field; the chain's fields from the root down; a held tree
agrees with the text). bedit can name a definition by its `:field :name` child.

## ADR-760 — A map's shape is checked in one place; a line's end is named; a swap is one edit

**Status:** accepted (2026-11-19).

**Context.** "Is this map the right shape, and if a key is unknown which did you mean" was
hand-rolled wherever a map is read as configuration: the project manifest's unknown-key warning
(`std/tool/project.blsp`), the tree-sitter face table and injection rules, `settings`, and in
bedit its language specs, source-table rows, plugin maps and settings. Each walked the keys
itself, and only some suggested a near miss. Separately, bedit spelt "the char where line N
ends" as `(if (< (inc line) (text/line-count rope)) (text/line->char rope (inc line)) (count
rope))` at seven sites. And `fuzzy/nearest`, the one "did you mean", ranked by Levenshtein
distance, which counts the commonest typo — two adjacent characters swapped (`:nmae`,
`widht`) — as two edits, so a short transposed name got no suggestion.

**Decision.**
- `(map/shape-problems value shape)` checks `value` against `{:required #{keys} :optional
  #{keys} :check {key predicate}}` (each part optional) and answers problems as DATA, `()` when
  it fits: `{:kind :not-a-map :value v}` (nothing else checked), `{:kind :missing :key k}`,
  `{:kind :unknown :key k :suggestion k2-or-nil}`, `{:kind :invalid :key k :value v}` — missing,
  then unknown, then invalid, each sorted by printed key. The suggestion is `fuzzy/nearest` over
  the allowed keys the map does not already hold, compared printed (`:name`), so string and
  symbol keys work alike. `(map/shape-problem->string problem)` says one as a sentence
  ("unknown key :nmae — did you mean :name?"). In `map` because it is a map transformation
  with no state, and a caller that warns, fails or draws a diagnostic each wants the data.
  The manifest's unknown-key warning is now one of its callers, and gains the suggestion.
- `(text/after-line->char rope line)` is the char index just after line `line`, its newline
  included: the next line's start, or the text's length on the last line — the half-open end
  `text/line` reads to. In Brood over `%rope-line->char`, which already answers the length for
  the line one past the last, so it is `(line->char rope (inc line))`; its one branch on the line
  count refuses a line out of range and ends the empty line past the end (`line-count` itself)
  where it begins. Named "after" so it cannot be read as the position OF the newline.
- `fuzzy/edit-distance` (and so `nearest`) is optimal string alignment: Levenshtein plus an
  adjacent swap at cost one.

**Rejected.** *A schema language* (nested shapes, types, defaults): `settings` already declares
typed values with defaults; this is the flat key check every reader needs first, and
`:check` predicates cover a value. *A new `shape` module*: two functions over maps belong with
the map helpers. *`text/line-end-char`*: whether "end" includes the newline is exactly what the
seven sites would have had to look up. *A transposition-aware distance only for shapes*: every
"did you mean" surface (the LSP's unbound-name action too) wants the swap counted the same way.

**Consequences.** Tests: `tests/map_shape_test.blsp` (every problem kind, the suggestion,
string and symbol keys, order, across processes), `tests/project_test.blsp` "project: an
unknown manifest key", `tests/rope_test.blsp` "text/after-line->char" (bounds exactly what
`text/line` reads), `tests/fuzzy_test.blsp` swaps. `editor/treesit/face-table-problems` and
`settings` keep their own walks for now — their messages name selectors and setting specs, not
just keys; they can move onto `shape-problems` when touched. bedit's seven line-end sites can
call `text/after-line->char`.

## ADR-761 — `defability` is the one contract mechanism; `defbehaviour` and `(:implements …)` go

**Status:** accepted (2026-11-19). Supersedes ADR-168 point 8 and what was left of ADR-158.

**Context.** ADR-168 made the ability the one *value-dispatch* seam and kept `defbehaviour` for
the case it called different: a contract a *module* satisfies, "a namespace with no dispatch
value". A module claimed one with `(:implements Name)` in its header, and the checker compared
the module's functions against the declared ops. Use since then measured it: the only
declarations anywhere were hatch's `LiveModule` and `LiveComponentModule`, and nothing in any
project claimed either, so the check had never run on real code. hatch's live views did not
need it either — the router held a record of closures, already a value.

An ability already enforces what a behaviour promises. Bodyless ops are required and the
checker reports an `impl` missing one or with the wrong arity; ops with a body are optional
defaults (ADR-185); `:requires` stacks contracts and `:sealed` closes a set. The one thing a
behaviour lacked an ability for — "there is no value" — costs one line: the module defines
one.

**Decision.** `defability` is the one contract mechanism, covering what other languages split
into protocols (one operation over many types) and behaviours (functions a module must
supply). A module contract is an ability over a value the module defines:

```clojure
(defability LiveModule
  (mount (view params))
  (render (view model))
  (handle-tick (view ms model) model))   ; provided
(defmodule counter-view)
(defrecord view ())
(impl LiveModule view (mount (_ params) {}) (render (_ model) model))
```

The caller holds the value and every call dispatches. Gone: `defbehaviour`,
`%register-protocol`, the `*protocols*` registry and `std/protocol.blsp` (the prelude's last
file outside `std/prelude/`), `reflect/behaviour-ops`, the `(:implements …)` header clause,
the checker's behaviour pass and its `*protocols*` dependency key, and the LSP's
`:implements` goto and hover. `(:implements …)` in a header is refused with a message naming
`defability`.

**Rejected.** *Keep `(:implements X)` but let it name an ability*: an op takes the dispatch
value first and a module function would not, so arities never line up, and nothing would
dispatch — a check with no runtime meaning. *Make a module itself a dispatch identity*: a new
kind of identity for something a zero-field record already gives.

**What it took for the check to hold across modules.** Moving hatch onto abilities showed the
contract was only checked inside one file, which is never where a module contract lives:
- **An `impl` is checked against every loaded ability**, not just the file's own `defability`
  forms: `protocol::collect` reads the `*abilities*` registry first.
- **The contract is per id, not per `impl` form.** A required op another `impl` provides for
  the same id — in the file or a loaded module — is not missing; bedit splits an LSP request
  kind's ops between `lsp` and `lsp/commands` on purpose, and a project check loads both.
- **`impl` registers under the ability's bare name.** `(impl web/session/SessionStore …)` —
  the spelling another module writes — filed its methods under a key dispatch never read.
- **`system/reload-defs` re-runs a top-level `impl`.** It re-ran only `def…` forms, so an
  edited contract method kept its old body after a save.
- **Each declaration is qualified with its own module's region** (ADR-223): two modules in
  one file that each `(defrecord live-view ())` read each other's constructor sigs.
- **`editor/ui`'s `Overlay` makes its ops provided** instead of a hand-written `:default`
  impl, which registered the same fallback but read as "every op required" to the checker.

**Consequences.** hatch's `deflive` / `deflive-component` generate a per-view record and an
`impl` of its `LiveModule` / `LiveComponentModule` ability, and the live runtime dispatches on
that value instead of holding a record of closures (hatch, same day). Tests:
`crates/nest/tests/module_contract_check.rs` (a missing op and a wrong arity on an impl of an
ability from another module, the qualified spelling, a contract split across two modules),
`types/check/tests/abilities.rs` "a module contract …", `names_as_types.rs` "same-named
records in two modules of one file", `tests/ability_test.blsp` "impl ability qualification"
(across processes too), `tests/reload_watch_test.blsp` "reload-defs: a top-level impl",
`tests/modules_test.blsp` "(:implements …) is refused, pointing at defability" — each
sabotage-verified.

## ADR-762 — A half-typed buffer: the indenter reads what is open off the parse's tokens

**Status:** accepted (2026-11-19).

**Context.** `editor/treesit/indent-column` counts the `:blocks` and `:brackets` nodes that
enclose a line. Typed a line at a time — electric pairs off, or a line pasted into the middle of
a file — a block is still unclosed when the next line is typed, the parse is broken, and no node
encloses anything: tree-sitter's recovery leaves the unclosed `{` or `do` as a bare token in an
ERROR node, or inserts a zero-width MISSING closer at the end of the text, where no chain
reaches. The indenter's fallback carried the previous line's indentation, one level deeper only
when that line ended in one of the language's `:opens` words, so RET after an unclosed `{`, `(`
or `[` landed a level short in every language that had not listed it, a closing `}` stayed a
level deep, a second `\` continuation went a level deeper again, and a keyword block (`do`,
`function`, `if … then`) indented by luck. bedit's corpus check that types each sample a line at
a time listed 163 such lines. Emacs's treesit answers the case with per-mode rules keyed on an
ERROR parent and on `no-node`; that is a rule per language per shape.

The same recovery surfaced in fontify: a MISSING node is a keyword or punctuation by its kind, and
the span walk reported it as a zero-width span, which every caller had to tolerate.

**Decision.**
- **The kernel reports the tokens.** `%tree-sitter-tokens source lang offset texts` (and
  `%tree-sitter-tree-tokens` over a held tree) answers the anonymous tokens before `offset` whose
  text `texts` names, in source order, each `{:kind "text" :start :end :parent}`. A token ending
  in an opening delimiter `texts` names counts as it (`${`, `%{`, `#{`, `\{` open what `{`
  opens). MISSING tokens are none. A construct that parsed cleanly and ends before `offset` is
  skipped whole, since it closes what it opens, except the last one before `offset` (an
  `elseif_clause` holds the `elseif` of an `if` left open outside it) and one made of tokens
  alone (HCL wraps a block's `{` in a `block_start`). So the walk is the path to `offset` plus
  the broken parts.
- **Brood matches them as a stack** (`ts-open-stack`): the delimiters always; a language's
  `:pairs` (`{"do" "end"}`) for keyword blocks; for such a language, the `:dedent` words that
  are not closers (`else`, `catch`) move their opener's header line to their own; `:clauses`
  (Elixir's `->`) open a clause that the next clause or the block's closer ends; tokens held by a
  `:modifiers` node kind (Ruby's `if_modifier`) open nothing. A delimiter closer pops to its
  opener; a keyword closer never pops past an open delimiter.
- **What the stack decides, on a broken parse only.** A line that closes (a delimiter, or a pair
  closer or middle word) sits at the line its opener's statement began on, which is the opener's
  line unless that line begins inside a bracket it closes first (`T t) {` of a continued
  parameter list). The line right below an opener's header goes a level in from it, or aligns
  under a `(`/`[` with content after it. Any other line carries the code line above it: a comment
  line as it stands, a line inside a `:verbatim` node as the line the node opened on, a level
  deeper when the line above ends in an `:opens` token (a token with no word in it, `\` or `:`,
  matched as a suffix), and a continuation (a non-word, non-bracket `:opens` token) adds its
  level once, the line after the run going back to where it began.
- **At the end of the text**, a line is measured at the newline before it, so an element the
  grammar closes implicitly at the end of input (HTML) still encloses it, unless that newline
  is a token of the grammar (go.mod). A closing line's verbatim check is asked at its first
  character, so `</style>` is not content of the `<style>` it closes.
- **`%tree-sitter-spans` drops an empty span** where spans are made: it colours nothing.
- `language-names` reports `:pairs` and `:clauses` tokens and `:modifiers` kinds, so
  `grammar-problems` checks them against the grammar.

**Rejected.** *Scanning the text for brackets*: a bracket in a string or comment would count,
and telling it apart is the parse's job. *Asking for the tokens with `%tree-sitter-parse`*: it
projects every node of the file, on every RET of a broken buffer. *Doing the matching in Rust*:
which tokens pair, which sit between, which are clauses is per-language policy, which belongs in
Brood. *Deriving keyword openers from `:blocks` node kinds*: in an ERROR node there is no
`if_statement`, only its `if`; the kinds say nothing about the tokens. *Per-shape rules keyed on
ERROR, as Emacs has*: one rule per language per shape, where the token stack is one mechanism.

**Consequences.** Tests: `tests/treesit_module_test.blsp` "indent-column on a broken parse" (an
unclosed delimiter, keyword `:pairs`, `:clauses`, `:modifiers`, a continuation, the end of the
text, the tokens, no empty span), "language-names … :pairs and :clauses". bedit's corpus typing
gaps go from 163 lines to 55, 14 of them Lisp indent rules and most of the rest `case`/`default:`
labels, which no `:electric-indent` names. bedit's Elixir, Julia, Lua, Ruby and shell modes name
their `:pairs` (Elixir its `:clauses`, Ruby its `:modifiers`), CSS `:` and Kotlin `=` join
`:opens`, shell's continuations (`\`, `|`, `&&`, `||`) too, and its corpus robustness check
refuses an empty span.

**Amendment: a continuation is named, `:continues`.** A continuation was guessed from the token's
shape: any `:opens` token that was neither a word nor a bracket. PHP's `:`, Scala's `=`/`=>` and
Kotlin's `->` are that shape and open blocks, so a broken parse's nested `if ($a):` / `if ($b):`
stopped nesting. The tokens that continue a statement are now named, `:continues #{"\\" "|>"}`:
a line ending in one carries a level, once, and needs no `:opens` entry. Tests: "indent-column
on a broken parse: openers that end in no word nest".

## ADR-763 — `sexp/enclosing` descends through reader-macro wrappers

**Status:** accepted (2026-11-19).

**Context.** `sexp/enclosing` answers the deepest list, vector or map holding a point. A quote, a
quasiquote, an unquote, a splice or a pin is a WRAPPER node holding the one form it prefixes, and
`enclosing` treated it as a leaf: a point inside `` `(let …) `` was enclosed by the form around the
backquote. Its docstring called descending through them a deferred refinement. Every Lisp
indenter built on it (bedit's `lisp-indent-with`, for Common Lisp, elisp, Scheme) indented a
quasiquoted macro body from the `defmacro` rather than from its own paren, and the structural
motions (`up`, `raise`) skipped a quoted list.

**Decision.** `enclosing` descends through a wrapper (`sexp/wrapper-kind?`: `:quote` `:quasi`
`:unquote` `:splice` `:pin`) as through a container, without ever answering the wrapper itself: a
point inside the wrapped list is enclosed by that list, and a point on the wrapper's prefix is
enclosed by whatever holds the wrapper.

**Rejected.** *Answering the wrapper as a container*: it has no head or arguments of its own, so
an indenter asking for its forms would read one form and no head.

**Consequences.** Tests: `tests/sexp_test.blsp` "enclosing descends through reader-macro
wrappers". bedit's Common Lisp corpus sample indents its backquoted body as written.

## ADR-764 — A Lisp dialect names its own docstring places

**Status:** accepted (2026-11-19).

**Context.** `editor/highlight` tells a docstring from a string value by Brood's doc-carrying
heads (`(reflect/doc-forms)`, ADR-265): the string after the name or the parameter list of a
`defn`. A dialect passes its own special-form set, but not this: elisp's `defun` was never a doc
head, so its docstring painted as a string, and its `defvar` documents in a place no Brood head
uses, third, after its value.

**Decision.** `highlight-spans` takes an optional `docs` table, and `lisp-line-lexer` a `:docs`
option, as the special-form set already is: head → `:fn` (after the name or the parameter list,
with more body after it), `:head` (the same places, nothing needed after) or an integer N (the
form's Nth element after its head, whatever follows: `defvar` is 3). Absent, Brood's table.

**Rejected.** *A fixed union of every dialect's heads in std*: elisp's `defvar` and Brood's `def`
disagree, and the table is the dialect's to say.

**Consequences.** Tests: `tests/highlight_test.blsp` "a dialect's :docs table", "the line lexer
reads the same table". bedit's `deflisp` takes `:docs`; elisp and Common Lisp name theirs.

## ADR-765 — A face selector may ask for a child: `:has`

**Status:** accepted (2026-11-19).

**Context.** A face-table selector matches a node by its kind and its context (`:parent`
`:field` `:nth` `:text` `:after`, ADR-486, ADR-487, ADR-614). A coloured node is painted whole,
so two nodes of one kind that differ only inside cannot be told apart: Rust's `///` and `//` are
both a `line_comment`, the first holding a `doc_comment`, and `///` could not take the doc face.

**Decision.** A selector map takes `:has`: a child the node must have, named by a kind keyword or
a `{:kind :field :text}` map (the field it fills in the node). It is checked last, walking the
node's children, named or anonymous, and it outranks every other constraint at its level.
`face-table-problems` checks its shape, and `language-names` reports its kind and field, so
`grammar-problems` checks them against the grammar.

**Rejected.** *A Rust special case in the kernel's span walk*: every grammar that marks a node by
a child (a doc comment, an attribute) wants the same. *Painting the child and not the node*: the
`///` marker and the text would colour apart.

**Consequences.** Tests: `tests/treesit_module_test.blsp` "face tables: :has", "face-table-problems
and language-names know :has". bedit's Rust face table paints `///` and `//!` as docs.

## ADR-766 — An indent spec's `:blocks` and `:brackets` take a kind in a context

**Status:** accepted (2026-11-19).

**Context.** `indent-column` counts the `:blocks` and `:brackets` nodes enclosing a line, named
by kind. A grammar may give one kind two roles: Ruby's `rescue` body is a `then`, the kind an
`if`'s branch has, but it sits inside the `body_statement` that already counted the method's
level, and a method's own `else` is an `else` inside it too. Counting the kind everywhere put
every `rescue` body a level too deep.

**Decision.** An entry is a kind keyword or a map: `{:kind :then :parent-not :rescue}` counts the
kind only when its parent in the chain is none of `:parent-not`, `{:kind :then :parent #{:if}}`
only when its parent is one of `:parent` (each a kind or a set). `language-names` reports the
kinds such an entry names.

**Rejected.** *A per-token dedent for `rescue`*: it fixes the `rescue` line, not the body below
it. *Ancestors further up than the parent*: no grammar met so far needs one, and the parent is
what a chain reads in one step.

**Consequences.** Tests: `tests/treesit_module_test.blsp` "indent-column: a :blocks kind in a
context". bedit's Ruby spec scopes its `then` and `else`.

**Amendment: one context language, the face selectors'.** The entry map above was a second,
smaller copy of the face-table selector language (ADR-486, ADR-614, ADR-765): `:parent` there
takes a selector map, here a kind or a set, and `:parent-not` had no counterpart. It could not
say "a `rescue` whose parent is a `body_statement`", and `block-entry-holds?` raised on a vector
of entries and ignored `{:parent [:if :unless]}`. An entry is now a kind keyword or a face
selector, in the part of that language a node's chain answers: `:kind`, `:field`, `:parent` (a
kind or a selector, asked of the node above, so a grandparent is a `:parent` of a `:parent`) and
`:not`, a new constraint in both: a kind or a selector the node must not satisfy at its place.
The face tables take `:not` too (the kernel's `Selector`, weighted above `:has` in specificity);
`:nth`, `:text`, `:after` and `:has` need siblings, children or text a chain does not carry, and
the new `indent-problems` refuses them in an indent entry, as it refuses an unknown spec key, an
old `:parent-not` and a kind list that is not a collection. `{:kind :then :parent-not :rescue}`
is `{:kind :then :not {:parent :rescue}}`. Only a NAMED node holds an entry: a keyword token
often shares its node's kind (Ruby's `else` keyword is an `else` inside the `else` node) and
never encloses a line. The entries are any collection.

The chain-level question is public as `indent-entry-holds? (entries chain index)`; the node-and-
parent `block-entry-holds?` stays one release as a deprecated alias over a two-node chain, said in
its docstring rather than with `(meta … :deprecated)`: the checker's advisory finding would fail
bedit's strict ratchet before bedit switches.

A dedent table entry may be `:spanned` (`{"else" :spanned}`): one level when a counted block spans
the node the token begins, none when not. Ruby's method-level `else` is a child of the
`body_statement` that counted the method's level, an `if`'s `else` an arm beside the `then`, and
one number for `else` was wrong in one of them; the chain at the token tells them apart. A
`begin` holds its statements directly, so it is a `:brackets` entry (it opens on its own line)
and its `end` backs out with `{"end" :spanned}`. A closing line counts only the nodes that began
before its token: re-indented from scratch the token sits at the line start, and the `else` arm
it begins counted as enclosing its own line, a level deep where the line as written held (the
Ruby corpus listed it as a gap).

**Rejected (amendment).** *Keeping a second, indent-only context map*: two languages for "this
node, here" drift, and the face one already had the nesting. *Sets in `:kind`*: one entry per
kind says the same with no new shape. Tests: `tests/treesit_module_test.blsp` "face tables:
:not", "indent-entry-holds?", "indent-problems", "indent-column: a :blocks entry in a context".

## ADR-767 — A block bounded by sibling tokens: `:token-blocks`

**Status:** accepted (2026-11-19).

**Context.** `indent-column` counts enclosing nodes. HEEx's `<%= if … do %>`, `<% else %>` and
`<% end %>` (and ERB's) parse as three SIBLING directives, so no node encloses the block between
them and its content was not indented. ADR-762's open stack matches keyword `:pairs` over the
parse's tokens, but only on a broken parse, and its token walk skips clean constructs.

**Decision.** With `:token-blocks true`, the stack counts on a clean parse too: every keyword entry
open before the line is a level added to the enclosing nodes', less one on the line whose first
such token closes or re-opens one (its `<% end %>`, its `<% else %>`). `%tree-sitter-tokens` takes
an `all?` flag that walks every token before the offset, since a clean directive is exactly what
it skipped; and a `:pairs` closer may be a NAMED leaf's kind when that is the grammar's only
spelling (HEEx's `end` is an `ending_expression_value`).

**Rejected.** *Rewriting the directives into a tree in Brood*: the token stack already is that
tree's depth, and ADR-762 built it.

**Consequences.** Tests: `tests/treesit_module_test.blsp` "indent-column: :token-blocks". bedit's
HEEx spec names its `do`/`end` pair and the key; its `do`-block lines indent as written.

**Amendment: clauses, middles, and what the vocabulary cannot see.** A `:clauses` token (`<% 1 ->
%>`) opened a level that no line took back: a clause line counted the clause before it, and a
closer that popped a clause and its opener backed out one. The line's first keyword token now
backs out what it pops — a clause the clause before it, a closer every level between the stack
before and after it, a middle the clauses and one more — and that first token skips delimiters,
as a line's leading `{@x}` closes no keyword block. A middle word is named with `:middles`
(`#{"else"}`), beside the ones taken from `:dedent` for a language with keyword `:pairs`: HEEx
listed `else` in `:dedent` only to make it a middle, and so dedented a line of TEXT starting with
"else". The line's tokens are read once, to its end. The limit is the vocabulary: HEEx's
expression is one leaf, so the `fn` of `<%= Enum.map(xs, fn x -> %>` is no token, its `->` reads
as a clause of the enclosing `do`, and its `<% end %>` closes that `do` too — the docstring says
so, and a test pins it. On a broken parse the line's first keyword token is its closer wherever
on the line it sits (`<% end %>` begins with `<%`), and a clause line sits at the clause before
it. Tests: "indent-column: :token-blocks with clauses, middles and
delimiters", "indent-column on a broken parse: :token-blocks closers and clauses".

## ADR-768 — A release bundle launches lazily from its own image, std modules included

**Status:** implemented (2026-11-19). Amends ADR-484.

**Context.** ADR-484 gave a bundle its own startup image but kept "a bundle loads every
embedded module" at launch, naming a lazier boot as a separate change. bedit's bundle had grown
to 308 modules, an 11.8 MB image, and `bedit --version` — answered on `main`'s first line —
took ~0.6 s and ~287 MB: 272 sections materialised before `main` ran. Tracing a launch found
two more costs. The std modules a bundle uses came from the stdlib image in the user's cache,
written only by a `nest` or `brood` of exactly the same stdlib, and from SOURCE without one: a
fresh machine, or a toolchain one version away from the release, made the same launch 2.5×
slower. And the bundle's own boot code (`project-release`, `project-image`, `project`, …) loads
before `run-bundle` installs the image, so it had the same dependency on the cache.

**Decision.**

1. **A launch with an image loads nothing up front.** `bundle-boot-load` takes a mode:
   `:launch` installs the image and requires only modules the image has no section for (a file
   that declares another namespace, which no first use could find); each other module
   materialises on first use, as `nest run`'s does (ADR-218). The root section already restores
   every module's registrations. `:check` (`--brood-boot-check`, the release smoke) and
   `:source` (the image writer) still load every module, so a module that cannot load fails the
   release, not the user's launch.
2. **The bundle's image carries the std modules its load used.** `write-bundle-image` counts a
   std module loaded at write time as carried and drops its names from the baseline, so they
   are sectioned like the app's. A std module first reached at run time is not in the image and
   comes from the stdlib cache or source, as before; carrying every baked-in module would put
   registrations from modules the app never loads into the root section.
3. **Registries ride the root section only.** A std module's registry stays in root even when
   the module is carried (that module may have materialised from elsewhere first, and its
   section would never be read — every app's `registry/*registries*` lost), and a registry in
   root is no longer also written into its module's section.
4. **The prelude preinstalls the bundle's section directory.** At boot, before the stdlib
   image, `%bundle-image-preinstall!` adds the bundle image's directory (no root section) as a
   feature source when its stamp matches, so the boot code materialises from the bundle. The
   stamp is `%bundle-image-stamp`, the one the writer uses.

**Consequences.** bedit: `--version` 0.60 s → 0.20 s (~287 → ~212 MB), the same with or
without a stdlib cache; a headless `--serve` reaches "serving" in ~205 ms against ~620 ms. The
image grows by the carried std sections (11.8 → 14.8 MB). The largest remaining piece is the
root section (3.4 MB, ~50 ms), which every launch decodes. `BROOD_IMAGE_TRACE` now reports
each section in microseconds with its facts, uses and deferred-define time, plus a total and
read time per call — the millisecond figures had rounded most of the cost to zero. Guard:
`release_bundle.rs` `an_imaged_bundle_launches_lazily_and_carries_its_std_modules` (an
unreached module stays unmaterialised, a std module and the boot code come from the bundle
with an empty cache, the app's registration survives with and without a stdlib cache); each
half sabotage-verified.

## ADR-769 — A startup-image section spells each symbol once

**Status:** implemented (2026-11-19).

**Context.** Images reuse the node wire codec for values, and the codec spells a symbol by name
everywhere it occurs — necessary between runtimes, whose interners differ. An image's values
are mostly code-as-data, which is mostly symbols, so decoding one paid a string allocation and
an interner lookup per occurrence: 336 000 of them to start bedit (ADR-768), the largest share
of the 38 ms its sections spent decoding.

**Decision.** Each section carries a symbol table after its entry count: every distinct symbol
the section's entries encode, spelled once and interned once on load; the entries name a symbol
by `u32` index into it. The codec consults a per-thread `SymbolTableScope` that only the image
writer and readers open, around one section at a time, so a node link never sees a table and its
encoding is unchanged; an index outside the table is a decode failure. Sections stay
self-contained, so a partial rebuild's copied sections (ADR-419) keep working. The prelude image
uses the same section encoder and gets the table too. `MAGIC` v12, `PRELUDE_MAGIC` v9.

**Rejected.** *A table for the whole image*: a section is read alone, lazily, and copied
verbatim between images; a shared table would tie every section to the file it was written in.
*Interning symbols by id*: ids are per process, and images outlive the process that wrote them.

**Consequences.** bedit's bundle: section decode 38 → 15.5 ms of a `--version`, bytes read
9.1 → 7.3 MB, the image 14.8 → 11.9 MB, `--version` ~0.20 → ~0.18 s. Every image shrinks
alike — the stdlib cache, `nest run`/`nest test` project images and the prelude image. Guards:
`symbol_table_tests` (a repeated symbol is spelled once and restores intact — sabotage-verified
by spelling every symbol; the node codec still spells; an out-of-table index does not decode).
What remains of a launch's section time is the promote copy into the RUNTIME region (~47 ms on
bedit's `--version`) and `from_message` (~25 ms); building straight into the region would remove
most of both, but holds unpublished RUNTIME values across the define's lock — GC-region work to
prove under stress on the test machine, left open.

## ADR-770 — String patterns: `(str "prefix" slot "suffix")`, and a dead string clause fails compilation

**Status:** accepted (2026-11-19).

**Context.** Brood code tests strings by their ends constantly — 854 `string/starts-with?` and
286 `string/ends-with?` calls across std/, tests/ and seventeen downstream repos, 176 of them
followed within three lines by slicing the prefix off, and twenty-odd `cond` chains testing three
or more prefixes in a row. Such a chain is correct only in its order: bedit-agent's diff
colouring tests `"+++"` before `"+"`, and swapping the two lines makes the header case dead with
nothing to say so. `match` could not help: it had no way to say "a string that starts with".
The view-pattern thread (handoff thread 8) was the general answer and stays deferred; Erlang
(`<<"GET ", Path/binary>>`), Elixir (`"GET " <> path`) and the Lisps' regexp patterns all
answer parsing with a fixed, pure text pattern instead of a call inside a pattern.

**Decision.** One named pattern form, written like the `str` call that builds the string:

```clojure
(match line
  ((str "GET " path) (serve path))      ; prefix — the rest binds
  ((str stem ".blsp") (load stem))      ; suffix
  ((str "<" tag ">") (open-tag tag))    ; both ends
  ((str "exact") :exact)                ; no slot: the exact string
  (_ :other))
```

Each part is a string literal (or a pin, an end known when the match runs — see the follow-ups),
and **at most one** part is a pattern — the slot — matched against what lies between the literals
before it and after it. Adjacent literals join. The value must be
a string, long enough to hold both ends without overlap; ends are compared in characters, as
`count` and `string/substring` count. It lowers to the test a hand-written one makes (a type
test, a length floor, the ends compared with `%eq`, one substring for the slot — none for `_`).
It is a pattern everywhere patterns are: `match`, `fn` heads, refutable `let`, and `receive`,
where it is safe because it calls no user code.

Refused at expansion, each with a message naming the fix:

- **A second slot.** `(str key "=" value)` could split more than one way; the message points at
  `string/split` and `regex/find`.
- **`&`.** `(str "GET " & path)` — the slot already takes the rest.
- **A clause an earlier one makes unreachable because of a string pattern.** A guard-free
  earlier clause whose `(str …)` pattern, with a slot that always matches, covers every string a
  later pattern matches fails compilation, as a clause after a catch-all does: `(str "+" _)`
  before `(str "+++" _)` or before `"+x"`. The comparison is structural — lists and vectors by
  position, an `(or …)` by its alternatives — so it holds in an `fn` head and inside a message
  vector (`[:line (str "E" _)]` before `[:line (str "ERROR " _)]`). An alternative of one
  `(or …)` that an earlier alternative covers is refused the same way.

The check reports only when a string pattern is part of the proof, so every match without one
compiles exactly as before; the checker's `:unreachable-clause` warning still reports the rest.
A dead clause here is a certainty the macro holds both literals for, so it is a compile failure,
not a new warning.

**Rejected.** *A regexp pattern* (Racket's `(regexp rx pat)`, `pcase`'s `rx`): searching versus
matching the whole string is a trap either way it is decided, two regexps cannot be compared at
expansion, so the dead-clause check is lost, and a clause that looks like data hides a scan of
the text; `regex/find` with named groups and a map pattern already says it. *A view pattern
(`app`)*: deferred (handoff thread 8) — it runs user code inside a pattern, which `receive`
re-runs on every mailbox scan. *Several slots split at the first or last occurrence*: a rule
the reader has to remember for every pattern; one slot needs no rule. *A pinned prefix
(`(str ^sep rest)`)*: additive, and nothing asked for it yet (ADR-011). *A new head word* (`prefix`,
`text`): `str` reads as the constructor, the way `[a b]` and `{:k v}` do.

**One failure exit, by construction.** The pattern lowers to a single `(if (and (string? v)
(>= (count v) n) prefix-test suffix-test) matched fail)`. The first lowering had a type test with
its own exit around the rest, and the clauses after it are spliced at every exit, so the checker
read their copy under the type test's exit with the value as `(not string)`: a string-taking
call in a later clause, on a value it knew nothing about, was reported as a mismatch. Every
migration agent hit it within minutes; the fix is the shape, not a checker exception.

**Migration (same day).** brood's std/ (14 sites in 13 modules — `url`'s RFC 3986 §5.2.4 loop
now reads as the RFC's steps, `fuzzy`'s `^…$` arithmetic as four clauses), bedit (42 sites),
hatch (18), mur-forge (16), hive, bedit-agent, mail and s3 (7). The dead-clause check found one
real redundancy (bedit's `vcsproc`, `"new mode"` after `"new "`, harmless). What the migration
said about the form: a prefix held in a variable is the commonest site it cannot take (a pin
would be the slot); an end that is one of several literals, `(str (or "a" "b") _)`, was tried
twice and is now refused with a message naming `(or (str "a" _) (str "b" _))`; a non-empty slot
needs a `:when` (or a literal clause first) to keep an old `count > n` guard; and the
formatter's hanging of a long clause body under its pattern pushed a few conversions back to
`cond`. In a module that defines its own `match` (`fuzzy`), the form is `/match`.

**Follow-ups (same day), from the migration's findings.**

- *A pinned part is an end.* `(str ^marker body)` — a prefix held in a variable, the commonest
  site the form could not take. A pin is text known when the match runs (the pinned value's
  `str`, as the `str` call would build it), so it joins the literals beside it and is never the
  slot. Nothing changes meaning: `(str "#" ^x)` used to pin the remainder to `x`, which is the
  string `(str "#" x)` either way. The dead-clause check passes over a pinned end. A pinned value
  that is `nil` makes the clause fail: read as `(str nil)` it would be the end `"nil"`, and a
  prefix that was never set would match `"nil-thing"` (found migrating bedit, where a nil prefix
  needed a hand-written `:when prefix`).
- *The formatter lays a clause's body under its pattern.* A list whose head is a pattern
  rather than a symbol is a clause; its body rides the pattern's line only when it fits there,
  else it starts the next line at the body indent — a call's first argument would hang deep under
  the pattern's end. `:when guard` rides the pattern's line. The one-time reformat of the tree
  collapsed each body the old layout had hung (a break the old formatter made, which the
  formatter would otherwise keep as an author's) before re-breaking it.
- *No spelling for a non-empty slot.* A literal clause first, or a `:when`, says it with what
  exists; a marker in the slot would be one more rule in the grammar for no new meaning.
- *From the review (same day).* A literal that is not a string — `(str "v" 1)`, `(str "x" :a)`
  — is refused: it could only be the slot, which never equals text, so it compiled a clause that
  never runs. `(str s)` lowers through the same one exit (its own `string?` test had brought the
  `(not string)` misreading back). The dead-clause comparison runs only for a match with a string
  pattern in it. The formatter decides a clause by context — every child of `match`/`receive`
  after the scrutinee, and an `fn` clause (a list, vector or map head) — so `(:error …)` and
  `(_ …)` lay out like `([:ok v] …)`, and `:when guard` rides only a clause, never a call whose
  first argument is `:when`, and never past a comment, which riding would have dropped.

**Consequences.** `ListForm::Str` and `Pattern::Str` in `syntax/pattern.rs`; the hygiene and CST
readers walk its parts as `or`'s; `sigs.rs`' clause domain is `string`. A list pattern headed by
the symbol `str` — before this, a list of that length binding a variable named `str` — now means
the string pattern. Guards: `tests/string_pattern_test.blsp` (shapes, binding sites, refusals,
the dead-clause check in all its positions, a property differential against a hand-written
test, and the pattern across processes — each red under sabotage), `pattern_grammar.rs`'s corpus,
and `type_check_catalog.rs`'s must-not-warn cases for a value past a refutable string clause (red
with the two-exit lowering back).

## ADR-771 — An imaged value is built straight into the RUNTIME region

**Status:** implemented (2026-11-19).

**Context.** Materialising a section rebuilt each value with `from_message` into the process's
LOCAL heap and then bound it, and the bind's promote copied the whole value again into the shared
RUNTIME region, leaving the LOCAL copy as garbage. On bedit's `--version` (ADR-768/769) the
two together were 64 ms of the sections' 102 ms. ADR-769 left this open because the value would
sit in RUNTIME before being bound.

**Decision.** `Heap::build_shared` rebuilds an imaged message directly in RUNTIME: lists,
vectors, strings, byte blobs and closures (arms, pass-through analysis, captured frame) are
minted in place, and every list position of the value is stamped under one lock rather than one
write lock per list. A map, set, failure or record builds its children shared and its trie LOCAL
around them, then copies the nodes. The rare rest (a big number, a closure with module guards or
shared arms, a handle) is rebuilt LOCAL and promoted as before. A table entry stays LOCAL, since
its contents are deep-cloned into a fresh store anyway.

Every slot is minted under the `promote_lock` read guard, as `promote` mints them. The guard is
not held into the bind: the lock is not reentrant against a queued writer, and the facts a
define replays take `registry_lock`, which orders before it. The bind follows with no safepoint
in between, so the process cannot ack a drain while holding the unbound value. `env_define`'s
promote passes a RUNTIME value through, and its re-home moves one an aging flip left behind.
That is the window a journalled `def` already leaves when it stages a binding.

**Rejected.** *Holding the guard across the bind*: a lock-order inversion with `registry_lock`
and a re-acquisition of a non-reentrant lock. *A batched promote*: measured, no change, because
the cost was the copy itself.

**Consequences.** bedit's `--version` 0.17 → 0.135 s; its sections 102 → 75 ms (build plus bind
64 → 37 ms). Every imaged start gains alike: the stdlib cache, `nest run`/`nest test` project
images, bundles. Guard: `build_shared_tests`. A value of every kind comes back in RUNTIME equal to
its source, its closure calls through its captured frame, its forms keep their positions, and
no list is built LOCAL. Each of the last two was red under sabotage. The image test binaries
(cli, nest), `startup_image_test` and `stdimage_test` pass. GC stress over every test file runs
in CI (`full.yml`), not on the development desktop.
## ADR-772 — A line breaks at LF, CR or CRLF, and nowhere else

**Status:** accepted (2026-11-19).

**Context.** The rope took ropey's default `unicode_lines` feature, which breaks a line at VT,
FF, NEL, U+2028 and U+2029 as well as LF, CR and CRLF. Nothing else in the system counted lines
that way: LSP breaks at LF, CR and CRLF, `scanner::line_starts` had dropped U+2028/2029 for
exactly that reason, a buffer search's `^` followed LF only, and the points handed to tree-sitter
came from the rope. So `(text/line-count "a\u{c}b")` was 2, `end-of-line` in `"x\u{c}y\nz"` stopped
at the form feed, `^ab` never matched where the rope said a line began, and every diagnostic and
semantic token bedit placed in an Emacs Lisp or C file (both use `^L` page breaks) landed a line
off per form feed.

**Decision.** One definition: **a line breaks at LF, at CR, or at CRLF (one break)**, never at
a form feed, a vertical tab, NEL or a Unicode separator.

- The rope builds ropey with `default-features = false, features = ["simd", "cr_lines"]`.
- `scanner::line_starts` already counted that way.
- A buffer search (`regex/rope-*` in line mode) reads `^` and `$` as `(?mR:^)` / `(?mR:$)` and
  `.` as `[^\r\n]`: `$` stops before a CRLF, and `^` follows a lone CR.
- The points handed to tree-sitter count it both for a rope and for a flat string
  (`host/treesit.rs`, `point_of` and `FlatText::points_of` now agree). Tree-sitter's own rows
  count LF only, so on a lone CR its rows differ from ours; the parse is byte-addressed and
  nothing reads a row back, so the difference changes no answer.

`text/line-text` and `text/line-end->char` (new natives) strip and stop before whichever break
a line has, so a caller never strips `"\n"` by hand and misses a `"\r\n"`. ADR-760 rejected a
`text/line-end-char` because "end" left open whether the newline was in; `line-end->char` is
the end of what `line-text` answers, and its docstring says so, beside `after-line->char` for
the end with the break. `text/char->utf16` and `text/utf16->char` (ropey's
`char_to_utf16_cu` / `utf16_cu_to_char`) give an LSP client its positions without building a
codepoint list per line.

**Consequences.** A form feed is an ordinary character on its line. A CRLF file's line text
from `text/line-text` carries no stray `\r`. A lone-CR file has the same lines in the rope, the
scanner, LSP and a search.

## ADR-773 — Compiled contracts: the call site caches a shim's original, native code links through it, and the kernel reads the type grammar

**Status:** implemented (2026-11-20).

**Context.** ADR-748 took a contract shim apart in `dispatch`: a call whose arguments the
kernel vouches for runs the original in the shim's place, and a return handler checks the
result. It left three things, each named in its "Not done": every contracted call still went
through `dispatch` to find the original's arm (the call ICs left a shim uncached, as they leave
a thin wrapper); native code never linked through a shim, so a JIT'd caller took the slow path
and `dispatch` on every contracted call; and the arguments the kernel could not vouch for — 22
of ~540 contracted calls in a bedit key, by ADR-748's count — ran the Brood `type-matches?`
walk, ~12% of an armed update. The idea for the last was to compile a declared type once into a
native verdict structure.

What those calls are was measured first, with a new diagnostic: `BROOD_CONTRACT_WALK_TRACE=1`
names every declared type the dispatcher could not vouch for and the kind of value it met.
Through `tools/profile-turn.blsp` on `src/view.blsp` at 213×49 (bedit's whole profile run,
startup included), 19 405 such checks:

| checks | position | declared type | value |
|---|---|---|---|
| 9 331 | argument | `editor/buffer/buffer` | a `buffer` record |
| 5 659 | result | `editor/buffer/buffer` | a `buffer` record |
| 1 106 | argument | `(record &open :__id__ :editor/buffer/buffer :file (or string nil))` | a `buffer` record |
| 762 | argument | `buffer` | a `buffer` record |
| 622 | result | `(or (list symbol) nil)` | a list |
| 496 / 50 | argument / result | `bedit/model/model` | a map |
| 441 | result | `editor/pane/layout` (a `len` field) | a map |
| 362 | result | `(list (tuple int int (or nil int) vector))` | a list |
| 240 | result | `(vector (map keyword any))` | a vector |
| 181 | argument | `(map int int)` | a map |
| 136 | the rest | `or`, `tuple`, `map` shapes | |

Four fifths are a `defrecord` NAME against a record: the kernel decided base names, literals,
`?A`, arrows and `or`, and a record or vector shape one level deep, but a record name went to
`%nominal-type-matches?` every time — and a record value is never remembered (the memo keys by
handle, and a record is not one). The rest are compound forms the kernel did not read (`tuple`,
`map`, `len`) or read only one level deep.

**Decision.**

1. **The call IC holds a shim's original** (`core/heap/vm_cache.rs`). A new entry kind,
   `CalleeKind::Shim`, holds the ORIGINAL's arm and env behind the shim value. It is read back
   only through `vm_call_ic_contracted`; to every other reader — the VM's arm path, the
   self-tail probe, the fast-link mirror the IR reads, the debug views — the entry is arm-less,
   exactly what a shim's entry was. So nothing can run or link the original without the
   vouching, by construction rather than by every reader remembering to check. The entry stays
   48 bytes (the kind byte was there). `contracts::shim_call_site_arm` decides what may be
   cached: a shim the dispatcher enters, at an arity its template accepts, over an original
   that is a closure with a compiled arm and neither a thin wrapper (`dispatch` redirects
   those) nor itself a shim — the cases where "call the original's arm" is what `dispatch`
   would do. A shim's captured frame never changes, so the epoch the entry already carries is
   all the invalidation it needs.
2. **The bytecode call site enters the shim itself** (`exec_chunk.rs`). The probe it already
   makes returns the original's arm too (`vm_call_ic_probe_shim`, one borrow); on a hit it asks
   `enter_shim` — the same reading as `dispatch`, over the arguments where they lie on the
   operand stack (`Heap::roots_slice`) — and on `Forward` runs the original's arm as the call's
   `fast` arm. A declared result other than `any` is owed: the call then takes the frame path
   with `result_contract` set, so the return handler, the tail-call collapse (KI-216, ADR-396)
   and the errors are ADR-748's unchanged. An `any` result owes nothing, so such a call takes
   every fast path a plain call does — in place, the VM→native direct call, the inline self-tail
   reset. A call the kernel cannot vouch for goes to `dispatch`, which runs the shim.
3. **Native code links through a shim** (`jit_runtime/dispatch.rs`, `jit_dispatch_call`).
   Native code's resolve fills the same entry (a shim whose original cannot be cached is
   installed arm-less once, not re-examined per call), and a hit vouches for the staged arguments and
   links the original's native code exactly as it links any closure — or, not yet native, runs
   its arm on the VM — then checks the returned value (`finish_checked`, what `dispatch` does
   for a call it runs to completion, so a native caller's errors are what they were). A linked
   call that owes a check does not preempt by unwinding (ADR-401): the rebuilt bytecode frame
   would return past the check. The link stays in Rust: the IR's flat fast-link cell is never
   published for a shim entry (the entry is arm-less to `vm_call_ic_fast_link`), since the IR
   cannot vouch for an argument. A native TAIL call into a shim still goes through `dispatch`
   (`jit_dispatch_tail`), whose `Step::Tail` carries the owed check to the driver.
4. **The kernel reads the type grammar** (`core/heap/type_verdicts.rs`, `Heap::decide`). One
   recursive reading replaces the form / one-level / decided-part trio, mirroring `%type-match`
   case for case:
   - a type NAME by what it names — an alias by its expansion, `?A` accepts, a sealed ability
     admits its members' record ids, and a nominal name (a `defrecord`'s, or one nothing
     defines) admits a record whose id it names (`%record-id-named?`) and otherwise refuses
     exactly when some record carries the name. What a name is (`NameKind`) is remembered per
     name, and whether an id names a type per pair, under the verdict stamp — every input
     (the alias store, `*sealed*`, `*record-ids*`, the namespace) moves it;
   - a form by its head symbol, compared as an interned id with no list built: an arrow
     anywhere, `or`, `and`, `not`, `is`, `(int lo hi)`, `(len T lo hi)`, `list` (uniform and
     positional), `vector`, `set`, `seqable`, `map`, `record` and `tuple`;
   - descending into the value's elements, fields and positions as the walk does, to
     `DECIDE_DEPTH` (24), remembering every compound part it decides — so a fresh model whose
     buffers did not change is the top level and one lookup per buffer;
   - a record INSTANCE's field is its field map's entry, and a missing or nil field is nil
     when its record implements no `Lookup` (`*impls*`, remembered per id); one that does is
     the walk's, since only `get` can ask it.

   Left to the walk: `rec`, an int or string literal type (`=` is numeric), a string's or
   bytes' `len` (`count` is characters), a lazy range or seq-view where a list is asked for, a
   sealed ability over a non-record, an unknown head, and anything deeper than the bound —
   a cyclic alias among them, which the walk's `seen` answers.

**Why not a compiled type structure.** The plan was to compile each declared type once into
a native verdict tree. Every input such a tree would bake in — an alias's expansion, a name's
record, a sealed set, a record's `Lookup` — can change while the program runs, so the tree
would need the verdict stamp's invalidation, and a lookup to find it per check costs what
reading the form now costs: the form is a few pairs, its head an interned-id compare, and the
part that was expensive (what a NAME means) is exactly what is remembered. The memo then makes
an unchanged compound value one lookup. So the "compilation" is that reading — no list built,
no spelling compared, names resolved once per stamp — and there is no second representation of
a type to keep in step with the first.

**Measured.** bedit at 213×49 on `src/view.blsp` (`tools/profile-turn.blsp`, three interleaved
runs each; `base` is brood `9c1e11e9a`, this branch at `7658723`, before the probe refinements
below; release-fast, this desktop):

|---|---|---|---|
| `update "x"` | 3.24–4.05 ms | 2.30–2.46 ms | 2.01–2.18 ms |
| `view` after typing | 2.38–3.00 ms | 1.68–1.74 ms | 1.42–1.61 ms |
| `update :ctrl-n` | 2.74–3.21 ms | 1.84–2.19 ms | 1.54–1.67 ms |

## ADR-774 — A word is letters and digits plus what the word syntax adds

**Status:** accepted (2026-11-20).

**Context.** `editor/buffer`'s `forward-word` / `backward-word` treated a word as "anything that
is not a delimiter": `*word-delimiters*` was whitespace and ` /()[]{}";,`. So `.`, `-`, `_`,
`=`, `+`, `:`, `'` and `<` were all word characters, and M-f over `foo.bar(x) + baz_qux`
crossed `foo.bar` and `+` and `baz_qux` each as one word. The line editor (`editor/lineedit`,
the REPL's M-f / M-b) had its own predicate with a slightly different delimiter list and a
`:path` mode that added `/`. Neither matched Emacs, which bedit targets, and neither could vary
with the text: Emacs's text-mode joins "don't" into one word while its programming modes split
`foo_bar` and `foo-bar` (`_` and `-` are symbol constituents there, not word constituents).

**Decision.** Emacs's model: **a word is a run of word characters, and a word character is a
Unicode letter or number, a combining mark, or one of the extra characters a WORD SYNTAX
declares.** Everything else separates words.

- A word syntax is plain data, `{:word-chars "'"}`. Letters and digits are implied; nil, or a
  map without `:word-chars`, adds nothing. Which syntax applies is the caller's business (an
  editor reads it from the buffer's mode); the toolkit does not know modes.
- `%skip-word (text at forward? word-chars inside?)` is the native scan: how far a run of word
  (or non-word) characters reaches from `at`, over a rope or a string. On a rope it walks the
  leaves from `at` and reads only the run, as `%rope-skip` does, so a word motion on a large
  buffer costs the word. Rust is justified for the same reason `%rope-skip` is: the class
  "letter or number" is a Unicode table, and a Brood predicate per character would put a closure
  call on every character crossed. A combining mark counts so a decomposed `é` (e + U+0301)
  stays inside its word.
- `std/text` carries the policy: `word-char?`, `forward-word`, `backward-word` and
  `word-bounds` (the word at or just before an index — a double-click, `thing-at-point 'word`),
  each taking the text, the index and the syntax.
- `editor/buffer/forward-word` and `backward-word` take the syntax:
  `(forward-word buf syntax)`. No default arity: every caller says which words it means.
  `*word-delimiters*` is gone.
- `editor/lineedit` moves by the state's `:word-syntax` (a `lineedit-init` option, default nil)
  through the same scans, and its private predicates are gone. `:word-mode :path` (a file
  prompt) keeps its own unit: there a word is a whole path component, everything between two
  `/`, so C-w takes `foo.txt` back to the folder at once, as Emacs's vertico-directory does.

**Defaults.** nil — letters and digits only — is Emacs's programming-mode answer (python-mode,
emacs-lisp-mode, c-mode: `_` and `-` are symbol constituents) and the REPL's, whose lines are
Brood. Emacs's standard syntax table also makes `$` and `%` word characters, and text-mode adds
`'`; an editor that wants those spells them in the syntax it passes.

**Rejected.** A predicate function as the syntax (`(fn (character) …)`): it cannot reach the
native scan, which is the whole cost. Symbol constituents as a second class beside words (Emacs's
`_`, which `forward-symbol` and dabbrev read): nothing in the toolkit moves by symbol yet, and
`text/skip-forward` over a delimiter set already serves the callers that want identifier-shaped
runs. It is additive when one does.

**Consequences.** M-f / M-b / M-d / C-w stop at `_`, `-`, `.`, `'` and other punctuation under
the default syntax, in an editor buffer and at the REPL. A caller of `forward-word` /
`backward-word` passes a syntax (bedit reads its mode's).

## ADR-775 — A window can tell its app each time a frame is presented

**Status:** accepted (2026-11-20).

**Context.** A game loop (b2d's `run-on`) stepped its simulation on a timer — `receive` with an
`(after)` deadline every `1/fps` — and drew fire-and-forget with `gui/draw`, into a window that
presents FIFO. Nothing told it when a frame reached the screen or how long a refresh is, so a
60 Hz timer beat against a 59.95, 60.02 or 144 Hz panel: some refreshes showed the same frame
twice, others dropped one. In a side-scroller that is visible jitter, and no amount of policy
in Brood could fix it without a signal from the display. The window already knew both things:
each paint ends in a present (the GPU target's `queue.present`, softbuffer's `present`), and
`frame_period` reads the monitor's refresh for the window's own animations.

**Decision.** Mechanism only; pacing stays the app's policy.

- **`{:present-events true}`** in `gui/open`'s opts (so also `gui-display`'s): after every paint
  that reached the compositor — the GPU target's and the CPU painter's alike — the window
  delivers **`[:presented t-ns]`** to its subscriber, through the same mailbox as its input and
  resize messages. A paint that presented nothing (a GPU frame skipped for want of a swapchain
  image, a softbuffer buffer that could not be had) sends nothing. Headless windows present
  nothing and send nothing.
- **Every frame drawn is answered.** A window does not repaint a frame identical to the one on
  screen; one that reports its presents presents it again, unchanged. Otherwise a loop paced by
  presents that drew a frame with nothing new in it — a 60-step game on a 144 Hz panel, between
  steps — got no present back and stalled until its own timer fired (measured: presents fell from
  144 to ~23 a second in dino).
- **Off by default.** A window opened without the option sends no new message, so every
  existing app's `receive` is untouched. It is a build-time option, not a `:configure` one: a
  thin client's window would forward each present over the wire as input, which is the wrong
  clock for the game on the other end.
- **`t-ns` is on `os/now-ns`'s clock, kept monotonic:** the wall clock is read once (the first
  present) and every stamp is that plus the monotonic time since. Two presents a refresh apart
  are a refresh apart even across an NTP step, and a stamp still compares with `os/now-ns` (to
  within the wall clock's drift since). It is when the present call returned, not when the panel
  scanned out — wgpu exposes no presentation-time feedback — but on Wayland both paths are paced
  by the compositor's frame callback (ADR-726) and on X11 the GPU target's FIFO acquire blocks,
  so under vsync the stamps come one a refresh.
- **`gui/refresh-hz`** (`%gui-refresh-hz`, and a `gui-display`'s `:refresh-hz`): the monitor's
  rate in hertz as the platform reports it, or nil (no rate reported, headless). The window
  re-reads it at most once a second while it paints, as it already did for `frame_period`.

**Consequences.** A game draws one frame per `[:presented]` and steps its fixed-dt simulation
by the time since the last one (b2d's present pacing: whole steps from an accumulator, the
remainder carried, the time snapped to whole refreshes of `gui/refresh-hz`), which is one frame
a refresh on any panel. A display that presents unpaced (a CPU window on X11, MAILBOX or
IMMEDIATE) sends presents as fast as the app draws; the option does not throttle them, so a
loop that paces by them must treat a present less than half a refresh after the last as no
refresh at all. Remote displays and older runtimes send none, so a loop keeps its timer as the
fallback. Tests: `present_tests` (the message's shape, the opt-in, the clock),
`window_spec_tests` (the option's parse, off unless asked), `tests/gui_present_events_test.blsp`
(headless: asked, sends nothing; no refresh rate).

## ADR-776 — A project keeps its image and check verdicts per build, three slots each

**Status:** accepted (2026-11-20).

**Context.** A project's startup image (`.brood/image.bin`, ADR-218) and its check-verdict
manifests (`checks`, `checks-run`, `verdict` under `~/.cache/brood/check/<root>/`, ADR-119/382)
were one file each, stamped with the build id (and for the manifests the walk flags). Anything
that ran a second binary on the same checkout threw the first one's away: an installed `nest`
beside one built from a working tree, a release and a debug build, a profiling build, or one
run with `BROOD_TIER=1`. The next run with the first binary paid it back whole. On bedit that
is a 4 s `nest run` with 26 s of CPU (the pre-flight re-checking the entry's closure) where a
warm start is 0.27 s, and a profile taken with a second binary measured the rebuild instead of
the start.

**Decision.**
- **The image is slotted by build and contract mode**, the half of its key a partial rebuild
  (ADR-419) cannot work around: `.brood/image-<build-id>[-contracts].{bin,includes,modules}`.
  The build id (`version+sha+binary stamp`) is already a file name, so the slot is readable.
  Within a slot nothing changes: the full fingerprint and the partial rebuild work as before.
- **A manifest is slotted by its stamp**: `<name>-<16 hex of sha256(stamp)>.blsp`. A slot is
  exactly 16 hex digits, so `checks` never claims `checks-run`'s or `checks-strict`'s files.
- **Three slots of each, least recently USED evicted.** A slot that is read is touched
  (`file/set-mtime`), and a write prunes its kind to the three newest by mtime. Eviction by
  write time would let a run of fresh dev builds push out the installed toolchain's slot,
  which is the case this exists for.
- **No migration.** A checkout's old `image.bin` and `checks.blsp` are left where they are;
  `.brood/` is a gitignored build artifact and the check cache's weekly sweep removes an
  abandoned project's directory.

**Consequences.** Switching toolchains on a project costs a cold start once per build, not
once per switch. Disk: up to three images per project (bedit's is 12 MB). The `brood file`
pre-flight cache and the prelude and stdlib images were already keyed per build. Test:
`crates/nest/tests/image_slots.rs` (four builds against three slots, from one binary copy whose
mtime is reset before each run; sabotage-verified for the single path and both touches).
