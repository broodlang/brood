# Design decisions: ADR-500 onward

One of the six files the ADR log is split across by number; the index, and the notes that
apply to every entry, are in [../decisions.md](../decisions.md).

## ADR-500 — Hygiene at every binding site of the one pattern grammar

**Status:** implemented (2026-10-28).

**Context.** The ADR-066 amendment made a quasiquote template's own binders hygienic, but
only plain-symbol `let`/`letrec`/`fn` binders. A destructuring pattern, a `match` or
`receive` clause, and every standard binding macro (`when-let`, `for`, `doseq`, `with`,
`try`'s `catch`, a template `defn`'s params, …) left the template's binder literal, so it
captured caller code spliced into its scope — silently, exactly where the docs said
hygiene was automatic. A typed binder was worse: `(fn (x:int) …)` was renamed to
`x:int__609`, which kept neither the annotation nor the binding of the body's `x`.

**Decision.**
- The rename runs before the macros in a template expand, so it is told where each form
  binds. It follows the one pattern grammar in `let`/`letrec`/`fn` binders and in clause
  patterns: a symbol binds; a pin's expression, a dynamic `bytes` size and an `:or` default
  are references; a quoted symbol, a literal and a `record` name are neither; a name
  repeated in one pattern (an equality constraint, `or`'s alternatives) keeps one
  replacement.
- The standard library's binding macros are described by shape in the hygiene pass:
  binding pairs (with keyword modifiers, and `if-let`/`if-some`'s else branch outside the
  binding), pattern clauses (`match`, `match*`, `receive` with its `after`), `catch`,
  `as->`, and the params of `defn`, `defmethod` and `impl`.
- A typed binder renames its name and keeps its annotation: `x__12:int`.
- The resolver reads the same shape table (`hygiene::shaped_binders`). It qualifies a
  template's free names when the macro is defined, before these macros expand, so without
  the table it qualified their binders under a runtime `eval` (`a` → `my-module/a`). A
  qualified name is never renamed, so those binders escaped hygiene and their arglists read
  `(my-module/a)`.
- A renamed binder is shown as written. Every place a parameter list reaches a person — an
  arglist, `reflect/arglists`, the runtime arity error, the checker's arity warning — reads
  it through `ClosureArm::source_params`, which shows a gensym by its prefix
  (`value::source_symbol`). A template `defn`'s params are renamed like any other binder;
  before this, `map`'s doc read `(map coll__60 f)` (bedit's doc pane caught it).
- No user-facing way to declare a macro's binding shape. Every knob is a tax on every macro
  author (ADR-011); a user's own binding macro used in a template stays literal, with
  `#`/`gensym` as before.
- `{:keys [a]}` stays literal: its names are the keys looked up, and the grammar has no
  spelling of "key `:a`, bound as something else" that keeps `:keys`' never-fails meaning.
- A computed binder (`(fn ~params …)`) stays literal: the macro builds those names, so it
  names them.

**Consequences.** Any template containing a binding form now takes the runtime expansion
path (fresh names per expansion), not only one with a plain-symbol binder. A macro that
relied on a literal binder in one of these sites being visible to the caller's code was
relying on the capture; it must say so with `~'name`. The shape table names standard
macros in the kernel — a rename of one of them must update it. Tests:
`tests/hygiene_test.blsp` ("hygiene at every binding site", across processes).

## ADR-501 — Every error is a map; `catch` takes a pattern

**Status:** implemented (2026-10-28).

**Context.** A `catch` handler saw four shapes. A built-in error was a
`{:kind :message :code :file :line :col :trace}` map; `error` and `assert` raised a plain
string; a failed `match`, refutable `let` or pattern `fn` raised the vector
`[:match-error ctx value patterns]`, which also printed as that vector when uncaught; and
`throw` raised its argument as it was. `error-message` hid the difference, but anything
that branched had to know all four, and `catch` could not choose: one bare binder, and
handlers rethrew by hand.

**Decision.**
- **Every error the language raises is an error map**, `{:kind :message …}`, with a code,
  position and trace: `error` raises kind `:error` (`E0090`), `assert` kind `:assert`
  (`E0091`), and a pattern nothing matched kind `:match` (`E0092`) with `:context`,
  `:value` and `:patterns`. One primitive, `%raise`, raises a Brood-built error map with a
  code the language owns; the catch site enriches it as it already did for a contract
  violation (`LispError::caught_value`). Uncaught, these render as `error: <message>`.
- **`throw` raises any value as it is** — a keyword for a non-local exit, a program's own
  error written as a map with `:kind` and `:message`. Wrapping thrown values was rejected:
  `(throw :found)` would have to be read back as `(:value e)`, and a program's own error map
  would nest.
- **`catch` takes a pattern** from the one pattern grammar, with an optional `:when` guard,
  and a `try` may have several after its body. The first that matches runs; when none does,
  the error is raised again from where it was first raised. `(catch e …)` is a pattern that
  matches anything, so every existing handler keeps its meaning. A guard-only form was
  rejected as a second way to test a shape the language already tests with patterns.
- The no-match branch lowers to `(%raise (%match-error 'ctx target 'patterns))`. The
  checker's exhaustiveness lint, `:total` check, parameter domains and clause recovery find
  it through one recogniser (`guards::match_failure_parts`), with the arguments where the
  vector's elements were.

**Consequences.** Code that read a caught `error` as a string, or matched
`[:match-error …]`, changed — `error-message` reads every shape. A `catch` clause list that
ends in a catch-all compiles without a rethrow; one that does not rethrows what nothing
matched. Tests: `tests/try_catch_test.blsp`, `tests/pattern_matching_test.blsp`, the
checker's exhaustiveness and inference tests.

## ADR-502 — A fold calls a closure reducer from Brood, so a `receive` in it parks

**Status:** implemented (2026-10-28). Amends ADR-494 §4 and ADR-403. Amended by ADR-505: a builtin hands its kernel dispatch back to the engine, so most of "What still blocks" below now parks.

**Context.** ADR-494 left one path where a `receive` in an interrupt window blocks its worker
instead of parking: a window opened inside a builtin's callback, which runs under the
builtin's Rust frame that no engine can capture. It is wider than windows: any `receive` in a
callback blocks, and in a `ui-run` turn the window is OUTSIDE, so a synchronous call (a
`buffer-query`, a `gen-call`) in a `map` or `fold` callback of `update` blocks too. ADR-494
judged the fix to be resumable builtins — every higher-order native rewritten as a frame kind.

So which higher-order builtins are there? Taken one by one, almost none. `map`, `filter`,
`reduce`, `mapv`, `each`, `sort-by` (`%merge-sort`), `every?`, `any?` and the rest are Brood,
and all of them that walk a collection walk it through `fold`. `fold` over a list is Brood
(`%fold-loop`). Only `fold` over a VECTOR or a RANGE called into Rust: `%vector-fold-span` and
`%range-fold-span` (ADR-403), each calling the reducer per element from a native loop. The
other natives that call Brood are once-per-call (`%try` and `%binding`, already frames on both
capturing engines; `isolate`; contract wrapping) or a kernel dispatch from inside a builtin (a
record's `num/add` under `+`, `compare-to` under `<`, `->seq` under `first`, the `apply`
builtin taken as a value, a `*err*` port's warning write).

**Decision.** A span folds only a reducer it INLINES — `+` and `*` (`reduce_prim_op`), whose
step runs no Brood. Any other reducer is declined before an element is folded: the span
answers `:%fold-walk`, and `fold` walks the collection in Brood (`%vector-fold-walk`,
`%range-fold-walk`, self-tail loops beside `%fold-loop`), calling the reducer from the
process's own engine, where a `receive` in it parks — on the VM, on the tier-0 machine, and
through a window it opens (ADR-491's region or ADR-494's frame). The walk yields at its back
edge like any loop, so ADR-403's between-element stop now matters only to an inlined
reducer's fallback (a bignum, a record's `Num` method). The span's higher-order fast path
(`hof_resolve` per span) is gone from it; the mailbox matcher still uses it.

Option (b), a continuation frame for the span's loop state in the bytecode driver and the
tier-0 machine, was not needed: once only `fold` was left, a Brood loop IS that frame, on
both engines, with nothing new in either. Option (c), bounding the dirty handoff, would bound
the cost of blocking without parking anything.

**Native code.** A walk the JIT has compiled is native; a `receive` under a native activation
still cannot be captured, so the FIRST one blocks, and the suspend-host latch (ADR-410) takes
the walk arm off native code; every later one parks. That is what `%fold-loop` over a list has
always done. After that latch the walk runs on the VM, calling its reducer (native or not)
through the VM's own call path.

**What it costs — reasoned, not measured.** Nothing for `(fold v 0 +)` and the other inlined
reducers: same span. A closure reducer over a vector or range now costs a VM or native
self-tail loop per element where it cost a Rust loop calling the reducer's arm through the
higher-order fast frame: per element, a bounds compare, `%vector-ref` and a closure call,
against a native-entry gateway per call. ADR-360 §7 records the gateway as what the counted
loop rewrite removes. The shared walk is one call site for every reducer, so its call is
megamorphic, and once a callback anywhere has parked under it, it is interpreted. To check on
the benchmark machine: `nqueens`, `pipeline`, `json`, `reduce` (`make ab`).

**What still blocks.** Brood a builtin calls back into under its own frame: a record's
`Num`/`Ord` method under `+`/`<` (and a record reducer under an inlined `+`), `->seq` /
`->count` reached from `first`/`rest`, `apply` taken as a value by a native, a contract
wrap, `isolate`'s thunk, a `*err*` port. These are kernel dispatches, not iteration; the
§7.4 handoff serves them as before, and an interrupt reaches the waiter once it runs. Also
the first park under a native walk (above), a closure with no VM arm above tier 0, and an
alias of `proc/interruptible` (ADR-494 §3).

**Tests.** `crates/lisp/tests/interrupt_one_worker.rs` (one worker, `proc/info` barriers),
at the default tier and `BROOD_TIER=0`: a window opened in a `reduce` callback over a vector
(ADR-494's blocking case), a `fold` over a range, `map` and `mapv` callbacks, a `ui-run`-shaped
turn (the window outside, the `receive` in a `map` callback), and a window in a callback in a
window — each waits, lets the next process run, answers, takes a ceiling that passed and a
`proc/interrupt` once running, and leaves the dirty-receive count flat. A walk the JIT has
compiled blocks at most once in a program of three waits. What still blocks is pinned by a
window opened in a record's `num/add` under `+`: the count rises.

ADR-493's capture pass gets its test too: `regex_native`'s
`the_group_pass_over_a_match_longer_than_a_window_stops_inside` finds a 100 000-character
match with its groups, then hands the group pass (`groups_polled`, split out of
`search_captures_polled`) a poll that finds an interrupt due — `InterruptPoll::raising`, a
`cfg(test)` constructor — and the Pike VM stops at its first probe. End to end, a pending
interrupt stops the search first, so the pass could not be reached otherwise. Sabotaged red:
the group pass given a fresh poll.

## ADR-503 — Quasiquote has levels

**Status:** implemented (2026-10-28). Replaces item 4 of ADR-152.

**Context.** ADR-152 made a template inside a template an error: levels were not tracked,
so an inner `~x` was filled by the outer template. That kept the door open — every template
it accepted keeps its meaning under level tracking — at a price: a macro whose expansion
defines a macro had to build the inner template with `list`/`quote`, or move it into a
public function the generated macro could call. Nothing in std or downstream needed it yet;
the rule is what a reader of any macro-writing example expects, and the error met them on
the first try.

**Decision.**
- **Levels.** The template being built is level 1; each `` ` `` raises the level, each
  `~`/`~@` lowers it. A hole that reaches 0 is filled; anything deeper is rebuilt as
  written, markers included. So `~~x` fills `x` at the outer level and leaves the inner
  `~`, `~'~x` makes the outer value a constant of the inner template, and `~@~xs` /
  `~~@xs` splice at the levels they name.
- **Names resolve where the macro was written, at every level.** The resolver qualifies
  the inner template's free names when the outer macro is defined, so the macro it
  generates calls the defining module's `helper`, not one the user's module defines. A
  hole lowers the level by one instead of returning to code; a quote inside a template
  still resolves its holes (`'~(helper x)` was left unqualified before this, at any level).
- **Binders belong to the template that runs them.** The hygiene pass renames only the
  outermost template's binders. An inner template's binders are renamed each time the
  macro it builds expands — renamed once, every use of the generated macro would share
  them. A hole back to level 1 inside the inner template is the outer template's code and
  takes its renames: in `` `(let (x 1) `(f ~x)) `` the inner `~x` reads the `let`'s `x`.
- **`x#` belongs to the template that directly holds it**: replaced at level 1 only, so
  `` `(a `(b c#)) `` leaves `c#` for the inner template and `` `(a `(b ~c#)) `` takes the
  outer gensym.
- **A nested template takes the runtime expansion path**, like a template with a binder:
  its holes back to level 1 may bind.
- The root escapes ADR-423 writes into a macro's templates are written at every level: a root
  call head in the inner template comes out `/name`, so the generated macro cannot be
  captured by a module that defines the name. As data, `(/list 7)` is not `(list 7)`.

**Consequences.** Macro-writing macros are written as templates. The `~'~x` and `~~x`
spellings take two moments of expansion to read; the docs show them on a working example
(`def-tagged`). The checker already walked templates by level, so it needed no change.
Tests: `tests/nested_quasiquote_test.blsp` (levels, splices, three levels, `x#`, generated
macros and their hygiene, the defining module's names, across processes).

## ADR-504 — `tcp-send` waits on its peer: outbound backpressure

**Status:** implemented (2026-10-28). Amends ADR-143's "`tcp-send` is asynchronous".

**Context.** ADR-143 made `tcp-send` queue its bytes to the reactor and return, bounding a
stuck reader with a 16 MiB per-socket cap past which the connection is dropped. Nothing
slowed the producer. A server streaming a response (`stream-resp`, a release file, an
archive made while it is sent) therefore made the whole of it as fast as it could read its
sources, whatever the client's pace: the queue held all of it, up to 16 MiB a connection,
and a response larger than that was cut off for any client slower than the server, which on
the internet is every client. The mur forge met it with a 21 MB archive of Brood's own
trunk. `tcp/send`'s doc said "blocking" all along. Inbound had flow control since the
`InboundFlow` work; outbound had none.

**Decision.**
- **A send waits past a high-water mark.** Each stream has an `OutboundFlow`: the bytes
  handed to `tcp-send` and not yet written to the kernel (for TLS, the plaintext not yet
  fully flushed as records). `%tcp-send` charges it, queues, and returns whether the caller
  must wait: true once the queue is at 1 MiB or more. `tcp/send` then waits for
  `[:tcp-drained sock]`, parked like any `receive` (no worker held). A producer runs at its
  peer's pace and holds about a megabyte, not what it sends. Overshoot is one `tcp-send`.
- **Exactly one wake per wait, by the first of two events.** The reactor sends
  `[:tcp-drained sock]` when the queue falls below 256 KiB, or when the connection is gone
  by any route: the reactor holds the flow in a `SendGuard` whose drop closes it (a write
  failure, the cap, a stall, an idle or linger deadline, owner death, the reactor's own
  death unwinding); a send for a connection already gone closes it at once; the reactor's
  death hook closes every registered socket's flow. A closed flow parks no one again. The
  park decision and the wakes are taken under one lock, so a release cannot slip between a
  sender's check and its parking. Waiters are whichever processes sent, not the owner: a
  helper writing to a socket another process owns parks itself, and the owner's mailbox
  never sees `[:tcp-drained]`.
- **A stall bound ends a wait on a peer that stopped reading.** With sends waiting, a peer
  that never reads would park its sender forever; the cap used to end that. Output that
  makes no progress for 60 s now drops the connection, as an idle reap does (`[:tcp-closed]`,
  or `[:tcp-error]` for a one-shot TLS client), which wakes the sender.
  `tcp/set-stall-timeout` changes it per socket, and 0 disarms it. Only a peer whose kernel
  buffers are full can stall, so an idle stream (SSE, long-poll) is never touched; that is
  why it is on by default where the idle timeout is not.
- **The cap stays, as the backstop** for a single `tcp-send` larger than 16 MiB.

**Consequences.** A process that sends a lot and reads only afterwards, to a peer doing the
same, now waits where it used to buffer: two such ends deadlock until the stall bound drops
the connection. A request-response protocol never does this (each side reads before it
answers), and buffering instead was only ever deadlock deferred to 16 MiB. A test that
queued a large payload to a peer not yet reading and then went on (the backpressure and
lingering-close tests) sends it from a writer of its own. `tcp/close` still flushes for
the 5 s linger; a writer parked on the socket wakes once that flush has drained it or given up.

**Guard.** `tests/tcp_send_backpressure_test.blsp`: a writer to a peer reading nothing
parks well short of the 32 MiB it is given and every byte arrives once the peer reads (red
before: the writer queued all of it and the cap dropped the connection); a writer parked on
a peer that closes, and one on a peer that stalls past a 500 ms bound, are woken; a small
reply to a peer not reading never stalls; a listener has no stall timeout.

## ADR-505 — A builtin hands its Brood call back to the engine that called it

**Status:** implemented (2026-10-28). Amends ADR-502's "What still blocks" and ADR-494 §3.

**Context.** After ADR-502 the Brood a builtin still ran from Rust, under its own frame, was a
kernel dispatch: a record's `num/add` under `+` (and `num/sub`, `num/mul`, `num/div`), its
`compare-to` under `<`/`<=` (and through them `>`/`>=`), its `->seq` under
`first`/`rest`/`empty?`, its `->count` under `empty?`. Each was one `apply_engine` call nested
under the builtin, so a `receive` in the method blocked the worker. One more ran nested
without a builtin choosing to: `count`, `first` and friends on a map are `PrimOp1`s whose
fallback ran a closure head (the prelude's `count`) with `dispatch(…, false)` and then
`force`, a nested driver. And a wrapper over `proc/interruptible` bound under another name
was a passthrough the VM elided to the builtin, which ran its thunk nested (ADR-494 §3).

What these share is that the builtin's whole result IS the Brood call's result, or is one
small step from it. So the builtin need not make the call at all.

**Decision.**
- **A redirect.** A builtin whose slow path would call Brood returns
  `Control::Redirect` instead, with the call it would have made waiting in
  `Heap::take_redirect`. The engine that called it makes that call in its place, as an
  ordinary call: `dispatch` loops on it (so with `tail` a VM closure comes back un-run as
  `Step::Tail` and its caller pushes the frame), and the tier-0 machine continues its
  dispatch loop on it (a closure's body becomes the frame's). A `receive` in the method then
  parks, on both engines.
- **Only when offered.** A builtin is called from many places, most of which cannot take a
  redirect: another builtin calling it from Rust (`add_values` for `table/add`, the JIT's
  fallbacks, `extremum` for `math/max`). So an engine that can take one OFFERS it for the
  call it is making — `Heap::offer_redirect` records the address of the argument slice it
  hands the builtin, `call_native_redirectable` — and the builtin takes the offer only if
  its own `args` is that slice (`Heap::redirect_offered`). A builtin another builtin called
  has a slice of its own, sees no offer, and makes its nested call as before. No other code
  ever sees the signal. The offer costs a store before and after a native call through
  `dispatch` and the tier-0 machine; the inlined arithmetic and comparisons never reach one.
  Not measured: this desktop runs no benchmarks. On the benchmark machine, `make ab` with a
  native-call-heavy row beside ADR-502's (`nqueens pipeline json reduce`).
- **Where the result needs a step, a prelude shim.** `num/add` & co. ARE the result, so `+`
  hands back the multimethod itself. `<` needs the sign of `compare-to`, and `first` the head
  of `->seq`: the builtin hands back `%ord-lt` / `%ord-le` / `%record-first` /
  `%record-rest` / `%record-empty?`, which do that step in Brood. A shim the prelude has not
  defined yet (during boot) is no offer taken; the builtin compares or asks here, as before.
- **A map operand takes the call path in the bytecode.** `Prim1` / `Prim2` fallbacks with a
  map operand — every record is one — dispatch with `tail` and turn a `Step::Tail` into the
  frame push a non-tail `Call` makes (`prim2_dispatch_step`); `first`/`rest`/`empty?`'s direct
  builtin call is skipped for a map so the redirect can happen. Every other operand keeps the
  nested path it had, so the change is confined to records and plain maps.
- **`proc/interruptible` under any name is never a passthrough target.** The shared
  `passthrough_redirect_ok` refuses a native marked `is_interruptible`, so a wrapper over an
  alias is entered and its call is the VM's region (ADR-491). The tier-0 machine already
  framed it by the native's own name.

**What still blocks.** `isolate`'s thunk: making it a frame means the global snapshot and
restore, the isolate stamp and the reap running on return, on unwind and across a park and a
migration, on both engines — far more than a redirect, for a builtin only the test runner's
`:isolated` tests use. The §7.4 handoff serves it. A contract wrap, macro expansion, the module
loader and a `*err*` port's write are left as they were (none is on a running program's
update path). A builtin's callback reached from native JIT code: the JIT's fallbacks offer no
redirect and call nested, so the first `receive` blocks and the suspend-host latch takes the
arm off native code (ADR-410), as for ADR-502's walk; a JIT arm's staged tail call goes through
`dispatch`, which takes a redirect as a tail call. The JIT's fence still names
`proc/interruptible` by symbol, so an alias called from a hot JIT-compiled arm runs its thunk
nested. `apply` taken as a value never blocked from Brood: every engine unfolds it where it is
called. A builtin calling `apply` from Rust is a builtin calling Brood, the case above.

**Tests.** `crates/lisp/tests/interrupt_one_worker.rs`, default tier and `BROOD_TIER=0`:
ADR-502's pinned case — a window opened in a record's `num/add` under `+`, whose dirty-receive
count rose — now stays flat, as do a window in `num/sub` under `-` through a function's
locals, in `compare-to` under `<`, in `->seq` under `first`, in `->count` under `count` and
under `empty?`, through `apply` taken as a value, and through a wrapper over an alias of
`proc/interruptible`. Sabotaged red, per case: with `redirect_offered` always false, `+`, `-`,
`<`, `first` and `empty?` block at both tiers (3 blocks each); with the map operand's frame
push and the gate's refusal taken out, `first`, `count`, `empty?` and the alias block at the
default tier (tier 0 already framed `count` and the alias). Record arithmetic, ordering and
sequences answer as before at both tiers (`record_test`, `ability_test`, `counted_test`,
`multimethod_test`, `sorted_test`, `queue_test` and ten more files).

## ADR-506 — The bare namespace is the language: syntax, a measured core, and nothing else

**Status:** accepted (2026-10-28); moves landing family by family (ROADMAP B4).

**Context.** 302 names were bare. ADR-227's rule ("core stays bare, derived helpers move")
was overridden name by name by a second constraint — anything the prelude needed while
booting had to be bare, because the prelude cannot `require` — so `mapv` was bare and
`filterv` was not, `inc` bare and `even?` not. The boot constraint was never real: the
prelude can define a qualified name itself (`seq/lmap`, `string/->symbol` already are), so
where a function is defined says nothing about what it is called. A usage count over the 37
Brood projects beside this repo (comment lines skipped) showed the shape: 39 names in 25+
projects, 155 in fewer than 5 — 75 of the 77 dynamics among them.

**Decision.** A name is bare only when it is one of:
1. **Syntax** — every special form, and every macro that defines, binds or branches: the
   `def…` family, `impl`, `sig`, `fn`, `let`, `if`/`when`/`unless`/`cond`/`case`/`match`,
   the `if-let`/`when-let` family, `for`/`doseq`/`dotimes`/`fold-for`, the threading forms,
   `try`/`throw`, `receive`, `spawn`, `binding`, `with`, `comment`, `assert`, `include-str`.
2. **A measured core** — a function used in at least 15 of the projects counted, and the
   partner of a pair whose other half is core (`any?` with `every?`, `dec` with `inc`,
   `vals` with `keys`, `unlink` with `link`, `failure?` with `failure`).
3. **The built-in kinds** — the predicates and coercions of the language's own value kinds
   (`int?`, `keyword?`, `bytes?`, `record?`, `table?`, `->string`, `keyword`, `symbol`, …).
   A library type's predicate is its module's: `queue/queue?` (`queue?` again under
   `(:use queue)`). This reverses ADR-236's "every type predicate is bare" for library types.
4. **Operators**, `not=` among them.

Everything else is qualified by its family. Boot is not a reason: a function the prelude
needs is defined there under its qualified name.

| Module | Names moving |
|---|---|
| `combinator/` (new) | `complement` `constantly` `juxt` `fnil` `memoize` — `identity`, `partial` and `comp` stay bare: the language's own vocabulary, passed as values far more than a project count shows |
| `list/` (new) | the twelve `caar` … `cdddr` |
| `seq/` | `but-last` `drop-while` `take-while` `mapv` `partition` `repeat` `sort-by` — `seq` (a coercion, like `->string`) and `third` (with `first`, `second`) stay bare |
| `set/` | `disj` |
| `map/` | `assoc-in` `dissoc-in` `get-in` `update-in` — `hash-map` stays bare: the constructor of a built-in kind, and what the quasiquote expander emits for a map template |

## ADR-507 — The callback is last, and only its own arguments follow it

**Status:** accepted (2026-10-29); ROADMAP B5.

**Context.** ADR-308 put the collection first and the callback last, and named one deliberate
exception (a reducer's own parameters stay `(fn (acc x))`). It did not say what may follow a
callback, or what the "subject" is when the call is about a function. The language design
pass listed three suspected exceptions: `map/merge-with` takes the function first, `condp`
takes the predicate first, and a transducer `comp` reads left to right while plain `comp`
reads right to left. An audit of every public `defn` and `defmacro` in `std/` (parameter
lists with a function-named parameter that is not last) found these, and more:

| name | shape | why |
|---|---|---|
| `map/merge-with` | `(f & maps)` | variadic maps pushed the function forward |
| `condp` | `(pred expr & clauses)` | the predicate before the subject, unlike `case` and `match` (ADR-379 already made the predicate's call value-first) |
| `seq/transduce` | `(coll xform rf init)` | the seed after the reducer, where `reduce` and `fold` put it before |
| `seq/iterate-times` | `(f x n)` | function first, beside `seq/iterate`'s `(x f)` |
| `seq/times` | `(n f x)` | function in the middle |
| `stream/fn->` | `(f init)` | function first, beside `seq/iterate`'s `(x f)` |
| `editor/buffer/buffer-edit`, `buffer-edit-reply` | `(bp f &optional origin)` | an optional tag after the callback |
| `editor/buffer/buffer-edit-value` | `(bp f &optional origin (timeout 5000))` | two optional slots after the callback |
| `update`, `map/update-in`, `proc/offload`, `partial` | `(… f & args)` | the arguments after `f` are `f`'s |
| `combinator/fnil`, `combinator/complement`, `partial`, `gen/start`, `log/fn-backend`, `dev/jit-state`, `dev/why-not-native` | `(f …)` | the function is what the call transforms or runs |

None of the rows to reshape is the checker's: no curated signature, result inference or
callback synthesis reads their positions (ADR-308's silent-degradation trap does not apply).

**Decision.** One rule: **the subject comes first, a callback comes last, and only the
callback's own arguments may follow it.** The subject is what the call is about: a
collection, a map, a process, a seed. When the call transforms or runs a function, that
function is the subject (`(combinator/fnil f 0)`, `(gen/start server state)`), and it comes
first like any other subject.

Reshaped, every caller in the tree moving in the same change:
- `(map/merge-with maps f)` — the maps are one collection, so `(-> maps (map/merge-with +))`
  threads and a two-map merge is `(map/merge-with [a b] +)`. `nil` entries are still skipped.
- `(condp expr pred t1 r1 … [default])` — the subject first, as in `case` and `match`, and each
  clause reads in the order its test runs: `(condp line string/starts-with? "#" :heading …)`
  tests `(string/starts-with? line "#")`. The predicate's call stays value-first (ADR-379).
- `(seq/transduce coll xform init rf)` — `reduce`'s `(coll init f)` with the transducer added.
- `(seq/iterate-times x n f)` and `(seq/times x n f)` — the seed, how many times, then the step,
  as `seq/iterate`'s `(x f)`.
- `(stream/fn-> init f)` — the seed, then the generator.
- `buffer-edit` and `buffer-edit-reply` take two arities, `(bp f)` and `(bp origin f)`, as
  `reduce` has `(coll f)` and `(coll init f)`: the optional slot moves before the callback,
  and no name is added. `buffer-edit-value` adds a third, `(bp origin timeout f)`.

Kept, under the rule as written:
- **A function's own arguments.** `(update m k f & args)` calls `(f old & args)`;
  `update-in`, `proc/offload` and `partial` do the same. The arguments are the callback's,
  not the call's, and putting them first would separate them from the function they feed.
- **A function as the subject.** `fnil`, `complement`, `partial`, `gen/start`,
  `log/fn-backend` and the `dev/` probes take the function they transform or run first.
- **Transducer `comp`.** There is one `comp`, and it composes right to left. A transducer is a
  function from a reducing function to a reducing function, so in `(comp (seq/xfilter odd?)
  (seq/xmap inc))` the filter is the outermost wrapper and sees each item first: items flow
  through the stages in the order they are written *because* composition runs right to left.
  Nothing to reshape; language.md says it where transducers are taught.
- **The reducer's parameters** stay `(fn (acc x))` (ADR-308).

**How a stale caller fails.** ADR-308's test: a reorder should fail loudly. Every reshape
here does, at once or under the checker: the old `merge-with`, `transduce` and `times` calls put
a function where a number or a collection belongs, and the old `condp` puts the predicate
where the subject was, so the first clause calls a value. One reorder can fail silently: an
old `(seq/iterate-times inc 0 4)` read as `(x n f)` has `n` = 0, never calls `f`, and answers
`(inc)`. Its `f` (and `times`', `stream/fn->`'s and `merge-with`'s) is therefore annotated
`f:fn`, and the `buffer-edit` family declares `(sig … (and (any fn -> any) (any any fn -> any)))`,
so the checker rejects a non-function in that slot and an armed contract raises at the call.
An old `(buffer-edit bp f me)` would otherwise send the pid as the transform, and the buffer
process would fail calling it.

**Found on the way.** `iterate-times` called `f` once more than its result shows (fⁿ⁺¹(x),
computed and dropped), so `(iterate-times x 0 f)` called `f`: it now runs `f` exactly `n`
times. And a *documented* multi-clause `defn` with a typed parameter — `(defn f "doc" ((x:int)
…) ((x y) …))` — bound a variable literally named `x:int`: the refusal ADR-420 promises read
`(fn "doc" clause…)` as single-clause. It now peels the docstring as the `fn` lowering does,
and refuses.

**Rejected.** A variadic `merge-with` with the function last (`(merge-with a b & more+f)`):
the function would have to be found by position from the end, which no other function does.
A second name for the tagged `buffer-edit`: arities already say it, as for `reduce`.

**Consequences.** A library author has one rule to apply and one to look up (the subject,
when it is a function). `docs/language.md` states it beside the threading macros, where
argument order is taught. The stale "Brood has no `condp`" hint in the evaluator's
foreign-name table is gone: `condp` has existed since ADR-379.

## ADR-508 — A background at the grid's edge continues to the window's, and LCD text is filtered

**Status:** accepted (2026-10-30).

**Context.** Side by side with Emacs on the same panel, font and size (Hack 16 px, subpixel,
scale 1), a GUI window looked softer and unfinished in two ways. First, the cell grid rarely
fills the window: the inset sits on every edge and the sub-cell remainder (up to a cell less a
pixel) lands on the right and bottom, and both were painted with the window background. Every
full-width band (a mode line, a current-line highlight, a gutter) stopped a few pixels short of
the frame. Emacs paints its mode line and fringes through the same leftover pixels. Second,
subpixel text went through swash's `Format::Subpixel`, which is zeno drawing the glyph three
times at whole-pixel resolution, shifted ±0.3 px, one copy per channel: no 3× raster and no LCD
filter. A stem edge that covers one stripe of a pixel lit that stripe alone, a saturated orange
or blue fringe, where FreeType (under Cairo, under Emacs) spreads it over five stripes.

**Decision.** *Edge bleed:* an opaque, square background op (`Rect`, or `FRect` at full
opacity) that touches an edge of the grid gains `FRect`s covering the margin beside it, inserted
right after it. This is a frame rewrite (`host/gui/backend/bleed.rs`), run once per frame and
window geometry before either painter sees the frame, so the CPU and GPU painters, the CPU's
strip damage and the GPU's fragment cache treat the margin as frame content without knowing
about it. Text backgrounds do not bleed (a run's width is the shaper's), nor rounded or
translucent fills (a pill is not a band). Inside a `ScrollRegion` only the sides bleed, since
its rows move; a `CellRegion` paints at its own metrics and is left alone. A `Fragment`
(ADR-336, how bedit draws its mode line and gutter rows) is bled inside, and its bled ops are
kept by the fragment's address across frames, so an unchanged fragment stays one allocation
and the GPU fragment cache, which matches by address, keeps hitting. No setting: a
background that stops short of the frame for want of a few pixels is never what an app drew.

*LCD text:* the outline is rasterised as an alpha mask at 3× horizontal resolution, filtered
with FreeType's default LCD weights (`[8 77 86 77 8]`/256, which keep a solid run solid), and
each channel takes its own stripe (`lcd_filter`). Both painters bake glyphs through the same
function.

**Consequences.** `gui/inset` becomes padding in the edge bands' colours rather than a blank
frame. An app that wants a band to stop short of the edge leaves a cell free. A subpixel glyph
carries the same ink as its gray twin (a test holds the ratio), with lighter, near-neutral
edges. Hinting is unchanged: swash still hints the outline before the 3× stretch.

## ADR-509 — A collection is due on the bytes a process makes, not only on its object count

**Status:** accepted (2026-10-30); KI-307.

**Context.** The collector's trigger counted objects: a minor collection was due when the
nursery held `max(floor, 2 × live)` of them (64K for a lone process), a major when the old
generation had grown 4×. An object's size never entered it, but one object can own any
number of bytes. A vector is flat and immutable, so `(conj v x)` copies `v`'s elements into
a fresh buffer: building a 60 000-element vector one `conj` at a time makes 60 000 vectors
owning 43 GB of element arrays between them, at two objects per step. In
`scripts/gc-contention-repro.blsp` a process doing that in a loop reached 12.4 GB resident in
three seconds, and the run then died on a 16 GB address-space cap. That was KI-307: a
neighbour of such a process ran 2.5× slower, all of it in its own CPU time (no waiting on a
worker, no extra collection), because the machine's memory was being churned at gigabytes a
second. Under the system allocator the same background reached 11 GB, so the allocator was
not the cause.

**Decision.** A minor collection is also due once the process has allocated enough **fresh
buffer bytes** since the last minor: spilled vectors (their element buffers), string text,
and byte blobs that no other handle holds. The budget is `max(byte floor, growth × retained
buffer bytes)`, capped at 512 MiB, where the byte floor is 32 MiB for a lone process and
shrinks with the live process count to 1 MiB, exactly as the object floor does. A major is
also due once the old generation's buffer bytes reach `max(64 MiB, 4 × what the last major
kept)`.

- **Fresh bytes, not retained bytes.** The counter resets at every minor. Survivors scale
  the next budget instead; counting them would make one large live young vector due a
  collection at every safepoint.
- **Only the kinds one object cannot bound.** A map node, pair, closure or env frame is
  bounded per object, and the object count already covers it. A rope or a shared blob is a
  reference-counted view onto data that may already exist: bedit makes a new rope on every
  edit of a large buffer, and counting each in full would collect on every few edits.
- **O(1) on the allocation path, O(copied) in the collector.** Allocation adds one number.
  A tenure measures only the entries it appended to the old generation, from a mark taken
  before it, and a major measures the generation it has just copied.
- **No per-process cost.** A parked process is held to a memory floor (`process_floor`), and
  four `usize` fields on the heap broke it by 31 bytes on the first push. The minor budget is
  one `u32` countdown in 16-byte units (64 GiB), which sits in the heap's existing padding;
  the old generation's two figures live in the extras a collection boxes anyway.
- **A pinned floor stays pinned.** `BROOD_GC_FLOOR` and `BROOD_GC_STRESS` fix the object
  trigger for an A/B or a stress run; with either set, the minor byte trigger stands down so
  the pinned floor means what it says.

**Consequences.** Memory for a buffer-heavy loop is bounded by its live data plus the byte
budget, not by its object count. A process that allocates large buffers collects more often
than before; each such minor costs what survives it, so the cost per byte allocated stays
constant. `(conj v x)` is still linear in `v`, so a loop of `conj` onto a vector is still
quadratic in time; it is no longer quadratic in memory. Guards:
`tests/gc_byte_trigger_test.blsp` (a `conj` loop, a `str` loop, and four processes at once;
all three red with the byte half of `gc_due` removed) and the collector test
`an_old_generation_of_dead_large_vectors_is_compacted_on_its_bytes` (144 MB of dead vectors
kept without the major's byte half).

## ADR-510 — A Lisp is coloured a line at a time, from the state the line above ended in

**Status:** accepted (2026-10-30).

**Context.** An editor colours a large Lisp buffer by lexing a window: the visible lines plus a
fixed lead-in above them (200 lines in bedit), restarted at a top-level form start found by
`safe-restart`. `safe-restart` scans its input from the input's own first character, and so
assumes that character is outside any string. The lead-in starts wherever 200 lines up
happens to be. In a file with a docstring longer than one line, some scroll positions put
that start inside the docstring: the docstring's closing `"` reads as an opening one, every
quote after it pairs the wrong way, and the whole window colours as string. Reported in bedit
on wos's `rp2350.blsp`, where the windows starting at two lines in 560 were inverted. Markdown,
org and the config formats had already left windowed lexing for the line-state cache
(ADR-471); the Lisp modes, the oldest, had not.

**Decision.** `editor/highlight/lisp-line-lexer` is `highlight-spans` as a `line-lexer`: a
line starts in the state the line above ended in, which is everything the walk carries, the
form stack (head and docstring position) plus, when the line ends inside a string, that
string's face. A line that starts inside a string colours up to its closing quote in the
carried face and lexes the rest as code. The walk (`hl-walk`) is shared with `highlight-spans`
and returns the stack it ended with. `specials` is the head-symbol set, as for
`highlight-spans`, so every dialect gets it by passing its own.

A line cannot see the line below it, so one decision differs: a string in a docstring
position that ends its line, with the next form or the close on a later line, is a docstring
(more body may follow), where a lex of the whole source sees a lone last body string and
calls it a value. The faces are resolved when the lexer is built, as every line lexer's are;
the cache rebuilds it when a `:syntax/*` face changes.

**Consequences.** Nothing is guessed, so no scroll position inverts the colours. An edit
re-lexes from its line until a line starts in the state it started in before, which for most
edits is the end of the enclosing top-level form, against a 200-line lead-in plus the band on
every keystroke before. `safe-restart` stays for callers that lex a slice. Guards:
`tests/highlight_test.blsp` checks every window of a source with multi-line docstrings, escaped
quotes, a quote in a comment and a regex literal against a whole-source lex (red with the
carried string state ignored); bedit's `modes_test` checks a 250-line docstring above a deep
window (red without the mode's `:line-lexer`).

**Addendum (rainbow brackets).** `lisp-line-lexer` takes an options map; `{:rainbow true}`
colours each bracket by its depth in `:syntax/delimiter-1` … `-9` (Emacs's rainbow-delimiters),
cycling past the ninth. The depth is the form stack the lines already carry, so it is exact
across lines where a windowed lex would have to guess it. The faces are registered empty, so
nothing changes until an app names their colours. Guard: the rainbow test in
`tests/highlight_test.blsp` (red with the spans dropped).

## ADR-511 — A `conj` onto a vector appends in place when it can

**Status:** accepted (2026-10-30).

**Context.** A vector is flat — its elements in one buffer, which is what makes `nth` O(1)
and lets native code read an element with two loads — and immutable, so `(conj v x)` copied
all of `v`. A loop of `conj` was quadratic: building a 60 000-element vector that way copied
43 GB of elements, which is how KI-307's background reached 12 GB before ADR-509 bounded the
memory. ADR-509 left the time quadratic. A persistent trie would make `conj` O(log n) but
`nth` too, and every native element read would become a walk or a deopt.

**Decision.** A vector may share its element buffer with the vectors appended from it. The
buffer (`AppendBuf`) is a `Vec` whose length is how far it is **claimed** — the longest
vector built over it — and whose spare capacity is room for the next. A vector over it
(`VecStore::Shared`) reads its own first `len` elements. `Heap::vector_append`, behind `conj`
and `into` on a vector, writes `x` past the claimed length only when the vector appended to
ends exactly there and the room is there; anything else copies: exactly sized for a first
append, so a one-off `into` wastes nothing, and with room for as many again when the source
was itself an append, so a chain is amortised O(1). Two `conj`s onto one vector cannot both
claim a slot — the second finds it claimed and copies.

No value ever changes. A write lands only past every existing vector's length, once per
slot. What keeps that true:

- **One heap.** The buffer is LOCAL-only: promotion, messages and a `VecStore` clone copy the
  elements out, and the shared regions build their own stores. So one thread touches it.
- **Copy-on-write for every other write.** `VecStore::as_mut_slice` gives a vector a buffer
  of its own first unless it already holds it alone, so a builder, or the collector
  rewriting relocated handles, never writes into a buffer another vector reads.
- **The collector.** The last vector over a buffer takes it and rewrites its elements in
  place, cut to its length; while others hold it, a vector copies its elements out — into a
  buffer as roomy as the old one for the newest vector over it, the one a `conj` loop is
  building, or the garbage versions behind it in the nursery would cost it its room at every
  collection. An old buffer can hold a young element past the old vector's length, which
  only the young vector reads; the generational invariant concerns what a value can reach,
  and the old vector cannot reach that slot.
- **The JIT.** `Shared` keeps `ptr` and `len` where `Spill` has them, so the native element
  read serves both, with the tag order pinned by a `const` assertion.

**Consequences.** A `conj` loop is linear: 200 000 `conj`s run in a fraction of a second where
the copy each step would move about 480 GB. CLAUDE.md's immutability rule names the append
buffer, so it is not mistaken for the mutable buffer the rule forbids — and so its two
properties are kept. Guards: the heap tests `an_append_writes_in_place_only_past_the_newest_vector`,
`a_collection_keeps_every_vector_over_a_shared_buffer`,
`a_write_never_reaches_another_vector_over_the_same_buffer`,
`the_vector_a_loop_is_building_keeps_its_room_across_a_collection` and
`a_buffer_the_collector_holds_alone_is_cut_back_to_its_vector`, each red with its guard
removed, and `tests/vector_append_test.blsp` (every version read back, the native path, and
vectors built by `conj` across processes).

## ADR-512 — Every parameter list is a list; a vector is data

**Status:** accepted (2026-10-30); ROADMAP B6.

**Context.** "Lists for code, vectors for data" (ADR-010) had four apparent exceptions:
ability op specs `(area [self] :-> float)`, `impl` methods `(area [c] …)`, `defmethod`'s
`[money money]` dispatch tuple and `{:keys [a b]}`. ADR-149 had made a vector parameter list
an error in `defn` and `fn`, because a vector in a parameter position already means
something — it destructures — so a second meaning read Clojure-shaped code as a different
program. The ability forms kept the vector, and so did `defbehaviour`'s op specs. The two
dispatch forms even disagreed with each other: `defmethod` took its parameters as a list.

**Decision.** Sort the four by what the vector *is*.

- **Parameter lists take a list, everywhere.** An op spec is `(area (self) :-> float)`, an
  `impl` method `(area (c) body…)`, a `defbehaviour` op `(mount (params))` — the spelling of
  `defn`, `fn` and `defmethod`. A vector there is an error whose hint is the list it should
  be: `impl Shape: method \`area\` takes its parameters as a list, as defn does — write
  (area (c) …), not [c]`. No alias: the old spelling is refused, not accepted twice.
- **A vector that is data stays a vector.** `defmethod`'s `[money money]` is a tuple of
  dispatch ids matched against the arguments' identities, not parameters (those follow it as
  a list). `{:keys [a b]}` names the keys a map pattern binds. `:sealed [circle rect]` and
  `:requires [Eq]` are member lists.

`defability` now finds its op specs by position — past the docstring, every keyword takes the
form after it as its value — because "a list whose second element is a vector" no longer
marks one, and a `:derive-record` recipe `(fn (fields) …)` is a list too. The checker reads
parameter lists only as lists, so a typed parameter `(scale (self (factor float)))` is still
checked at every call; the one reader that still took only a vector (`spec_param_types`)
would otherwise have stopped checking typed op parameters silently.

**Consequences.** The rule is one sentence: a parameter list is a list; a vector is data.
Every first-party use moved: about 550 parameter lists in `std/`, `tests/`, `docs/`, the Rust test
fixtures and the LSP's method skeleton (`(op (self …) body)`), by a tool that changes only
those brackets, wherever the form is written — code, docstrings, comments, Markdown, Rust
string literals. Downstream projects move the same way; an unmigrated one fails at load with
the hint. Guards: `robustness_limits_test` (a vector op spec is refused with the list
spelling), `ability_test` (typed op parameters still checked), `behaviour_test`, and the LSP
completion tests.

## ADR-513 — An underline can have its own colour and a wave

**Status:** accepted (2026-10-30).

**Context.** A face's `:underline` was a flag: a rule in the text's own colour. bedit's spell
checker (Emacs's jinx) and its diagnostics want what Emacs draws, a red wavy line under a word

## ADR-514 — Keymap prefixes compose across layers

**Status:** implemented (2026-10-28). Replaces `docs/layers.md`'s "chord ownership" rule.

**Context.** A key resolved in the first layer binding it, so a layer binding one chord under
a prefix took the whole prefix: bedit's terminal mode (`C-x C-x`, `C-x c`) left `C-x b`,
`C-x o` and `C-x k` undefined, and any mode with a `C-c` chord hid the global `C-c` map. A
mode could add a key under a shared prefix only by copying the global map, which goes stale
and loses late binding; bedit's `ed-press-prefix` did that by hand.

**Decision.**
- **Each layer is laid over the ones below it** (`editor/keymap/keymap-overlay`): the higher
  layer wins every key it binds, except where both bind a sub-map, which are overlaid the
  same way at every level. A key a mode leaves unbound under a prefix reaches the global map.
- **A non-map hides what is below it.** A command or explicit `nil`, at the key or any prefix
  of it, replaces the lower binding outright. Unlike Emacs, `nil` hides rather than falls
  through, and a middle layer's command stops a lower prefix map from reaching past it; so
  one rule serves both the merged keymap and the per-key lookup.
- **Dispatch merges per keystroke.** `layer-binding` collects the pressed key's maps down to
  the first non-map and overlays only those; the result stays one map, as `keymap-resolve`,
  a `:pending` prefix and `describe-key` expect.
- **Help moves with dispatch.** `scope-bindings` shadows a binding when a higher layer binds
  the whole sequence, or a proper prefix of it to a non-map; `active-keymap` and
  `scope-keymap` fold the overlay, so all three agree.

**Consequences.** Every app on `editor/layers` composes prefixes as Emacs does; bedit can drop
`ed-press-prefix`'s merge. A layer that relied on owning a prefix to hide lower keys must bind
them to `nil` (none in std or bedit did). Tests: `layers_test` ("prefixes compose across
layers", the `scope-bindings` shadow rule), `keymap_test` (`keymap-overlay`).
