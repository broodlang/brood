# Whole-project review, 2026-10-08

A review of every layer at HEAD `0f5ff008` (v0.36.0) — heap/GC, VM + JIT, scheduler +
distribution, builtins + host bindings, reader/checker/LSP, and the stdlib — by six reviewers,
followed by fixes in seven workstreams split by file ownership. Every finding below was
reproduced (or traced to a concrete code path, marked *plausible*) before it was fixed, and
every fix has a regression test at the entry point a caller reaches, **sabotage-verified**:
the fix was undone, the test went red, the fix was restored. The narrative is the devlog's
2026-10-08 entry; user-visible changes are in `CHANGELOG.md` under Unreleased.

## Deferred on 2026-10-08, closed on 2026-10-09

- **Inbound socket backpressure** — ADR-397: per-socket credit carried in the mailbox
  envelope, no API change, applied to child-process output too. Guards:
  `tests/tcp_backpressure_test.blsp`, `tests/proc_backpressure_test.blsp`. Found on the way:
  KI-221 (a TLS server dropped bytes past 64 KiB pending).
- **A restarting peer waits for heartbeat expiry to reconnect** — the handshake carries an
  incarnation (wire v9): a new incarnation replaces the stale link and fires its node-down
  at once; a same-incarnation duplicate keeps the live link; `node/connect` reuses a link by
  dial address, so a bare name no longer re-dials (`docs/distribution.md` §1).
- **`http/parse-url` on `//host/x`** — reads the host now (`http_test`).
- **The `examples/hot-reload` strict warning** — the nil `current-file` is handled.
- Also closed on 2026-10-09: the CI fallout of the first push, the nightly ASan job's eight
  days of red (KI-217), three undocumented one-off flakes (KI-218..220), KI-193's watch, and a
  string reader's parse error that was placed in the caller's file (now `<string>`).

## Not changed — documented design

- **A failed package signature verification warns and continues** — ADR-212's documented choice.
- **`%untar-gz`** shells out to the system `tar`, so an archive bomb fills disk rather than
  aborting the runtime, and every archive is size-capped and sha256-checked before extraction.
- **`registry-install`'s destination must be under a `_deps` directory** (it always had to be,
  through `%rm-rf`); nothing calls it outside one today.
